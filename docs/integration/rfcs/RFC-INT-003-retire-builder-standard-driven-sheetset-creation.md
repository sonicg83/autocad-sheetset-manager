# DST Builder 退场与标准驱动的图纸集创建

## 提案

DST Builder 作为独立产品直接退场，不并入 DST Manager，也不迁移其项目数据库、`GenerationPlan`、构建状态机、独立前端或 Legacy Excel 兼容能力。DST Manager 成为唯一面向用户的产品，并新增“从已发布图纸标准创建新图纸集”的内核工作流。

正式的新建图纸集只能从已发布标准生成，不提供“选择任意 DST，直接创建未绑定标准项目”的旁路。创建成功后，成果直接成为普通 DST Manager 工作区，继续使用既有草稿、预览、修订、CAD 任务和安全发布机制，不发生产品间交接。

标准包用于快速生成标准化项目框架，并在后续提供已知标准下的合规检查。标准身份只使用稳定标准 ID 与版本，例如 `szmedi.gas@2.1.0`；本提案不建立字节指纹级标准证明。

## 动机

真实用户已经能够在 DST Manager 中通过“打开既有 DST、删除全部子集、逐个创建新子集”完成新图纸集搭建。继续维护独立 Builder 会重复建设以下能力：

- DST、DWG 与布局生成和校验；
- 属性定义、属性值和命名派生；
- CAD Worker、任务状态和原子发布；
- 桌面外壳、设置、模板和错误处理；
- Builder 成果再由 Manager 打开的双产品生命周期。

用户需要的不是第二个同类软件，而是在 Manager 内更方便地完成标准化首版创建。标准也不只是一个供复制的 DST 文件，而是一套属性定义、取值约束、字段联动、编号与命名规则、DWG 模板资产和验收规则。

## 产品边界

### DST Manager

DST Manager 统一负责：

- 从图纸标准创建新图纸集；
- 编辑既有图纸集；
- 管理官方标准和用户标准；
- 执行标准合规检查并生成报告；
- 管理修订、任务、CAD 执行与安全发布；
- 为受信扩展提供受控贡献点。

### DST Builder

Builder 退场实施应删除其运行代码、独立前端、API、启动入口、打包配置和专属测试，不以“嵌入 Manager”的方式保留第二套领域模型。

- 不兼容或迁移未完成的 `project.dstb` 等 Builder 项目文件；
- Builder 已发布的 DST/DWG 仍作为普通工程文件由 Manager 打开；
- 属于 Manager 数据库升级历史的既有 Alembic 迁移继续保留；
- 历史 RFC、ADR、计划和 changelog 保留追溯，但 Builder 文档 scope 转为历史入口；
- `ARCH-INT-002` 后续必须更新为单产品治理架构。

## 图纸标准包

### 定位

标准包是纯数据、不可执行、可版本化的 Manager 资产。它至少包含：

- 标准 ID、名称、版本、说明和支持的 AutoCAD 版本；
- 图纸集属性和图纸属性定义；
- 必填、枚举、固定值和一对一映射派生；
- 字段组合派生；
- 编号、序号后缀、不编号关键字与锁定策略；
- 图号、标题、布局和 DWG 文件命名规则；
- 基础模板 DWG、布局模板 DWG和最小 DST 骨架；
- 创建检查和归档检查规则。

AutoCAD 当前不支持本产品所需的子集自定义属性语义，因此首版只在标准 Schema 和扩展接口中预留子集属性，不把它作为必备能力。

标准包不得携带 Python、DLL、SCR、Shell、AutoLISP 或任意用户代码。规则只能使用宿主支持的封闭类型和结构化参数。

### 字段组合派生

标准可以使用字段引用、固定文本和有限格式码组合派生属性或名称，例如：

```text
{专业代码}{子集序号:02d} {子集名称}{图纸序号范围}
```

组合派生可用于图纸集属性、图纸属性、图号、标题、DWG 文件名、布局名和验证报告字段。标准发布前必须检查未知字段引用及直接或间接循环；派生字段在项目中只读。

首版不实现日期字符串格式化、条件表达式、循环、通用公式或用户脚本。

### 编号与设置优先级

新建流程复用 Manager 现有的全图纸集连续编号策略，包括流水号位数、序号后缀样式和不编号子集关键字。所有结构变化继续由同一个确定性派生过程计算图号、范围、标题、DWG 文件名、布局名和 DST 引用。

绑定标准的项目以标准设置优先：

```text
标准锁定值
    ↓
标准允许的项目覆盖
    ↓
标准默认值
    ↓
应用设置（仅用于标准未规定或未绑定标准的项目）
```

标准可以逐项声明锁定或允许项目覆盖。项目的有效配置随项目保存，不能因另一台电脑的应用设置不同而静默变化。

### 模板资产

标准包分别管理基础模板 DWG 和布局模板 DWG：

- 基础模板 DWG 复制为新子集主 DWG 的基底；
- 布局模板 DWG 提供导入主 DWG 的布局内容；
- 布局模板内的来源布局必须严格以标准允许的图幅命名；
- `Model` 不参与图幅匹配；
- 导入布局模板时由 Manager 读取并校验实际布局集合，不信任用户手写的布局名称。

创建时每个子集必须选择一个基础模板 DWG、一个布局模板 DWG和一个图幅。为降低首次创建操作复杂度，同一子集在创建流程中统一使用这组配置。该限制只属于创建流程，不是归档标准规则；创建完成后，用户可以在普通受控编辑模式中自行调整，最终校验不要求同一子集保持统一图幅。

### 标准身份、存储与恢复

DST 使用一个由 Manager 管理、在普通属性编辑器中只读的保留图纸集属性记录标准身份：

```text
DSTManager.Standard = <standard-id>@<version>
```

标准允许的项目覆盖值使用另一项 Manager 保留属性保存为受控结构化数据，确保只转移 DST/DWG、未附带 `.dst-manager` 时仍可恢复实际生效的项目配置。该属性不承担标准身份判断，也不向用户开放自由编辑。

标准保存三层副本：

1. 程序随包的只读官方标准；
2. `%LOCALAPPDATA%\dst-manager\standards\` 中的用户标准库；
3. 项目 `.dst-manager/standards/` 中的绑定版本快照。

项目快照缺失时，Manager 按标准 ID 与版本从官方库或用户库恢复；找不到时允许打开和编辑项目，但标准校验不可用。用户可以导入对应版本的标准包恢复。改用其他版本属于显式重新绑定，不得伪装成恢复。

已发布标准版本不可原地修改；内容变化必须发布新版本。本提案不要求项目通过 SHA-256 证明标准内容逐字节一致。

## 标准管理

普通用户可以在 DST Manager 中直接创建和维护用户标准。标准编辑器至少包括：

- 基本信息；
- 属性规范；
- 枚举、映射、字段组合和编号规则；
- 基础 DWG、布局 DWG和最小 DST 骨架；
- 标准检查、示例预览和发布。

标准可以从以下来源建立草稿：

- 空白标准；
- 官方或用户已发布标准的副本；
- 现有 DST。

从现有 DST 建立标准草稿时，只提取图纸集/图纸属性定义和必要安全结构。用户逐项决定既有值是清空、作为默认值还是改为派生值；原项目子集、图纸、路径和项目特有引用不进入标准。

标准采用“草稿 → 校验 → 发布版本”的生命周期。草稿可持续编辑，发布版本不可原地修改，但可以导出或复制为新版本草稿。

## 创建图纸集工作流

正式的新建入口只接受已发布标准，流程为：

1. 选择标准和版本；
2. 填写项目及图纸集属性；
3. 录入或导入子集、图纸和可输入图纸属性；
4. 为每个子集选择基础模板、布局模板和图幅；
5. 检查完整派生结果；
6. 在隔离目录生成、验证、原子发布并直接打开工作区。

创建表单由标准动态生成。枚举使用受控选择，映射和组合派生字段只读并实时预览。专业名称选择“燃气”后，专业代码可以由标准映射为 `RQ`。

预览必须展示最终图号、标题、序号后缀、子集范围、DWG 文件名、布局名、DST 引用及每个子集使用的模板来源。预览阶段不启动 AutoCAD，只进行确定性派生和轻量文件检查；真实布局复制与 CAD 校验在用户确认后的暂存任务中执行。

一个子集对应一个主 DWG，每张图纸对应主 DWG 内的一个布局。首版不支持一张图纸一个 DWG。

目标必须是尚不存在的新目录或空目录。创建流程不得合并或覆盖已有工程；任何失败都不得留下半成品正式成果。生成成功后保存项目标准快照、建立初始修订并直接打开为普通 Manager 工作区。

创建表单草稿保存在应用数据目录，不重新引入 Builder 项目数据库。应用异常退出后可以恢复输入，但旧预览必须失效；CAD 重试创建新 attempt，不续跑状态不明的中间命令。

## 批量结构导入

现有属性定义 CSV 继续承担属性定义合并，不等同于新项目结构导入。新建流程由当前标准生成版本化 XLSX 录入模板，支持一次导入：

- 子集；
- 图纸；
- 每张图纸的可输入属性；
- 子集使用的基础模板、布局模板和图幅。

枚举字段在 XLSX 中提供受控选项；派生和只读字段不要求用户填写。XLSX 只能引用标准中登记的模板稳定 ID 或受控显示名称，不接受任意文件路径。导入只形成创建草稿和预览，不直接写入 DST/DWG。

本提案不兼容 Legacy Excel 格式。

## 扩展边界

新建图纸集属于宿主内核能力。扩展不能取得可写 AcSm DOM、发布器或正式工程路径，也不能绕过预览和发布事务。

受信扩展可以贡献：

- 新的标准规则类型或字段格式器；
- 结构化数据导入器；
- 组织标准源；
- 标准检查器；
- 验证报告格式；
- 创建完成后的伴随成果。

标准使用扩展能力时必须声明 `extension_id`、能力 ID 和最低兼容版本。依赖缺失时，标准可以查看和导出，但不能用于创建或声称完整验证通过。

首版只支持宿主内置规则和随程序发布、进入固定白名单的受信内置扩展，不开放普通用户安装任意第三方插件。

## 标准校验与报告

首版只执行校验并生成报告，不自动收集工程文件或生成归档移交包。

宿主完整性检查至少覆盖 DST/AcSm 契约、DWG 和布局引用、Handle、路径边界、缺失文件及当前工作区状态。标准检查至少覆盖属性定义、必填值、枚举、映射、字段组合、编号、后缀、图号、标题、布局名和 DWG 文件名。

单条结果使用“通过、错误、警告、无法检查、不适用”；整体结果使用“符合标准、符合标准但有警告、不符合标准、无法完成验证”。即使存在错误也允许生成报告，报告生成成功不等于项目合规。

HTML 与 JSON 必须由同一份验证结果模型生成。报告记录工程、标准 ID 与版本、Manager/AutoCAD 版本、工作区修订、检查时间、规则汇总、对象级实际值/期望值/修复建议及未执行检查原因。

校验期间工作区修订或正式文件发生漂移时，本次结果作废。报告候选文件写入并回读验证成功后才向用户展示；报告失败不修改工程文件，也不产生工程修订。

## 失败与恢复

- 标准草稿可以带诊断保存，但存在阻断诊断时不得发布；
- 替换 XLSX、标准版本或模板选择后，旧预览立即失效；
- CAD、DST 构造或最终校验失败时不发布半成品；
- 正式发布复用现有锁、暂存、发布日志、永久 before 快照与恢复事务；
- 标准或插件能力缺失时必须明确失败，不使用默认值假装成功；
- 报告生成与创建任务都必须保持可定位诊断和稳定错误码。

4. **[标准校验报告（PLAN-DM-037）](../../../.planning/plans/dst-manager/PLAN-DM-037-standard-validation-reports.md)**：宿主与标准规则统一校验，生成同源 HTML 与 JSON。

## 非目标

- Builder 项目或 Legacy Excel 兼容；
- 任意 DST 直接创建未绑定标准的项目；
- 子集属性强制支持；
- 日期格式化；
- 条件表达式、通用公式或用户脚本；
- 用户安装任意第三方插件；
- 一张图纸一个 DWG；
- 归档移交包生成；
- 字节指纹级标准身份验证；
- 多用户协作、账号、审批或远程 Worker。

## 备选方案

### 将 Builder 整体并入 Manager

未采用。它会保留两套领域模型、状态机、前端和发布链路，只是把重复维护隐藏到同一个程序中。

### 将创建流程全部实现为内置扩展

未采用。创建发生在工作区存在之前，并需要新工作区身份、DST/DWG 初始化、CAD 调度和正式发布；让扩展承担这些职责会突破现有最小授权边界。标准来源、导入器和报告格式仍可作为扩展贡献。

### 保留任意 DST 快速创建旁路

未采用。旁路会绕开标准绑定、版本恢复和可复现校验，重新形成第二套创建语义。现有 DST 应先用于建立用户标准草稿，再由已发布标准生成项目。

## 影响范围

- 取代 `RFC-INT-001` 关于 Builder 独立产品持续演进的结论；
- 使 `ARCH-INT-002` 的双产品治理边界需要后续修订；
- 使 `PRD-DB-001`、`ARCH-DB-001` 与 `SPEC-DB-001` 转为历史文档；
- 扩展 DST Manager 的产品定位，但不改变其现有受控编辑和发布安全不变量；
- 需要为标准管理、项目创建和验证报告分别形成后续 Manager PRD/Architecture/Spec 与实施计划。

## 迁移路径

Builder 代码退场和 Manager 新能力建设分阶段完成，不要求在删除 Builder 前迁移其领域实现。Builder 已发布成果保持普通 DST/DWG 兼容；未发布 Builder 草稿没有迁移承诺。

在 Manager 标准创建能力完成前，用户仍可使用现有 Manager 手工流程从模板工程删除子集并重新创建。该临时流程不形成新的长期兼容契约。

## 开放问题

本 RFC 的产品方向没有阻断性开放问题。具体标准 Schema、API、UI 和任务契约由后续产品与架构文档细化。

## 评审结论

2026-09-21 经用户逐项确认后接受本 RFC。确认内容包括 Builder 直接退场、标准驱动创建、普通用户维护用户标准、ID + 版本绑定、项目标准快照恢复、创建阶段单子集统一模板、字段组合派生、受信扩展边界，以及首版 HTML + JSON 校验报告。
