# DST Builder 产品愿景

## 产品愿景

DST Builder 是面向图纸集首版生产的本地桌面应用。它通过可恢复的分步引导，把结构化项目数据转换为经过校验的 DWG、DST 和伴随成果，并以可审计的基线包交接给 DST Manager。

## 产品边界

- DST Builder 负责交接前的项目建模、修订、生成计划、构建、验收和正式成果发布。
- DST Manager 负责交接后既有 DST/DWG 的检查、编辑、修订和安全发布。
- 两个产品拥有独立入口、独立工作流和独立发布节奏，只共享已经被双方实际采用的稳定平台能力。
- 正式交接后，两边历史独立；首版不提供隐式双向同步。

## 体验原则

- 产品主结构是可保存、可恢复的工程向导，而不是一次性弹窗或自由工作区。
- 用户始终知道当前步骤、剩余工作、阻断问题和下一步动作。
- 应用内项目模型是唯一事实源；Excel 只承担旧项目导入、批量交换和只读数据快照导出，不能恢复完整项目修订、资产或审计历史。
- 构建前必须生成完整、不可变且可审阅的 `GenerationPlan`。

## 绿地原则

- 不兼容旧数据库、旧 API、旧项目格式或旧处理器。
- 不保留 PowerShell/WPF、旧 DST DLL 或 Legacy 运行链路作为产品级降级方案。
- Legacy 源码只作为规则考古和黄金样本来源，不成为运行依赖。
- 不为旧实现保留回退，不等于放弃工程安全：构建隔离、失败清理、发布事务恢复、成果版本和审计证据仍是强制能力。

## 首期成功方向

- 用户能够在一个引导流程中完成项目创建、规则配置、图纸编排、模板匹配、构建前检查、成果构建和 Manager 交接。
- AutoCAD 2016 与 2020 均能打开生成的 DWG 和 DST，布局、Handle、引用和图纸属性通过真实系统验证。
- 正式成果包根目录仅包含 `drawings/` 和 `metadata/`，其中 `drawings/` 可脱离 Builder 独立交付使用。
- 首版以单人本地桌面方式交付，但领域模型、任务协议和存储端口不绑定单机实现，为未来企业内网部署保留替换空间。
