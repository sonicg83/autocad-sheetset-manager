# DST Manager v0.3.1 桌面壳与操作易用性迭代设计规范

## 1. 背景

v0.3 实测后收集到三组操作易用性反馈（见 [v0.3 测试后意见](../../../.planning/memos/DMv03-test-report.md)）：DST 文件打开依赖手输绝对路径、待处理改动恢复不可发现、模板来源文件与布局名依赖手动输入。经评审（2026-09-03），确定如下基线调整：

- 本规范驱动的迭代为 **v0.3.1**，提前于原 UI/UX 重构；
- 原 [SPEC-DM-006](SPEC-DM-006-dst-manager-desktop-ui-ux.md) 驱动的界面重构（原定 v0.3.1，其实施计划 PLAN-DM-010 尚未编制）推后为 **v0.3.2**。先落地本迭代定义的交互模型，SPEC-DM-006 的视觉系统在其上重构，避免返工。

关键评审结论：

- 提前实现 **WebView2 桌面壳**，壳为唯一交付入口；文件路径获取依赖壳能力，不再受浏览器安全限制。
- 意见中的"待处理改动暂存"经核对**已基本存在**（草稿按 dst 路径确定性绑定、自动保存、重开恢复、清空与发布后清除，见 §5.5），真实缺口是**恢复不可发现**。本迭代只改进提示与状态可见性，不新增存储机制。
- `template_layout` 来源类型**保留 DWT** 支持，文件校验接受 `.dwg` 与 `.dwt`。

## 2. 目标与非目标

### 2.1 目标

1. 用户无需手输路径即可选择 DST 文件并打开项目；
2. 未打开/已打开两态的界面动线清晰，关闭操作有防丢失确认；
3. 未完成改动的草稿恢复过程对用户可见、可确认；
4. 模板来源文件与来源布局通过选择而非输入完成，布局名来自真实 DWG 读取并具备全局缓存。

### 2.2 非目标

- 不引入 [SPEC-DM-006](SPEC-DM-006-dst-manager-desktop-ui-ux.md) 的设计令牌、主题与统一组件系统（v0.3.2 范围）；
- 不新增草稿存储结构或操作历史回放能力（沿用现有草稿契约）；
- 不实现"最近打开"列表（后续按需另立需求）；
- 不改变后端 API 契约、发布事务、安全门禁与 CAD 分流约束。

## 3. 桌面壳（F-01）

### 3.1 选型与形态

- 壳采用 **pywebview**（Windows 底层为 WebView2 运行时），与现有 Python/FastAPI 后端同进程生命周期管理。
- 壳进程职责：启动后端服务（仍只监听 `127.0.0.1`）、创建主窗口加载本地服务、提供原生文件对话框桥、退出时优雅停止后端。
- 壳是唯一交付入口；后端 HTTP 服务继续绑定 `127.0.0.1`，不因壳的存在开放外部访问。手动以浏览器访问该端口不属于受支持形态，不在本迭代内做拦截。

### 3.2 原生能力桥

壳通过 pywebview 的 Python↔JS 桥暴露最小能力面：

| 桥方法 | 作用 |
| --- | --- |
| `select_file(filters)` | 打开原生单文件对话框，返回绝对路径或 null |
| `on_drop(cb)`（视实现可行性） | 注册拖拽文件的原生路径回调 |

**拖拽路径约束**：WebView2 的 HTML5 drop 事件同样拿不到文件绝对路径，需在壳侧注册原生 drop 处理（WinForms `IDropTarget` 拦截）并经桥转发路径。此项在实施计划中先行验证；若验证不可行，拖拽区域降级为"点击即打开原生对话框"，视觉上仍保留拖拽热区提示。验收以"用户能通过拖拽或点击完成选择"为准。

## 4. DST 文件打开与关闭（F-02 ~ F-04）

### 4.1 文件选择与校验

- 现有"输入 .dst 绝对路径"输入框取消，改为**文件选择区**：点击调用原生对话框（过滤器仅 `.dst`），拖拽路径同样接受。
- 选择结果须校验扩展名为 `.dst`（不区分大小写）；非 `.dst` 给出明确错误提示，不发起打开。
- 校验通过后**立即自动打开工作区**，无需再点"打开项目"。
- 既有后端路径校验（危险名称、越界路径）继续生效，前端不复制校验规则。

### 4.2 两态状态机

- **未打开态**：仅展示文件选择区（含简要说明文案）；现有"打开项目"与"修订历史"按钮在此态取消。
- **已打开态**：原"打开项目"位置替换为"关闭"按钮；"修订历史"入口保留在已打开态。
- 关闭回到未打开态，清空前端工作区状态。

### 4.3 关闭确认（F-04）

点击"关闭"时检查是否存在未发布完毕的改动（草稿动作非空或处于 stale/保存失败状态）：

- 存在 → 弹窗确认；文案注明改动已自动保存、"重新打开同一 DST 可继续处理"；用户选择"放弃改动"则删除草稿并关闭，选择"取消"留在当前界面。
- 不存在 → 直接关闭。

## 5. 草稿恢复可发现性（F-05）

### 5.1 现状认定

以下能力已存在，本迭代不改其数据流与契约：

| 能力 | 现状 |
| --- | --- |
| 草稿绑定 | `workspace_id` 由 dst 路径 `uuid5` 确定性生成（`service.py`） |
| 自动保存 | 每次操作经 `draftSaveQueue` 自动 `PUT /draft`，含 `expected_version` 乐观锁 |
| 重开恢复 | 打开工作区后 `loadDraft` 自动拉取并恢复 |
| 清除 | "清空"按钮删除草稿；全部变更发布成功后草稿清除 |
| 冲突防护 | stale 与 `DRAFT_CONFLICT` 检测 |

### 5.2 本迭代改进

1. **恢复提示**：打开工作区检测到非空草稿时，展示一次性提示条："已恢复上次未完成的改动（N 条待处理）"，提供"继续"与"清空重来"两个动作；
2. **保存状态可见**：草稿自动保存状态（保存中/已保存/保存失败）在工作区常驻位置展示，保存失败须醒目提示并给出重试入口；
3. **丢失场景兜底**：若测试者后续确认存在真实丢失场景（如未走草稿保存的操作路径或 stale 静默清除），以 bug 修复处理，不阻塞本迭代交付。

## 6. 模板来源与布局选择（F-06 ~ F-08）

### 6.1 来源文件选择（F-06）

- "来源文件"输入框改为"选择文件"按钮，经壳的原生对话框选择，过滤器仅 `.dwg`、`.dwt`；
- `template_layout` 来源类型保留 DWG/DWT 双支持；
- 选择后回填路径显示（只读展示），类型不符时给出明确错误提示，不发起读取。

### 6.2 布局名读取（F-07）

- Worker 插件（`DstManager.AutoCAD`）新增**只读轻命令**：枚举指定 DWG 的全部布局名并输出 JSON，不修改图纸；先盘点 `LayoutRenameCommand.cs` 等现有布局枚举逻辑，可复用则复用。
- 读取经现有 CAD 分流机制执行：固定命令 + 固定 SCR 渲染器 + 版本匹配的 Worker 插件 + accoreconsole（维持 [ARCH-DM-001](../architecture/ARCH-DM-001-dst-manager-mvp-baseline.md) 与 [SPEC-DM-003](SPEC-DM-003-deferred-cad-validation-and-subset-cad-operations.md) 约束），支持 2016/2020 双版本。
- 手动输入"来源布局"改为**下拉选择框**，选项来自读取结果；读取完成前下拉禁用并显示进度。
- **进度提示**：读取期间在来源布局区域展示进行中状态（进度条或明确的进行中文案），完成后自动填充下拉；超时与失败给出可读错误。
- **占用与失败**：DWG 已被 AutoCAD 打开或其他原因导致 accoreconsole 失败时，提示用户关闭占用程序后重试；不静默失败。

### 6.3 布局缓存（F-08）

- 全局缓存键为 DWG 文件内容 **SHA-256**，值为布局名列表，存后端 SQLite（`data_dir` 下现有数据库），新增 Alembic 迁移；
- 读取布局前先查缓存，命中则跳过 accoreconsole；未命中或文件内容变化（hash 不同）后重新读取并写回；
- 缓存跨 DST 工作区复用；缓存记录含来源路径、创建时间，供诊断展示；
- 缓存仅是加速层，读取失败时允许用户回退为手动输入布局名，不得因缓存问题阻塞插入图纸流程。

## 7. 架构边界与安全约束

以下既有约束不因本迭代改变，逐条适用：

- DST 修改仍必须经过 `DST -> XML DOM -> DST` 受控流程；本迭代所有改动为读取、展示与壳能力，不新增写入路径；
- 只读打开工作区仍不得创建 `.dst-manager/` 或修改 DST/DWG；布局缓存与草稿均存应用数据目录，不触碰工作区；
- 用户提供的路径继续保留危险名称与越界校验；经壳获得的路径同样走既有校验；
- 壳与后端同机通信，后端继续只监听 `127.0.0.1`；
- CAD 操作只经固定命令、固定 SCR 与匹配版本 Worker 插件执行，新增布局枚举命令纳入同一门禁。

## 8. 错误处理汇总

| 场景 | 处理 |
| --- | --- |
| 选择/拖入非 `.dst` 文件 | 前端明确提示"仅支持 DST 文件"，不发起打开 |
| 拖拽路径桥不可用 | 降级为点击打开对话框（§3.2） |
| 打开工作区失败 | 保留现有错误呈现，回到未打开态 |
| 关闭时存在未发布改动 | 确认弹窗（§4.3） |
| 草稿保存失败 | 常驻状态提示 + 重试入口（§5.2） |
| accoreconsole 读取布局失败/超时 | 可读错误 + 关闭占用提示 + 允许回退手动输入 |
| DWG 类型不符 | 提示仅支持 `.dwg`/`.dwt` |

## 9. 测试与验收

- **单元/集成**：布局缓存模型与迁移（全新数据库升级）、`.dst`/`.dwg/.dwt` 校验逻辑、草稿恢复提示触发条件的后端测试；
- **Web 交互**：Playwright 用例覆盖两态状态机、关闭确认、恢复提示与保存状态展示、来源文件与布局选择交互（Playwright 仍以浏览器运行，不依赖壳）；
- **真实 CAD 系统测试**：具备环境时运行 2016/2020 双版本布局枚举命令验证（`DST_MANAGER_RUN_AUTOCAD=1`）；
- **壳冒烟**：壳启动后端、加载界面、原生对话框返回路径、退出清理，作为发布前人工检查项；
- 生产构建（`npm run build`）与 Ruff/pytest 基线照常执行。
