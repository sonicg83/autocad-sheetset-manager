# 延后 CAD 校验与子集级 CAD 操作分流规范

## 1. 范围与目标

本规范定义 v0.21 后续优化的结构差异预览、确认执行、子集级 CAD 操作分流和布局改名协议。目标是消除预览阶段的 Core Console 启动，避免仅布局名称变化时执行全量布局重建，同时保持既有 DST/DWG 事务发布安全。

本规范不改变受控命令白名单、DST XML DOM 写入、发布器锁与回滚模型，也不允许图纸级拆分子集 DWG。

## 2. 快速结构差异预览

### 2.1 必须输出

结构差异预览必须基于一次确定性 `DerivedDocument` 计算，返回：

- 有序的前后结构差异；
- 每个最终子集的 `cad_operation`：`none`、`rename_only` 或 `rebuild`；
- 受影响 DWG 路径、操作显示名称和各类数量；
- 数量变化前沿的位置及其后的工作范围说明；
- 待延后到确认阶段的 CAD 校验说明；
- 用于确认执行的来源路径、存在性、扩展名、文件身份和 SHA-256 基准。

`execution_intent.groups` 必须携带 `cad_operation`。Web 对 `rename_only` 显示“批量改名布局”，对 `rebuild` 显示“清除并重建布局”，并显示 CAD 校验将在确认任务中执行。

### 2.2 禁止行为

快速预览不得：

- 调用 `CoreConsoleExecutor`、启动 `accoreconsole.exe` 或加载 Worker DLL；
- 枚举或校验 DWG 内的布局；
- 创建 `.dst-manager/`、任务记录、暂存副本或任何持久化写入；
- 用预览结果绕过确认执行时的来源基准复核。

## 3. 子集操作分类

### 3.1 数量变化前沿

实现必须按最终子集顺序比较原始与派生结构。首个满足以下任一条件的子集为数量变化前沿：既有子集图纸数量改变、插入非空子集、删除原有子集、插入图纸或删除图纸。

前沿及后续所有最终子集必须生成 CAD 工作单元。前沿之前，只有自身存在布局相关差异的子集生成工作单元；单独的子集名变化不得扩大到后续子集。

### 3.2 `rename_only` 资格

子集只有在下列全部成立时才可标记为 `rename_only`：

1. 原始和最终图纸数量相同；
2. 稳定图纸 ID 与顺序一一相同；
3. 每张图纸的布局内容来源可证明未变；
4. 差异仅为派生后的布局名、图号、图名序号后缀、子集名文字或最终 DWG 路径；
5. 运行时 CAD 校验能确认当前纸空间布局集合等于预期旧集合。

图纸数量、集合、顺序或内容来源改变，新增/删除子集，或者任何资格无法证明时，必须使用 `rebuild`。不在工作范围且没有布局相关差异的子集使用 `none`。

## 4. 确认执行与 CAD 工作单元

用户确认后，服务必须在现有写锁、暂存与发布事务中执行。对每个 `rename_only` 或 `rebuild` 单元：

1. 复核预览固定的来源路径、文件身份与 SHA-256；不一致时拒绝执行并要求重新预览。
2. 复制或创建该单元的暂存 DWG。
3. 在一次 Core Console 运行内完成 CAD 前置校验、指定操作、结果校验和保存。
4. 仅在所有单元成功后复核派生 DST 并进入既有多文件发布。

不得为同一单元先执行独立 CAD 检查，再启动第二次 Core Console 完成布局操作。失败必须保留正式 DST/DWG 不变，并继续使用既有任务失败、回滚与启动恢复路径。

任务进度必须记录每个单元的操作类型、开始/结束时间、耗时和错误摘要；现有队列、暂存或 CAD 运行状态可承载该信息，无需仅为此优化新增用户确认步骤。

## 5. `DstRenameLayouts` Worker 协议

### 5.1 输入约束

Python Worker 为每个暂存单元按暂存 DWG 路径派生并写入固定名称的布局映射副文件。SCR 只执行 `NETLOAD` 与无参数的 `DstRenameLayouts`，不传递请求路径；插件必须从当前 DWG 路径派生同一固定请求/结果路径。插件不得把副文件内容解释为 AutoCAD 命令、LISP 或任意文件系统路径。

映射必须同时包含完整预期旧名称集合和完整最终名称集合。插件必须拒绝以下情况：模型空间参与映射、旧名称缺失、旧名称重复、目标名称重复、非法目标名称、映射外的纸空间布局或最终集合不一致。

### 5.2 执行与结果

插件必须以任务生成且不与现有名称冲突的临时名称执行两阶段改名，支持名称互换与循环映射。改名不得删除、导入或重排布局，不得改写布局内容。

保存前，插件必须验证纸空间布局名称集合与最终集合完全一致，并写出结果副文件，至少含最终名称集合与实际改名数量。Worker 必须读取并核验该结果副文件后才认为单元成功。

`rename_only` 路径不得调用 `DstDeleteLayouts`、布局导入或 `DstGetLayoutHandles`。它不得生成 Handle 绑定，也不得向 DST DOM 覆盖已有 `AcDbHandle`。

## 6. DST 绑定规则

- `rebuild` 单元必须在布局重建后读取完整 Handle 集合，并按最终图纸一一绑定到派生 DST。
- `rename_only` 单元必须保留原 DST 的既有 `AcDbHandle`，只应用派生后的名称、图号、标题及路径字段。
- `none` 单元不得产生 CAD 绑定或 DWG 写入。
- 若 `rename_only` 对应图纸缺少、重复或非法 Handle，计划不得把它作为安全的改名单元；实现必须失败或选择由确定性规则得出的 `rebuild`，不得猜测 Handle。

## 7. 并发与配置

`DST_MANAGER_CAD_MAX_PARALLEL` 与 `Settings.cad_max_parallel` 的取值范围必须为 1–10，默认值为 4。所有确认任务中的 Core Console 进程使用同一全局预算；实现不得为验证、重建和改名分别创建互不约束的进程池。

并发调度不得改变最终结构顺序、DST 绑定确定性、发布文件顺序或回滚语义。实际性能验收必须至少覆盖并发度 1、4、10，并记录硬件、CAD 版本、工作单元数量和各阶段耗时。

## 8. 兼容性与安全

- 继续使用固定命令、固定 SCR 渲染器和版本匹配的 AutoCAD Worker DLL。
- 插件校验失败、结果副文件缺失或无法解析、来源基准漂移、并发单元任一失败，均不得发布任何正式文件。
- Web 仅展示后端确定性计划，不在前端复制最终 CAD 资格判断。
- 对旧任务记录或缺少 `cad_operation` 的数据，必须安全隔离或按既有兼容策略处理，不能默认为 `rename_only`。

## 9. 验收

至少应覆盖以下自动化与真实 CAD 验收：

- 结构预览不调用 Core Console，且能展示受影响 DWG 与三类操作；
- 仅子集名或派生布局名变化时，仅目标子集为 `rename_only`，后续子集不进入 CAD 工作范围；
- 插入/删除图纸或子集时，数量变化前沿为 `rebuild`，其后单元按资格分为 `rename_only` 或 `rebuild`；
- `rename_only` 的 SCR/插件路径不含删除、导入或 Handle 获取；名称互换、循环、冲突、缺失和意外布局均安全失败；
- 真正 AutoCAD 2016 与 2020 验收通过独立检查证明改名前后 Handle 不变；
- 预览后来源变化、写锁后来源变化、任一单元失败均不发布正式文件；
- 并发 1、4、10 均不超过全局 Core Console 上限，且保留完整事务、回滚与启动恢复回归。

## 10. 替代关系与状态

本规范替代 [SPEC-DM-002](SPEC-DM-002-v021-cad-single-script-execution.md) 中“所有结构单元均完整布局重建”的操作选择，同时保留其单次 Core Console、暂存、校验和发布安全要求。

本规范已经确认、实施并由 `PLAN-DM-008` 完成验收。2026-08-26 实测证明快速预览无 CAD、确认阶段延期校验、逐子集操作分类、`rename_only` Handle 不变、数量变化前沿及失败不发布；AutoCAD 2016/2020 非性能系统矩阵为 54/54，10 工作单元、`5 rename_only + 5 rebuild` 的并发 1/4/10 性能矩阵为 6/6。完整命令、环境和数据以 [PLAN-DM-008](../../../.planning/plans/dst-manager/PLAN-DM-008-deferred-cad-validation-and-layout-rename.md) 的实际验证记录为准。
