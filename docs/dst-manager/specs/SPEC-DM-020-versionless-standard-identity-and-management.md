# 无版本图纸标准身份与标准库管理规范

## 1. 目的与权威边界

本规范依据 2026-09-28 的用户决策，取代 [SPEC-DM-019](SPEC-DM-019-standard-version-and-package-import.md) 中标准发布版本、按 ID 归集、导入冲突与相关接口的长期契约。`schema_version` 仍是 JSON 格式版本，`dependencies[*].min_version` 仍是扩展能力版本；两者不因取消**标准发布版本**而消失。

级联属性拟将标准文档从当前 v3 扩展至 v4，设计见 [SPEC-DM-021（草稿）](SPEC-DM-021-cascading-enum-properties.md)；在该方案实施前，本规范的 v3 身份与包格式仍为现行契约。

标准属性、命名、资产及发布检查沿用 [SPEC-DM-017](SPEC-DM-017-standard-properties-and-dwg-naming.md)；创建向导的页面组织沿用 [SPEC-DM-018](SPEC-DM-018-standard-driven-sheetset-creation-ui.md)；DST/DWG 受控发布与项目快照沿用 [ARCH-DM-001](../architecture/ARCH-DM-001-dst-manager-mvp-baseline.md)。本规范只替换与标准身份、库列表、导入、删除直接冲突的条款。现有两步导入的限时快照、凭证、大小上限和路径安全门禁继续有效。

## 2. 身份、生命周期与时间

1. 标准包身份字段为 `standard_id`（规范化为小写带连字符的 UUID）、`name` 和 `published_at`。UUID 文本的大小写差异视为同一 ID；缺少连字符或非法 UUID 拒绝。不含标准发布 `version`，也不保存派生来源、版本历史或版本顺序。`description` 是标准内容说明，不参与身份、同名判断或名称／ID 搜索。
2. 新建空白标准、复制已发布标准、从 DST 提取标准时都立即创建**独立草稿**，生成新的 UUIDv4 `standard_id`；保存草稿、发布及导出沿用该 ID。内部 `draft_id` 仅标识草稿存储记录，不是标准身份。
3. 复制只复制可编辑内容与受控资产；不继承源 ID 或 `published_at`。再次从同一标准复制，也产生另一个独立 ID。界面使用“复制为新草稿”，不显示派生关系。
   - 创建请求可带一次性 `source_standard_id`；后端在标准库生命周期锁内读取对应已发布标准，请求文档只提供新 ID 与名称，其余内容以源标准为准。来源 ID 不持久化为新标准字段。
   - 实际复制源文档声明的全部 DWG/DWT 文件到新草稿目录，保留包内相对路径、资产 ID 与布局勾选；同一文件被多项资产引用时只复制一份，未声明文件不复制。来源可为官方或用户已发布标准，沿用受控路径、文件类型与 64 MiB 单文件大小门禁。
   - 副本独立于源文件，替换、删除新草稿或新标准的资产不影响原标准。模板全部复制成功后才写入草稿文档；来源缺失、路径非法、文件缺失、复制或文档写入失败时，撤销本次创建及全部副本，不留下可读取的半成品。
4. 草稿 `published_at: null`；首次发布在服务端写入 UTC Unix **毫秒**时间戳（JSON 整数），同一次发布只写一次。已发布标准的文档、ID、名称和发布时间不可原地修改；编辑内容需复制为新草稿。
5. 已发布包导入时保留原 UUID 和 `published_at`，不按导入时间重写。导入名称冲突时仅在导入确认边界改写新入库副本的 `name`，不修改来源文件；入库后仍只读。再次导出反映本机入库名称，ID 与发布时间不变。
6. `schema_version` 升为 `3`；新格式的已发布文档和 `.dststandard` manifest 必须含 UUID、非空名称及有效 `published_at`，不得含标准发布 `version`。新格式草稿必须含 UUID 和 `published_at: null`。旧格式不按新格式静默解析。
7. 界面将 UTC 时间戳转换为**运行设备的系统时区**，显示为 `YYYY/MM/DD HH:mm`（例如 `2026/09/28 14:30`），分钟补零；该样式是指定显示格式，并非 ISO 8601 字符串。API、包和磁盘只保存 UTC 时间戳，不保存格式化后的本地时间。
8. 现有发布检查中的「版本说明」改名为「标准描述」，存入文档顶层 `description`。它是可为空的纯文本：草稿可编辑、保存，发布和导出保留原文；已发布标准只读，复制为新草稿时复制其描述。新格式不再写入 `release_notes`。旧草稿或旧发布包的 `release_notes` 在经过验证的迁移中原样转入 `description`；若两字段同时存在，以明确的 `description` 为准并记录冲突，不静默丢弃旧文字。无可信描述的旧数据保持空值，不自动生成文案。

## 3. 名称、列表与操作入口

标准库按独立标准包**平铺**，不再按 ID 折叠成版本组，不显示 `v<n>`、最高版本或版本历史。列表仍支持已实现的名称／ID 搜索、来源（全部／官方／用户）过滤和状态（全部／草稿／已发布）过滤。列表卡片以名称为主信息，名称下方显示标准描述，过长时单行省略并允许查看完整文本；无描述时显示统一的空值提示。卡片不显示 UUID，UUID 仅在详情中完整显示并可复制，但名称／ID 搜索仍可命中。来源、状态及已发布时的本地发布时间是列表辅助信息；草稿不显示伪造的发布时间。列表响应需直接提供描述，避免为每张卡片单独请求详情。

名称比较继续使用既有 Unicode NFKC、首尾空白去除、连续空白归一及 `casefold()`。非空名称在官方、用户、草稿库中唯一；创建或复制草稿时若建议名称重复，要求用户输入不冲突名称后保存。草稿可在编辑期间改名，已发布标准不可改名。空名称草稿可暂存，但不得发布。

标准管理页顶部始终可见操作区，顺序为「新建草稿」「导入标准包」「返回欢迎页」；前两项位于返回按钮左侧，且不随列表滚动移出视口。窄视口允许换行，不改变动作顺序，不产生横向滚动。搜索和现有两种过滤保留在列表区域。

页面按已确认的静态 Demo 调整为顶部标题及操作区、左侧标准库卡片、右侧当前标准详情的主从布局；长列表只在列表区域滚动，操作入口始终可见。详情在标题下直接呈现状态、来源与操作，不在标题下显示标准描述；标准描述放在详情的「标准内容概览」中完整显示，UUID 与本地发布时间放在「基本信息」中。沿用产品现有主题令牌，在浅色／深色主题下保持同一信息层级与响应式行为。Demo 中的假数据、情境切换和“仅演示”提示不进入正式页面。

视觉参照：[已确认 Demo 的浅色页面截图](assets/SPEC-DM-020/standard-management-demo-light.png)。它用于核对页面层级、双栏比例、卡片密度、按钮与筛选器的位置、状态徽标和详情分区；截图摄于本次文字修订之前，其中「详情标题下的描述」和「列表卡片中的 ID」均**不属于验收目标**，应按本规范上段改为详情内容概览显示全文、列表名称下显示截断描述。正式实现应保留产品现有页眉、主题切换、组件与真实数据，不逐像素复制截图颜色或演示文案。

## 4. 导入与冲突

1. 维持“选择 `.dststandard` → 服务端复制到限时快照并预检 → 用户确认 → 只消费快照”的两步流程。
2. 先校验 ID：只要官方、用户或草稿库已有相同 UUID，预检即阻止导入，显示“已有同 ID 标准「XXX」”；不能通过改名绕过。候选包内容、名称或发布时间不同也一样阻止。
3. ID 不同而规范化名称相同时，预检返回名称冲突及可用的 `preview_id`；界面弹出改名输入，预填可编辑的建议名称。用户可取消。只有提交非空且不冲突的新名称后才可确认导入；原 UUID 与发布时间保持不变。
4. ID、名称都不冲突则可直接确认。确认阶段必须在库锁内重新检查 ID 和最终名称，避免预检后并发新增造成覆盖；冲突返回稳定 409，保持预检快照可供用户重新改名或重新预检。
5. 包结构、资产、路径和凭证安全门禁沿用 SPEC-DM-019；非法包不能通过改名进入库。预检与确认成功后均不得修改原始 `.dststandard` 文件。

## 5. 删除已发布标准及关联创建草稿

用户已发布标准与用户标准草稿均可删除；**官方标准不可删除**。已发布标准不可原地编辑。删除已发布标准时，服务端按 UUID 查找**未完成的图纸集创建草稿**，预览返回其数量与一次性确认凭证。确认界面写明“删除该标准时，将同时删除 N 个未完成的图纸集创建草稿”；N 为零时仍正常确认删除。用户取消则均不改变。官方标准在界面不提供删除入口，服务端同样拒绝其删除请求。

确认时在受控锁内重新核对关联草稿集合。创建图纸集草稿与启动创建任务也要通过同一生命周期门禁，避免扫描后、提交前新增引用或开始执行。若关联集合与预览时不同，返回冲突并要求重新显示数量、重新确认，不得把预览后新增的草稿静默纳入删除。用户确认后，标准包与预览中的关联草稿作为同一删除事务处理：失败或中断时恢复为全部保留，成功时全部从库和草稿列表消失；启动恢复能收敛未完成事务。未关联的草稿、其他标准及已创建图纸集不删除。

正在执行的图纸集创建任务仍需读取标准包及资产；若目标标准存在非终态创建任务，删除确认返回稳定冲突，提示待任务结束后重试，不能中途移走执行所需文件。已创建图纸集已有项目内标准快照，删除库内标准不移除项目快照，也不改写 DST/DWG。若旧工程本来缺少快照，继续按现有缺失诊断处理，不把库删除描述为可修复该缺失。

## 6. 创建链路与兼容边界

新创建草稿、计划、XLSX 元数据和新工程的 `DSTManager.Standard` 绑定都只使用 UUID；移除标准发布 `version`、`standard_version` 与 `id@version` 的**新写入**。完整标准包和资产仍在创建预览、执行阶段按固定 ID 查找，已发布标准的不可变性保证同一 ID 内容稳定。

旧 `schema_version: 2` 标准包、用户数据及旧 `id@version` 工程绑定必须在实施前清点。已有工程不得为了换身份而直接改写 DST 或项目快照；旧工程保留只读兼容解析，继续优先使用项目快照。若目标环境发现真实旧标准库、创建草稿或绑定工程，实施须先补经过验证的迁移映射与备份，不能删除旧数据、把文件时间或迁移时间冒充历史发布时间，也不能把多个旧版本合并为一个 UUID。没有可信发布时间的旧发布包仅在迁移兼容层中标记“发布时间未知”；任何**新发布或新导入**的 v3 包仍必须具有有效发布时间。

## 7. 验收要点

1. 新建、复制和从 DST 提取各自生成 UUID；复制两次得到两个不同 ID；草稿发布时间为空，发布后为稳定 UTC 毫秒值且不可编辑。
2. ID 相同优先阻止导入并显示现有名称；ID 不同而名称冲突可在对话框改名后导入，保留 ID 与发布时间；预检后库状态变化会重新阻止冲突。
3. 标准列表无版本组，搜索与来源／状态过滤仍可用；新建和导入按钮在返回欢迎页左边，列表滚动及窄视口仍可访问。
4. 删除确认展示关联创建草稿数量；取消无副作用，确认仅删除目标标准和确认时列出的草稿；并发新增、故障恢复和运行中任务均不造成部分删除。
5. 删除库内标准后，已有项目仍可从项目快照打开；新的创建流程不能再选择它。旧工程只读打开不改写 DST/DWG。
6. 发布检查使用「标准描述」字段；草稿保存、发布、导入导出和复制保留描述，旧 `release_notes` 迁移不丢文字。列表名称下一行显示可截断描述且不显示 UUID；详情标题下不显示描述，内容概览可查看全文。官方标准的删除入口和服务端删除能力均关闭。
