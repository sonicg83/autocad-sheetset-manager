# DST Manager v0.3.2 命名与模板流程需求变更规范

## 1. 背景

v0.3.1 交付后的实际使用中收集到四项需求性变更（2026-09-03 讨论评审确认）：

1. 组内图纸标题的序号后缀不进入 DWG 文件名：重复标题派生的 DWG 文件名只含基础标题（如 `RQ-01-02 图纸目录.dwg`），与图纸标题（`图纸目录 (1)`、`图纸目录 (2)`）脱节，检索时不直观；
2. 批量新增图纸的"已有布局"来源（`existing_snapshot`）仍要求用户手选来源文件与来源布局，但该来源的实际语义应当就是目标子集自身的 DWG 与布局，手动选择多余且易错；
3. 批量新增图纸与新建子集的表单文案中"来源/模板"措辞不统一，两处"模板"含义不同（提供 DWG 基底 vs 提供布局），需要拆分命名；
4. 新建子集时布局模板文件身兼两职（既复制为新子集 DWG 基底、又提供布局来源），无法表达"图纸模板"与"布局模板"分离的真实工作流。

同时，原随界面重构版本执行的两项后端/表单事项并入本迭代（2026-09-03 决策）：

5. `application/service.py`（1984 行）超出「代码组织契约」软上限，其全量拆分（原定随 v0.3.2 界面重构，见 [DMv031-deferred-findings](../../../.planning/memos/dst-manager/DMv031-deferred-findings.md)）调整为**先于本迭代功能变更执行**——本迭代 Task 正要修改该文件的来源校验逻辑，先拆分可让功能 diff 落在拆分后的模块上；
6. 遗留评审项 M6（`closeWorkspace` 不重置批量新增图纸表单模板状态）与 M4（`loadLayoutOptions` 硬编码 `cad_version: "2020"`）与本次表单重构直接重叠，顺带吸收。

版本基线调整：本规范驱动的迭代为 **v0.3.2**；原定 v0.3.2 的 [SPEC-DM-006](SPEC-DM-006-dst-manager-desktop-ui-ux.md) 界面重构推后为 **v0.3.3**（其计划编号 PLAN-DM-010 含义不变），M1-M5、M7 与 T 系列其余遗留项随 v0.3.3 处理。

## 2. 目标与非目标

### 2.1 目标

1. 组内多张图纸的序号后缀按压缩规则进入 DWG 文件名；
2. 批量新增图纸选"已有布局"时，来源文件与来源布局不再由用户选择，强制解析为目标子集的 DWG 文件与第一个非 Model 布局；
3. 统一批量新增图纸与新建子集的表单文案；
4. 新建子集增加必填的"基础模板文件"（图纸模板），新子集 DWG 基底与布局来源彻底分离；
5. `application/service.py` 完成全量拆分（先纯辅助簇、再功能域），拆分后行为零变化；
6. 关闭 M6（表单模板状态重置）与 M4（布局读取版本一致性）。

### 2.2 非目标

- 不改变图号分配、布局名派生（`{number} {title}`）、标题后缀类型（中文/阿拉伯数字）与后缀开关的既有规则；
- 不改变发布事务、整批回滚、`DST -> XML DOM -> DST` 受控流程与 CAD 分流门禁（[ARCH-DM-001](../architecture/ARCH-DM-001-dst-manager-mvp-baseline.md)、[ADR-DM-003](../adr/ADR-DM-003-deferred-cad-validation-and-subset-cad-operations.md)）；
- 不为"已有布局"解析新增 CAD 脚本调用或布局缓存交互——解析只读 DST 文件本身；
- 不引入 [SPEC-DM-006](SPEC-DM-006-dst-manager-desktop-ui-ux.md) 的设计令牌与组件系统（v0.3.3 范围）。

## 3. 序号后缀进入 DWG 文件名（F-01）

### 3.1 现状

- 同一子集内图纸按基础标题统一派生标题（`derive_group_titles`）；组内多张（或跨子集同标题合计多张）时标题带序号后缀，格式为 `基础标题 (后缀)`，后缀为中文数字或阿拉伯数字；
- DWG 文件名由 `_target_file_name` 以**基础标题**生成：`{前缀}{图号范围} {基础标题}.dwg`。

### 3.2 派生规则

文件名标题部分改为组内带后缀标题的**压缩拼接**：

- 组内所有图纸共享同一基础标题（受控派生保证），每个标题形如 `基础标题 (后缀)`；
- 多张时：`基础标题 (首后缀)-(末后缀).dwg`，即公共前缀 `基础标题 (` + 首张图纸后缀 + `)-(` + 末张图纸后缀 + 收尾 `)`（区间压缩，仅保留首末序号，如六张为 `(一)-(六)`）；
- 组内仅一张（无后缀）时：`{前缀}{图号范围} {基础标题}.dwg`，与现状完全一致，向后兼容；
- 标题不符合 `基础标题 (后缀)` 结构（理论不可达，防御性回退）时沿用基础标题。

示例（阿拉伯数字后缀）：

| 图纸标题 | 图号范围 | 现状文件名 | 目标文件名 |
| --- | --- | --- | --- |
| 图纸目录 | RQ-01 | RQ-01 图纸目录.dwg | RQ-01 图纸目录.dwg（不变） |
| 图纸目录 (1)、图纸目录 (2) | RQ-01-02 | RQ-01-02 图纸目录.dwg | RQ-01-02 图纸目录 (1)-(2).dwg |
| 图纸目录 (一)、图纸目录 (二) | RQ-01-02 | RQ-01-02 图纸目录.dwg | RQ-01-02 图纸目录 (一)-(二).dwg |

- 布局名（`{number} {title}`）、图纸标题、图号与范围派生不受影响；
- 文件名长度上限（240）与不安全字符校验沿用；多个子集派生同名文件的 `DWG_TARGET_COLLISION` 检查沿用；
- **项目前缀对齐**：派生文件名的前缀优先取来源 DWG 文件名自带前缀（如来源 `RQ-01 图纸目录.dwg` → `RQ-`）；来源为模板文件（无前缀）时，回退采用从图纸集既有 DWG 登记名提取的项目级前缀，使新建子集的 DWG 文件名与图纸集原有文件对齐（如既有 `RQ-001-002 …` → 新子集 `RQ-003-004 主要设备及材料表 (一)-(二).dwg` 而非 `003-004 …`）；
- 规划展示名（`{图号范围} {基础标题}`）不变，仅派生 DWG 文件名受影响。

## 4. "已有布局"强制使用目标子集（F-02）

### 4.1 行为定义

- 批量新增图纸的模板来源选"已有布局"（`existing_snapshot`）时，前端禁用并隐藏"布局模板文件"与"布局模板名称"输入，显示只读说明：来源为目标子集 DWG 的第一个非 Model 布局；
- 后端契约 `LayoutSource` 对 `existing_snapshot` 放宽 `file`/`layout` 为可选字段（`template_layout` 仍必填）；命令提交时不携带文件与布局；
- 解析在预览规划期完成，**只读 DST 文件本身**（不调用 accoreconsole、不读布局缓存）：
  - 目标子集 DWG 文件 = 该子集第一张图纸在 DST 中登记的 DWG 路径（既有 `_source_target_file` 语义）；
  - 来源布局 = 该子集第一张图纸在 DST 中登记的布局名（DST 图纸均为纸空间布局，不存在 Model）；
- 解析结果回填 source 后进入既有规划、预览与执行链路；预览中逐布局展示解析出的 `source_file`/`source_layout`（只读），用户可确认实际来源。

### 4.2 失败处理

- 目标子集在 DST 中无 DWG 登记（如子集尚未创建过 DWG）导致无法解析时，预览规划阶段报 `LAYOUT_SOURCE_INVALID` 明确阻断（无法生成有意义预览，不产生半预览）；
- DST 解析成功但执行期发现实际问题（DWG 文件已删除、布局缺失、文件被 AutoCAD 占用等）不前置校验，由 CAD 任务失败后走**现有整批回滚**兜底；
- 来源基准快照（SHA-256）机制保留，作用于解析出的目标子集 DWG，防止预览与执行之间文件变化。

### 4.3 校验边界

- 解析出的 DWG 天然位于工作区内且为 `.dwg`，既有 `existing_snapshot` 的越界与扩展名校验改为作用于**解析后**的文件（防御性保留，语义不变）；
- `template_layout` 来源的行为与校验完全不变。

## 5. 表单文案统一（F-03）

| 位置 | 现状文案 | 目标文案 |
| --- | --- | --- |
| 批量新增图纸 | 来源类型 | 模板来源 |
| 批量新增图纸 | 来源文件 | 布局模板文件 |
| 批量新增图纸 | 来源布局 | 布局模板名称 |
| 新建子集 | 模板文件 | 布局模板文件 |
| 新建子集 | 模板布局 | 布局模板名称 |

仅改用户可见文案，不改字段名、API 契约与状态变量名。

### 5.1 顺带修复的遗留项（M6/M4，归入 F-03 表单域）

- **M6**：`closeWorkspace` 重置时同步清空批量新增图纸与新建子集表单的模板文件、模板布局与布局选项状态（本次新增的基础模板文件状态一并纳入），避免重开工作区后残留旧模板路径；
- **M4**：`loadLayoutOptions` 的 `cad_version` 改用当前工作区的 `cadVersion` 响应式值，去除硬编码 `"2020"`。

## 6. 新建子集基础模板文件（F-04）

### 6.1 契约与输入

- `InsertSubsetCommand` 新增必填字段 `base_template_file`（基础模板文件，定位为**图纸模板**）：绝对路径，扩展名接受 `.dwg` 与 `.dwt`，校验复用既有绝对路径/危险名称校验；
- 原 `source` 字段含义收窄为**布局模板来源**（提供布局，类型仍固定 `template_layout`）；
- 前端新建子集表单新增"基础模板文件"文件选择器（必填，过滤器 `.dwg/.dwt`），未选择时不允许提交。

### 6.2 创建流程

1. 复制**基础模板文件**作为新子集 DWG 文件的基底（即既有 `source_snapshot` 语义，规划时 `source_snapshot` 由布局模板文件改为基础模板文件）；
2. 布局仍按现有 `-LAYOUT _Template` 流程从**布局模板文件**的指定布局复制（SCR 渲染、Worker 插件、Handle 回读全部不变）。

即：DWG 基底与布局来源解耦——基础模板文件决定"这张图纸画在什么样的图纸环境里"，布局模板文件决定"新增布局长什么样"。

### 6.3 失败处理

- 基础模板文件不存在或扩展名非法：契约校验阶段拒绝（提交即报错）；
- 复制/执行阶段失败：走现有整批回滚与启动恢复机制。

## 7. 代码组织拆分（F-05）

`application/service.py`（1984 行）按 [AGENTS.md「代码组织契约」](../../../AGENTS.md) 与 [DMv031-deferred-findings](../../../.planning/memos/dst-manager/DMv031-deferred-findings.md) 已决策方案全量拆分，**先于本规范第 3-6 节的功能变更执行**：

1. **阶段一（纯辅助簇）**：`_build_semantic_diff`、`_summarize_*`、`_operation_digest` 等 ~600 行无状态辅助函数迁移到同层独立模块，行为零变化；
2. **阶段二（功能域拆分）**：`DstManagerService` 只保留跨功能域公共编排与共享门禁（workspace 门禁、修订检查、事务辅助），drafts/editing/revisions/xml_io/repair 等功能域按域拆分到同层独立模块并在入口组合。

约束：

- 拆分保持既有公共接口、错误码与序列化契约不变；
- 以既有全量测试为安全网，拆分本身不新增行为，不与本规范功能变更混合提交；
- 功能变更（第 3-6 节）落在拆分后的模块结构上，后续新增功能优先新建同层模块组合。

## 8. 架构边界与安全约束

以下既有约束不因本迭代改变，逐条适用：

- DST 修改仍必须经过 `DST -> XML DOM -> DST` 受控流程；本迭代不新增写入路径；
- 用户提供的路径（布局模板文件、基础模板文件）继续保留绝对路径、危险名称与扩展名校验；"已有布局"的解析结果来源于 DST 内部登记，不引入新的外部输入面；
- CAD 操作只经固定命令、固定 SCR 渲染器与匹配版本 Worker 插件执行；
- 正式写入继续保留永久 before 快照、锁、暂存校验、发布日志与可回滚事务。

## 9. 错误处理汇总

| 场景 | 处理 |
| --- | --- |
| "已有布局"来源但目标子集无 DWG 登记 | 预览规划期 `LAYOUT_SOURCE_INVALID` 阻断（§4.2） |
| 解析出的 DWG 执行期缺失/占用/布局缺失 | CAD 任务失败 → 整批回滚（既有机制） |
| 预览与执行之间目标子集 DWG 变化 | 来源基准 SHA-256 校验失败阻断（既有机制） |
| 新建子集未选/错选基础模板文件 | 契约校验拒绝（422，字段必填 + 扩展名白名单） |
| 派生文件名含不安全字符或超长 | 沿用 `DWG_FILE_NAME_INVALID` |
| 派生 DWG 文件名撞名 | 沿用 `DWG_TARGET_COLLISION` |

## 10. 测试与验收

- **单元（domain）**：文件名压缩拼接（中文/阿拉伯后缀、单张兼容、结构异常回退）；`existing_snapshot` 可选来源的解析与无登记报错；`base_template_file` 契约校验（必填、扩展名）；
- **单元/集成（application）**：拆分前后全量测试等价（行为零变化的安全网）；`source_snapshot` 改用基础模板文件；`existing_snapshot` 基准快照作用于解析后文件；OpenAPI 契约再生成（`npm run generate:api`，LF 门禁）；
- **Web 交互**：既有 Playwright 用例随文案与表单结构调整后全绿；
- **真实 CAD 系统测试**：具备环境时以 `DST_MANAGER_RUN_AUTOCAD=1` 验证"基础模板文件（.dwg 与 .dwt 各一）+ 布局模板"的新建子集流程；
- 生产构建（`npm run build`）与 Ruff/pytest 基线照常执行。
