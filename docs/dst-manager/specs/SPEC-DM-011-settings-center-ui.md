# 设置中心 UI 设计规范

> 状态：草稿（G4 Demo 待用户操作确认与冻结；G6 起进入实施计划）
> 定位：设置中心前端子项目的权威交互 Spec。架构、API 契约、存储与校验语义的权威是 [ARCH-DM-004](../architecture/ARCH-DM-004-settings-center.md)，本文只引用不复制；视觉基准来源为 [设计冻结包](#7-设计冻结包)（含[交互 Demo](../mockups/SPEC-DM-011-settings-demo.html)）。门禁方法依据 [GUIDE-DM-001](../guides/GUIDE-DM-001-frontend-design-implementation-gates.md)。

## 1. G0 立项与范围

- **一句话**：让用户在不加载 DST、不编辑 `.env` 的前提下，通过桌面界面查看、修改应用配置并了解软件版本与协议。
- **变更等级**：L 级——触碰共享外壳（顶部栏）、后端契约（`/api/settings`、`/api/about`）、桌面壳（ShellBridge 新增原生选择器/外链）、发布链路（PyInstaller spec 数据文件）。已拆分为两个可独立验收的子项目：
  - **子项目 A（配置域后端）**：resolver / store / 快照 / Worker 传播 / API / 打包触点。纯后端，GUIDE-DM-001 不适用，按 ARCH-DM-004 §7 测试策略验收。
  - **子项目 B（本 Spec）**：设置中心 UI，走 G0～G9 全流程。
- **范围**：顶部齿轮入口、设置模态对话框（常规配置 + 扩展 + 关于）、动态表单渲染、原生路径选择器桥接、来源/覆盖标记、外链、诊断横幅、内置扩展的启停与状态查看。
- **非目标**：扩展自身的设置与工作区偏好编辑（仍只归扩展页面，ARCH-DM-006 §8）；完整扩展中心（安装/卸载/市场/依赖管理，PRD-DM-001 后续立项）；扩展卡片基线的推迟项（多列网格、搜索/筛选/排序、分页与虚拟滚动、卡片可展开详情、图标与品牌资源、批量启停、依赖关系可视化）——重启条件写在 §3.3；`data_dir`/`draft_dir` 界面化；模板目录；第三方组件声明页；主题或全局导航改动。

> **修订（2026-09-10，「停用不可逆」缺陷修复）**：原非目标整条排除「扩展中心」，导致启停入口的归属无人认领——启停控件只长在扩展自己的页面上（`SheetCatalogView` 的「停用扩展」），而 [ARCH-DM-006](../architecture/ARCH-DM-006-builtin-extension-platform.md) §7 要求停用后移除该页面入口，开关因此变成单向：用户点一次停用就再也找不到启用入口，且启停意图持久化在 `extension_states`（重启对账仍会重新停掉），被永久卡死。现将非目标收窄为：设置中心**只**承载内置扩展的启停与状态查看，扩展自身设置与偏好仍归扩展页面（ARCH-DM-006 §8），完整扩展中心仍属后续立项。启停入口唯一固定在设置中心，扩展页面不再提供停用（否则停用会移除该页入口本身）。

> **修订（2026-09-10，启停交互改进：滑动开关 + 停用不关窗）**：上一版修复确立了「入口唯一在设置中心」，但交互上有两处遗留：启停控件是文字按钮（开关方向只能靠"启用/停用"字样反推，看不出当前状态），且停用会**立即关闭设置窗口**。后者并非产品意图，而是被模态层叠逼出来的：设置窗口是原生 `<dialog showModal>`，进入 top layer 后页面其余内容 inert，而当时的闸门模态（宿主未提交输入三选一 `UnsavedInputDialog`、目录页三选一）都是**页面内联遮罩**，会被设置窗口 inert 吞掉（用户看得见弹框却点不动，PATCH 永远不会发出），所以只能先关窗让位。
>
> 本次改从根因下手：两个闸门模态均改为原生 `<dialog showModal>`，由平台 top layer 自行叠在设置窗口之上，遮罩（`::backdrop`）、焦点圈闭与 Esc 归属一并交给平台（Esc 只作用于最上层模态，不再需要各窗口互相感知）。于是设置窗口无需再为闸门让位，停用与启用完全对称：落库 → 成功就地收敛 → 失败就地行内呈现。连带简化两处：停用不再关闭窗口，也就不会丢弃本对话框的编辑缓冲，「放弃修改并关闭」前置确认随之删除；原「焦点归还被移除标签的邻近标签」也随之失效（停用时标签栏处于 inert，对 inert 元素调 `focus()` 是空操作），焦点改为收敛在对话框内并归还到同一开关。
- **权威来源**：业务行为 → ARCH-DM-004；交互与状态 → 本文；视觉 → 设计冻结包；实施顺序 → 后续 Plan。
- **同主题检索**：无既有 Spec/Plan/Demo 覆盖设置中心；PRD-DM-001 仅定义扩展平台预留边界。

## 2. G1 业务目标

- **主要用户**：使用 DST Manager 桌面软件的单机用户（非开发者，不应被要求编辑 `.env`）。
- **核心用户任务**（按重要性）：
  1. 配置 AutoCAD 版本路径（首次使用的前置任务）；
  2. 调整任务执行参数（超时/并发/租约）；
  3. 切换编号规则选项；
  4. 查看版本号、开源协议与反馈入口。
- **可观察成功标准**：不加载 DST 即可完成上述全部任务；每项修改保存后无需重启即对下一次操作生效；误输入在保存前得到行内提示；用户可把任一项恢复为继承值。
- **不可变约束**：服务只监听 `127.0.0.1`；配置语义权威为 Pydantic Settings（ARCH-DM-004 §2.1）；凭据永不进入设置。
- **数据描述**：典型 9 个配置项、4 个分组、2 个分区；极端为超长路径（>200 字符）、含中文与空格的路径、被网络盘断开的路径。

## 3. G2 用户流程与状态矩阵

### 3.1 流程

- **入口**：顶部栏齿轮（常驻，含未加载工作区态）→ 打开设置对话框。
- **主路径**：选择分区 → 修改字段 → 即时校验 → 保存（PUT）→ 已保存反馈 → 继续或关闭。
- **取消路径**：无修改时 Esc/✕/遮罩直接关闭；有修改时确认（放弃/留在此处）后关闭。
- **失败恢复路径**：校验失败 → 行内错误 + 焦点定位，输入保留；保存失败（写入/权限）→ 错误横幅，内存值不替换，用户可重试或关闭；配置文件损坏 → 诊断横幅 + 已回退默认提示；Schema 过新 → 只读诊断态。
- **扩展分区路径**：打开分区时拉取扩展清单（不依赖工作区是否已加载，故未加载 DST 也能恢复被停用的扩展）→ 拨动滑动开关即时落库（不进入底部保存缓冲）→ 停用时经宿主的未保存输入三选一闸门（闸门是原生模态，叠在设置窗口之上；选「留在此处」则停用中止）→ 成功后就地收敛开关与状态文字，失败就地行内呈现。设置窗口全程不关闭，由用户手动关闭。
- **导航关系**：对话框悬浮于任何页面之上；关闭后焦点归还齿轮；不改变底层页面状态（工作区、草稿、任务浮层不受影响）。

### 3.2 状态矩阵

| 类别 | 状态 |
| --- | --- |
| 生命周期 | 初始（GET 加载中）、加载成功、加载失败（重试）、空（无诊断） |
| 编辑 | 未修改、编辑中、校验失败（逐字段）、待保存、保存中、保存成功（短暂提示）、保存失败 |
| 数据 | 短/长路径、缺失值（`null`）、来源 default/env/file、有覆盖/无覆盖、损坏文件、Schema 过新 |
| 导航 | 未加载工作区打开、已加载工作区打开、分区切换、关闭后焦点归还、重复打开 |
| 视图 | 浅色、深色、最小支持视口、200% 缩放、面板内滚动 |
| 权限与能力 | 桌面壳（桥可用 → 浏览按钮可用）、浏览器开发态（浏览禁用、手输保留）、外链能力 |
| 扩展分区 | 清单加载中、加载失败（重试）、空（无已登记扩展）、已启用、已停用、天然不可用（启动失败/不兼容）、启停处理中、启停失败 |
| 扩展卡片（SC-16） | 条目数 1（最小、不分段）/ 4（多状态：启用、停用、启动失败、不兼容）/ 8（触发按 `enabled` 分段）；卡片信息：名称+版本、描述、状态徽标、诊断码（有值时）；与上述主题/视口/缩放维度组合 |

### 3.3 关键状态规则

- 保存采用"全有或全无"（ARCH-DM-004 §3）；失败时逐字段显示后端错误，输入保留。
- 编辑期间后端值被外部改变（本设计下仅另一进程 `serve` 可能）→ 保存返回 409，对话框刷新快照并提示重新确认（输入保留）。
- `enable_add_number_suffix`、`number_suffix_type`、`cad_max_parallel` 保存成功后显示"已保存，相关预览将按新配置重算"提示（SC-13）。
- 扩展分区开关点击即落库（`PATCH /api/extensions/{id}/state`），**不**进入底部「保存/取消」缓冲；分区内固定说明该语义，避免用户误以为取消可回滚开关。
- 启停控件是滑动开关（`role="switch"` + `aria-checked`），并在开关旁给出可见状态文字「已启用/已停用」：方向不得只靠颜色或滑块位置表达；状态文字对辅助技术隐藏，语义由 `aria-checked` 承担，避免重复播报。
- 从设置中心停用扩展时**不**关闭设置对话框：宿主未提交输入三选一与目录页三选一都是原生 `<dialog showModal>`，由平台 top layer 叠在设置窗口之上，可见且可点击；Esc 归最上层模态处理，不会连带关闭设置窗口。停用既然不再关窗，也就不会丢弃本对话框的编辑缓冲，故不再需要「放弃修改并关闭」前置确认。
- 扩展是否启用以服务端 `enabled` 为准，不用 `status` 反推：`FAILED`/`INCOMPATIBLE` 等"天然不可用"值与用户启停意图在 `extension_states` 上可区分（ARCH-DM-006 §5）。
- **扩展卡片基线（SC-16）——语义角色**：卡片是**状态容器 + 唯一开关**，不可点击、不提供导航，也不承载扩展自身设置的入口（后者归扩展页面，ARCH-DM-006 §8）。将来若需要扩展详情页，必须另立 Spec 定义入口，不得直接让卡片长出导航。
- 卡片固定四层信息，顺序与字段权威固定：①名称（`name_key`）与版本（`version`）；②描述（`description_key`，随包清单已有、宿主 i18n 渲染）；③状态徽标（`status` 九值）+ 诊断码（`error_code` 有值时显示稳定枚举名，不显示原始异常文本）；④开关（`enabled`）与可见状态文字。`actions` 与 `ui_contributions` 不进卡片。
- **条目增长机制只有唯一预设答案**：单列卡片 + 面板内滚动；条目 **≥6 条**时按 `enabled` 分「已启用 / 已停用」两段（分组键必须与开关同一权威，否则同一卡片会在两段之间跳变），分组标题不显示计数。搜索、筛选、排序、分页、虚拟滚动、多列网格均为非目标；**重启条件是平台具备运行时安装能力**（第三方/市场/依赖管理立项、ARCH-DM-006 非目标解除），届时按新规模重新裁决本节。
- 布尔状态控件只有一种视觉语言：滑动开关（`role="switch"` + `aria-checked` + 轨道/滑块用既有令牌）。扩展启停（点击即落库）与常规配置的缓冲式 bool 字段（保存时落盘）**共用同一形态**，语义差异由分区文案（「启停立即生效，不受下方取消影响」）与「保存」按钮是否点亮传达，不靠控件形态区分。
- 卡片列表使用 `ul/li` 列表语义；开关可访问名沿用「启用 {name}」/「停用 {name}」（随状态翻转），可见状态文字「已启用/已停用」对辅助技术隐藏（`aria-hidden`），语义由 `aria-checked` 承担；卡片内唯一可聚焦元素是开关，Tab 顺序即 DOM 顺序，不引入 roving tabindex 与方向键导航。

## 5. G3 视觉方向裁决

- **比较过的方向**：
  1. **独立工作区标签页**——否决：设置是全局能力，标签栏在未加载 DST 时不出现，无法满足"未加载即可配置"；且稀释业务标签语义。
  2. **顶部齿轮 + 模态对话框（选定）**——用户裁决（2026-09-07，ASCII 草图确认）：入口常驻、形态与既有确认模态一致。
- **沿用基准**：SPEC-DM-006 设计令牌（色彩/圆角/阴影/间距/焦点环）、既有 `<dialog>` 模态模式（焦点圈闭 + `::backdrop` + 焦点归还）、表单行内错误模式（SPEC-DM-010 属性页 `.property.error` + `.field-error`）、徽章状态语言。
- 无新增全局 CSS 规则；对话框样式限定于组件作用域。
- **第二次裁决（2026-09-10，扩展卡片基线）**：
  1. **单列卡片行（选定）/ 两列网格（否决）**——面板可用宽约 570px，两列会同时挤窄名称、版本、状态与开关，中文长扩展名与描述折行更严重；且条目是随发版逐个加入（ARCH-DM-006 §4.1 固定索引），不是运行时批量涌入。
  2. **≥6 条按 `enabled` 分段（选定）/ 一开始就分段 / 现在就上搜索+筛选（否决）**——固定索引下近期规模为个位数；分段是零成本的第一杠杆，搜索与筛选在只有 1 条扩展时不产生价值。
  3. **四层信息（选定）/ 紧凑三层 / 含能力清单五层（否决）**——描述与诊断码是"为什么不可用"的唯一答案，必须有位置；`ui_contributions`/`required_capabilities` 属扩展自身页面。
  4. **卡片不可点击（选定）/ 失败时展开诊断 / 点入扩展页面（否决）**——后两者都会把设置中心变成第二个扩展入口，与 ARCH-DM-006 §8 冲突；"失败时展开"还需要先定义重试语义（见第 4 项讨论的待决点）。
  5. **布尔状态控件统一为滑动开关（选定）**——同一对话框内不再并存两种"开关"外观；代价是 `SettingsFormRow.vue` 的 bool 控件与卡片布局必须在同一实现批次落地（§6 已记）。
