# 设置中心 UI 设计规范

> 状态：已确认（G4 第三次重开（扩展全局设置入口 SC-17）已于 2026-09-12 经用户确认通过，确认记录见 [MEMO-DM-034](../../../.planning/memos/dst-manager/2026-09-12-plan-dm025-g4-confirmation.md)；生产实现由 PLAN-DM-025 任务 7/8 交付，G8 生产证据于 2026-09-13 补入 §7；G9 已于 2026-09-13 由用户在真实桌面壳验收通过，见 §8、§9）
> 定位：设置中心前端子项目的权威交互 Spec。架构、API 契约、存储与校验语义的权威是 [ARCH-DM-004](../architecture/ARCH-DM-004-settings-center.md)，本文只引用不复制；视觉基准来源为 [设计冻结包](#7-设计冻结包)（含[交互 Demo](../mockups/SPEC-DM-011-settings-demo.html)）。门禁方法依据 [GUIDE-DM-001](../guides/GUIDE-DM-001-frontend-design-implementation-gates.md)。

## 1. G0 立项与范围

- **一句话**：让用户在不加载 DST、不编辑 `.env` 的前提下，通过桌面界面查看、修改应用配置并了解软件版本与协议。
- **变更等级**：L 级——触碰共享外壳（顶部栏）、后端契约（`/api/settings`、`/api/about`）、桌面壳（ShellBridge 新增原生选择器/外链）、发布链路（PyInstaller spec 数据文件）。已拆分为两个可独立验收的子项目：
  - **子项目 A（配置域后端）**：resolver / store / 快照 / Worker 传播 / API / 打包触点。纯后端，GUIDE-DM-001 不适用，按 ARCH-DM-004 §7 测试策略验收。
  - **子项目 B（本 Spec）**：设置中心 UI，走 G0～G9 全流程。
- **范围**：顶部齿轮入口、设置模态对话框（常规配置 + 扩展 + 关于）、动态表单渲染、原生路径选择器桥接、来源/覆盖标记、外链、诊断横幅、内置扩展的启停与状态查看、声明设置的扩展在设置中心内的统一配置入口（`generated` / `custom`，SC-17），以及 AutoCAD 版本与持久主题的唯一配置入口（SC-18）。
- **非目标**：扩展的工作区偏好编辑（ARCH-DM-006 §8.3 只由宿主 best-effort 记录上次选中模板，用户不直接编辑）；完整扩展中心（安装/卸载/市场/依赖管理，PRD-DM-001 后续立项）；扩展卡片基线的推迟项（多列网格、搜索/筛选/排序、分页与虚拟滚动、卡片可展开详情、图标与品牌资源、批量启停、依赖关系可视化）——重启条件写在 §3.3；`data_dir`/`draft_dir` 界面化；模板目录；第三方组件声明页；除 SC-18 外的主题或全局导航改动。

> **修订（2026-09-16，应用偏好归一）**：用户确认把 AutoCAD 版本与浅/深主题纳入配置中心持久保存。Topbar 移除 AutoCAD 版本选择，避免同一持久偏好出现第二入口；主题按钮保留为会话级临时切换，不落 `localStorage`，刷新/重启后以配置中心 `ui_theme` 为准。配置中心明确保存主题时立即应用；保存无关配置不清除当前会话的临时主题。

> **修订（2026-09-10，「停用不可逆」缺陷修复）**：原非目标整条排除「扩展中心」，导致启停入口的归属无人认领——启停控件只长在扩展自己的页面上（`SheetCatalogView` 的「停用扩展」），而 [ARCH-DM-006](../architecture/ARCH-DM-006-builtin-extension-platform.md) §7 要求停用后移除该页面入口，开关因此变成单向：用户点一次停用就再也找不到启用入口，且启停意图持久化在 `extension_states`（重启对账仍会重新停掉），被永久卡死。现将非目标收窄为：设置中心**只**承载内置扩展的启停与状态查看，扩展自身设置与偏好仍归扩展页面（ARCH-DM-006 §8），完整扩展中心仍属后续立项。启停入口唯一固定在设置中心，扩展页面不再提供停用（否则停用会移除该页入口本身）。**（注：本条里“扩展自身设置仍归扩展页面”已被 2026-09-12 修订取代——扩展设置改由设置中心的「配置」入口承载，见下一条修订）**

> **修订（2026-09-10，启停交互改进：滑动开关 + 停用不关窗）**：上一版修复确立了「入口唯一在设置中心」，但交互上有两处遗留：启停控件是文字按钮（开关方向只能靠"启用/停用"字样反推，看不出当前状态），且停用会**立即关闭设置窗口**。后者并非产品意图，而是被模态层叠逼出来的：设置窗口是原生 `<dialog showModal>`，进入 top layer 后页面其余内容 inert，而当时的闸门模态（宿主未提交输入三选一 `UnsavedInputDialog`、目录页三选一）都是**页面内联遮罩**，会被设置窗口 inert 吞掉（用户看得见弹框却点不动，PATCH 永远不会发出），所以只能先关窗让位。
>
> 本次改从根因下手：两个闸门模态均改为原生 `<dialog showModal>`，由平台 top layer 自行叠在设置窗口之上，遮罩（`::backdrop`）、焦点圈闭与 Esc 归属一并交给平台（Esc 只作用于最上层模态，不再需要各窗口互相感知）。于是设置窗口无需再为闸门让位，停用与启用完全对称：落库 → 成功就地收敛 → 失败就地行内呈现。连带简化两处：停用不再关闭窗口，也就不会丢弃本对话框的编辑缓冲，「放弃修改并关闭」前置确认随之删除；原「焦点归还被移除标签的邻近标签」也随之失效（停用时标签栏处于 inert，对 inert 元素调 `focus()` 是空操作），焦点改为收敛在对话框内并归还到同一开关。
> **修订（2026-09-12，扩展全局设置入口）**：[ARCH-DM-006](../architecture/ARCH-DM-006-builtin-extension-platform.md) §8.2 已把设置中心定为**所有扩展配置的统一入口**：扩展卡片在声明设置时显示文字按钮「配置」，没有设置时不显示；简单标量与枚举配置用 `generated`（宿主按 Provider 字段生成表单），模板集合、字段映射、表达式等复杂设置用 `custom`（打开编译期白名单组件，不退化为 JSON 文本框）。因此本次改判：§1 非目标不再排除“扩展自身的设置”，而收窄为“扩展的工作区偏好编辑（§8.3，用户不直接编辑）”；§3.3 与 §5 第二次裁决第 4 项的“卡片不得承载设置入口”相应修正为“卡片本体仍不可点击、不导航，但声明设置的卡片动作行出现「配置」按钮”。随之新增 SC-17（统一配置入口、同一对话框子视图、无工作区访问、按扩展独立保存、焦点归还、脏状态闸门），Demo 与冻结包新增 `g4-13～g4-15`，并重开 G4（待用户对新 Demo 操作确认，见 §8）。本次重开与 PLAN-DM-025（任务 5）同批，生产实现属任务 7/8。

- **权威来源**：业务行为 → ARCH-DM-004；交互与状态 → 本文；视觉 → 设计冻结包；实施顺序 → 后续 Plan。
- **同主题检索**：无既有 Spec/Plan/Demo 覆盖设置中心；PRD-DM-001 仅定义扩展平台预留边界。

## 2. G1 业务目标

- **主要用户**：使用 DST Manager 桌面软件的单机用户（非开发者，不应被要求编辑 `.env`）。
- **核心用户任务**（按重要性）：
  1. 配置 AutoCAD 版本路径并选择任务使用的 AutoCAD 版本（首次使用的前置任务）；
  2. 选择应用启动时使用的浅色/深色主题；
  3. 调整任务执行参数（超时/并发/租约）；
  4. 切换编号规则选项；
  5. 查看版本号、开源协议与反馈入口。
- **可观察成功标准**：不加载 DST 即可完成上述全部任务；每项修改保存后无需重启即对下一次操作生效；误输入在保存前得到行内提示；用户可把任一项恢复为继承值。
- **不可变约束**：服务只监听 `127.0.0.1`；配置语义权威为 Pydantic Settings（ARCH-DM-004 §2.1）；凭据永不进入设置。
- **数据描述**：当前 13 个配置项、5 个分组、3 个分区；极端为超长路径（>200 字符）、含中文与空格的路径、被网络盘断开的路径。

## 3. G2 用户流程与状态矩阵

### 3.1 流程

- **入口**：顶部栏齿轮（常驻，含未加载工作区态）→ 打开设置对话框。
- **主路径**：选择分区 → 修改字段 → 即时校验 → 保存（PUT）→ 已保存反馈 → 继续或关闭。
- **取消路径**：无修改时 Esc/✕/遮罩直接关闭；有修改时确认（放弃/留在此处）后关闭。
- **失败恢复路径**：校验失败 → 行内错误 + 焦点定位，输入保留；保存失败（写入/权限）→ 错误横幅，内存值不替换，用户可重试或关闭；配置文件损坏 → 诊断横幅 + 已回退默认提示；Schema 过新 → 只读诊断态。
- **扩展分区路径**：打开分区时拉取扩展清单（不依赖工作区是否已加载，故未加载 DST 也能恢复被停用的扩展）→ 拨动滑动开关即时落库（不进入底部保存缓冲）→ 停用时经宿主的未保存输入三选一闸门（闸门是原生模态，叠在设置窗口之上；选「留在此处」则停用中止）→ 成功后就地收敛开关与状态文字，失败就地行内呈现。设置窗口全程不关闭，由用户手动关闭。
- **导航关系**：对话框悬浮于任何页面之上；关闭后焦点归还齿轮；不改变底层页面状态（工作区、草稿、任务浮层不受影响）。

### 3.3 关键状态规则

- 常规设置与扩展配置的文本编辑状态、字段级提示、错误优先级及保存动作可用性统一遵循 [SPEC-DM-015](SPEC-DM-015-frontend-text-edit-state-contract.md)。没有相对可信快照的修改时，保存按钮保持可聚焦但语义禁用，不得发出 PUT 或制造新的成功提示。
- 保存采用"全有或全无"（ARCH-DM-004 §3）；失败时逐字段显示后端错误，输入保留。
- **关于分区加载语义（SC-11）**：`GET /api/about` 返回的是按包元数据登记的静态值（应用名/版本/协议/链接，ARCH-DM-004 §8），不随配置、工作区或会话过程变化，因此 `fetchAbout()` 在**应用会话内只请求一次**：并发调用共享同一在途请求，成功后复用同一份元数据，分区来回切换与关闭重开对话框都不重放 GET（取数 memo 在 `web/src/api/settings.ts`，呈现归 `components/settings/AboutSection.vue`）。首次请求失败**不缓存**：memo 立即清除，重进关于分区即显式重试，避免一次网络抖动被固化成永久失败页；失败态就地显示「关于信息加载失败。」，不阻塞常规配置分区与保存路径。
- 编辑期间后端值被外部改变（本设计下仅另一进程 `serve` 可能）→ 保存返回 409，对话框刷新快照并提示重新确认（输入保留）。
- `enable_add_number_suffix`、`number_suffix_type`、`cad_max_parallel` 保存成功后显示"已保存，相关预览将按新配置重算"提示（SC-13）。
- **应用偏好（SC-18）**：`cad_version` 只有配置中心一个选择入口，保存后立即让旧预览与结构投影失效并按新版本重算，旧版本在途响应不得回填，后续预览/布局读取/执行统一使用新值；`ui_theme` 保存成功后立即成为持久主题。Topbar 主题按钮只改内存主题，不写持久层；保存其他字段不覆盖该临时主题，刷新/重启重新采用持久主题。启动读取失败时，首次成功打开配置中心须补初始化一次，后续普通加载不得覆盖临时主题。
- 扩展分区开关点击即落库（`PATCH /api/extensions/{id}/state`），**不**进入底部「保存/取消」缓冲；分区内固定说明该语义，避免用户误以为取消可回滚开关。
- 启停控件是滑动开关（`role="switch"` + `aria-checked`），并在开关旁给出可见状态文字「已启用/已停用」：方向不得只靠颜色或滑块位置表达；状态文字对辅助技术隐藏，语义由 `aria-checked` 承担，避免重复播报。
- 从设置中心停用扩展时**不**关闭设置对话框：宿主未提交输入三选一与目录页三选一都是原生 `<dialog showModal>`，由平台 top layer 叠在设置窗口之上，可见且可点击；Esc 归最上层模态处理，不会连带关闭设置窗口。停用既然不再关窗，也就不会丢弃本对话框的编辑缓冲，故不再需要「放弃修改并关闭」前置确认。
- 扩展是否启用以服务端 `enabled` 为准，不用 `status` 反推：`FAILED`/`INCOMPATIBLE` 等"天然不可用"值与用户启停意图在 `extension_states` 上可区分（ARCH-DM-006 §5）。
- **扩展卡片基线（SC-16）——语义角色**：卡片是**状态容器 + 唯一开关**，不可点击、不导航、不可聚焦（不引入 `tabindex`/`role=button`/`<a>`）；点击卡片本体不产生任何动作，进入扩展配置只能通过显式的「配置」文字按钮（SC-17）。将来若需要扩展详情页，必须另立 Spec 定义入口，不得直接让卡片长出导航。
- **扩展配置入口（SC-17）——唯一入口与呈现分派**：声明设置时卡片动作行出现文字按钮「配置」，可访问名为「配置 {name}」，**动作行 DOM 顺序固定为「配置按钮 → 状态文字 → 开关」**；停用、失败、不兼容的扩展**不**隐藏该按钮（设置保留，ARCH-DM-006 §8.1）。配置内容在**同一设置 `<dialog>` 内**的平级子视图呈现，带可见「返回扩展列表」，不叠加第二个模态；子视图内分区导航禁用（唯一出路是返回按钮，避免未闸门的隐式离开）；复杂设置（模板集合/字段映射/表达式）用 `custom` 专属组件，不退化为 JSON 文本框。
- **扩展配置子视图（SC-17）——独立保存与脏状态闸门**：每个扩展的设置独立保存（`PUT` 只提交本扩展的快照与 `expected_revision`），不与核心设置共享一次提交或修订号；核心配置的未保存缓冲不因保存扩展设置而变化。脏状态闸门覆盖四个出路：返回扩展列表、Esc、遮罩点击、关闭确认——前三者在子视图内等价于「返回扩展列表」（脏时先确认），✕/取消按关闭处理且确认文案合并子视图脏状态；选「留在此处」不得丢弃输入。Esc 只作用于最上层原生模态（确认框打开时不会连带关闭设置窗口）。焦点归还按出口分流：**返回子视图**（返回扩展列表）→ 触发它的「配置」按钮；**关闭整个对话框**（✕/取消/确认后）→ 齿轮入口（SC-09）——关闭时卡片与按钮已随面板销毁，对原节点 `focus()` 是空操作，不得据此写“归还配置按钮”。
- **扩展配置子视图（SC-17）——提示层级**：`generated` 表单逐字段显示修改提示；`custom` 图纸目录设置的输出过滤文本框同样显示字段级提示。两者在 clean 状态均不得保存空差异，只读 Schema 继续使用原生禁用。
- **扩展配置子视图（SC-17）——服务端状态就地呈现**：字段超限（关键词超 50 项或单项超 100 字符）在字段行内定位到 `excluded_title_keywords` 并保留输入、拒绝保存，绝不截断；修订冲突（`expected_revision` 不对，HTTP 409）就地显示冲突横幅并保留本地输入，提供「按新修订重试」与「放弃本地修改」两条出路；服务端已存更高 Schema 时（`EXTENSION_SETTINGS_SCHEMA_NEWER`/409）显示只读诊断、禁用输入与保存，但仍可不经确认返回（只读不可脏）。
- **扩展设置无工作区依赖**：清单与设置均不依赖工作区已加载（与 SC-15 同一原则），未加载 DST 也能进入、编辑与保存扩展设置；扩展设置属当前 Windows 用户、跨工作区共享（ARCH-DM-006 §8.1）。
- 卡片固定四层信息，顺序与字段权威固定：①名称（`name_key`）与版本（`version`）；②描述（`description_key`，随包清单已有、宿主 i18n 渲染）；③状态徽标（`status` 九值）+ 诊断码（`error_code` 有值时显示稳定枚举名，不显示原始异常文本）；④动作行（声明设置时的「配置」按钮、状态文字、开关）。`actions` 与 `ui_contributions` 不进卡片。
- **条目增长机制只有唯一预设答案**：单列卡片 + 面板内滚动；条目 **≥6 条**时按 `enabled` 分「已启用 / 已停用」两段（分组键必须与开关同一权威，否则同一卡片会在两段之间跳变），分组标题不显示计数。搜索、筛选、排序、分页、虚拟滚动、多列网格均为非目标；**重启条件是平台具备运行时安装能力**（第三方/市场/依赖管理立项、ARCH-DM-006 非目标解除），届时按新规模重新裁决本节。
- 布尔状态控件只有一种视觉语言：滑动开关（`role="switch"` + `aria-checked` + 轨道/滑块用既有令牌）。扩展启停（点击即落库）与常规配置的缓冲式 bool 字段（保存时落盘）**共用同一形态**，语义差异由分区文案（「启停立即生效，不受下方取消影响」）与「保存」按钮是否点亮传达，不靠控件形态区分。
- 卡片列表使用 `ul/li` 列表语义；开关可访问名沿用「启用 {name}」/「停用 {name}」（随状态翻转），可见状态文字「已启用/已停用」对辅助技术隐藏（`aria-hidden`），语义由 `aria-checked` 承担；卡片内的可聚焦元素只有动作行——声明设置时按 DOM 顺序为「配置 {name}」与开关，无设置时只有开关；Tab 顺序即 DOM 顺序，不引入 roving tabindex 与方向键导航。子视图内首个字段控件接收进入焦点；**只读子视图**（`EXTENSION_SETTINGS_SCHEMA_NEWER`，内部所有控件都 `disabled`）没有可用字段控件，焦点落在带 `tabindex="-1"` 的只读诊断条上，任何状态下都不退回 `<body>`。焦点归还同样按出口分流：返回子视图 → 原卡片的「配置」按钮；关闭整个对话框 → 齿轮入口（SC-09）。

## 5. G3 视觉方向裁决

- **比较过的方向**：
  1. **独立工作区标签页**——否决：设置是全局能力，标签栏在未加载 DST 时不出现，无法满足"未加载即可配置"；且稀释业务标签语义。
  2. **顶部齿轮 + 模态对话框（选定）**——用户裁决（2026-09-07，ASCII 草图确认）：入口常驻、形态与既有确认模态一致。
- **沿用基准**：SPEC-DM-006 设计令牌（色彩/圆角/阴影/间距/焦点环）、既有 `<dialog>` 模态模式（焦点圈闭 + `::backdrop` + 焦点归还）、表单行内错误模式（SPEC-DM-010 属性页 `.property.error` + `.field-error`）、徽章状态语言。
- 无新增全局 CSS 规则；对话框样式限定于组件作用域。
- **第二次裁决（2026-09-10，扩展卡片基线）**：
  1. **单列卡片行（选定）/ 两列网格（否决）**——面板可用宽约 570px，两列会同时挤窄名称、版本、状态与开关，中文长扩展名与描述折行更严重；且条目是随发版逐个加入（ARCH-DM-006 §4.1 固定索引），不是运行时批量涌入。
  2. **≥6 条按 `enabled` 分段（选定）/ 一开始就分段 / 现在就上搜索+筛选（否决）**——固定索引下近期规模为个位数；分段是零成本的第一杠杆，搜索与筛选在只有 1 条扩展时不产生价值。
  3. **四层信息（选定）/ 紧凑三层 / 含能力清单五层（否决）**——描述与诊断码是"为什么不可用"的唯一答案，必须有位置；`ui_contributions`/`required_capabilities` 属扩展自身页面。
  4. **卡片不可点击（选定）/ 失败时展开诊断 / 点入扩展页面（否决）**——后两者都会把设置中心变成第二个扩展入口，与 ARCH-DM-006 §8 冲突；“失败时展开”还需要先定义重试语义（见第 4 项讨论的待决点）。
  5. **布尔状态控件统一为滑动开关（选定）**——同一对话框内不再并存两种“开关”外观；代价是 `SettingsFormRow.vue` 的 bool 控件与卡片布局必须在同一实现批次落地（§6 已记）。
- **第三次裁决（2026-09-12，扩展全局设置入口）**：ARCH-DM-006 §8.2 把设置中心定为所有扩展配置的**统一入口**，本节第二次裁决第 4 项的“卡片不承载设置入口”就此修正（卡片本体仍不可点击，入口改为显式文字按钮），并在同一次裁决中固定以下三点：
  1. **卡片内文字按钮 + 同一对话框子视图（选定）/ 卡片本体可点击（否决）/ 另开第二层设置模态（否决）**——卡片可点击会让“看状态”与“改配置”混为一种动作，且误点即进配置；双层模态叠加会让 Esc/遮罩/焦点圈闭的归属含糊，与原生 top layer 的层级语义冲突。子视图与列表视图共用同一个 `<dialog>`，切换靠可见「返回扩展列表」。
  2. **复杂设置保留专属组件（选定）/ JSON 文本框（否决）**——ARCH-DM-006 §8.2 明确禁止把复杂设置降级为任意 JSON 文本框；`custom` 只打开编译期白名单里的 `route_key`，不按服务端字符串动态 import。
  3. **每个扩展独立保存（选定）/ 与核心设置共享一次提交（否决）**——扩展设置与核心配置的修订号互不相干（§8.1）；共享提交会让一次失败同时击毁两边的未保存输入。
