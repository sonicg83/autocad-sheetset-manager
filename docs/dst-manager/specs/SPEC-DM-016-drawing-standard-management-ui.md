# 图纸标准管理与欢迎页入口 UI 规范

## 1. 目的与权威范围

本文定义 DST Manager 首版图纸标准管理界面及欢迎页入口，是以下界面的唯一权威 UI 规范：

- 未打开工作区时的欢迎页；
- 官方标准、用户标准、草稿与发布版本组成的标准库；
- 用户标准草稿编辑器；
- 属性定义、取值规则、字段映射、字段组合派生与 DWG 命名编辑器；
- 基础模板 DWG 与布局模板 DWG 的资产管理；
- 标准发布检查页。

本文不重复定义标准包 Schema、规则求值、存储和发布 API；这些能力由 [RFC-INT-003](../../integration/rfcs/RFC-INT-003-retire-builder-standard-driven-sheetset-creation.md) 与 [PLAN-DM-035](../../../.planning/plans/dst-manager/PLAN-DM-035-drawing-standard-platform.md) 的领域和接口任务承担。本文也不定义“从标准创建图纸集”的表单步骤；欢迎页只提供入口，完整创建向导由 [PLAN-DM-036](../../../.planning/plans/dst-manager/PLAN-DM-036-standard-driven-sheetset-creation.md) 承担。已绑定标准的项目合规校验与 HTML/JSON 归档报告由 [PLAN-DM-037](../../../.planning/plans/dst-manager/PLAN-DM-037-standard-validation-reports.md) 承担，不与本文的“标准草稿发布检查”混用。

> **修订说明（2026-09-22）：** 本文 §6.3、§7.1～§7.3 的属性、映射、组合与 DWG 命名设计已由 [SPEC-DM-017](SPEC-DM-017-standard-properties-and-dwg-naming.md) 取代；相关段落与 §12.3 证据保留为 PLAN-DM-035 首次交付记录，不再作为后续整改的行为依据。欢迎页、标准库、模板资产、发布检查及通用 UI 约束仍以本文为准。

## 2. 设计目标

1. 保留 DST Manager “先打开现有 DST”的高频工作习惯，不让标准平台遮蔽既有主任务。
2. 普通用户无需编辑 JSON、表达式或脚本，即可建立和维护用户标准。
3. 官方标准与已发布版本始终只读；所有修改发生在用户标准草稿中。
4. 大量专业代码等简单对应关系以表格批量维护，不退化为逐条条件规则。
5. 发布前集中展示字段、规则、映射、命名和 DWG 资产的完整性，并能返回具体问题位置。
6. 继承 [ARCH-DM-007](../architecture/ARCH-DM-007-frontend-ui-foundations.md) 的视觉令牌、共享控件、浅深主题、最小视口和可访问性约束。

## 3. 信息架构与导航

### 3.1 应用级页面状态

未打开工作区时，应用级页面只有：

- `welcome`：欢迎页；
- `standards`：标准管理；
- 后续由 PLAN-DM-036 增加的 `create-sheetset`：从标准创建图纸集。

标准管理不是工作区页签，不加入“图纸 / 属性 / 修订历史”标签栏。进入标准管理不会创建 `.dst-manager/`、打开 DST 或触发 CAD。标准管理页必须提供明确的“返回欢迎页”。

若已打开工作区，首版不在工作区壳内重复增加标准管理入口；用户按现有关闭工作区流程返回欢迎页后进入。后续如增加全局入口，必须复用同一 `StandardsView`，不得产生第二套编辑器。

### 3.2 页面流

```text
欢迎页
  ├─ 打开现有 DST ───────────────▶ 既有工作区
  ├─ 创建新图纸集 ───────────────▶ PLAN-DM-036 创建向导
  ├─ 管理图纸标准 ───────────────▶ 标准库
  └─ 导入标准包 ─▶ 标准库导入结果 ▶ 标准详情

标准库
  ├─ 查看官方/已发布版本（只读）
  ├─ 复制为用户标准 / 派生新草稿
  ├─ 新建空白用户标准
  ├─ 从 DST 提取标准草稿
  └─ 编辑草稿 ─▶ 发布检查 ─▶ 已发布版本
```

## 4. 欢迎页

### 4.1 布局层级

欢迎页采用“打开项目优先”的双栏结构：

- 主栏约占可用宽度的三分之二，标题为“打开图纸集”，保留现有文件选择、拖放和无桌面壳时的路径输入能力；
- 辅栏约占三分之一，标题为“其他任务”，按顺序提供“创建新图纸集”“管理图纸标准”“导入标准包”；
- “打开图纸集”始终是唯一主强调动作；其他任务使用次级按钮或可点击任务行，不与主动作争夺视觉层级；
- 900×768 时允许降为单列，主任务仍排在最前，不能产生页面横向滚动。

最近打开的 DST 列表属于增强信息：只有宿主已有可信记录时才显示；首版不得仅为占位而伪造历史记录，也不得因没有该能力阻塞本规范实施。

### 4.2 入口行为

| 入口 | 行为 | 失败呈现 |
| --- | --- | --- |
| 打开图纸集 | 复用既有 `selectAndOpenDst` / `openByPath` | 复用欢迎页现有加载与错误区域 |
| 创建新图纸集 | 进入 PLAN-DM-036 的标准选择步骤 | 向导不可用时显示明确说明，不回退到无标准创建 |
| 管理图纸标准 | 将应用级页面切换为 `standards` | 标准库加载失败由标准管理页承载 |
| 导入标准包 | 打开受控 `.dststandard` 文件选择并进入导入预检 | 预检失败保留在标准管理上下文，不污染用户标准库 |

不存在“空白无标准创建图纸集”或恢复独立 Builder 的第三条创建入口。

## 5. 标准库

### 5.1 主从分栏

标准库采用主从分栏：

- 左栏：搜索、来源筛选、状态筛选与标准列表；
- 右栏：当前标准的身份、来源、发布状态、能力摘要、版本历史、草稿和可执行动作；
- 默认选择最近一次有效选择；无选择时显示引导空态；
- 窄视口改为“列表 → 详情”两级页面，详情提供可见返回按钮，不把两栏强行压窄。

左栏至少支持：

- 名称或 `standard_id` 搜索；
- 来源：全部、官方、用户；
- 状态：全部、已发布、有草稿；
- 稳定显示名称、来源、当前版本和草稿状态。

### 5.2 标准详情动作

| 当前对象 | 可用动作 | 禁止动作 |
| --- | --- | --- |
| 官方发布版本 | 查看、导出、复制为用户标准、用于创建 | 原地编辑、删除、覆盖发布 |
| 用户发布版本 | 查看、导出、派生新草稿、用于创建 | 原地编辑、覆盖发布 |
| 用户草稿 | 继续编辑、删除草稿、运行检查 | 用作正式创建标准、伪装成已发布版本 |

禁用动作必须同时显示原因文字；不得只用灰色或锁图标表达只读。

### 5.3 新建与导入

“新建用户标准”提供三个受控起点：

1. 空白标准；
2. 复制一个官方或用户发布版本；
3. 从 DST 安全提取属性定义。

“导入标准包”是独立动作，不混入新建草稿对话框。导入成功后定位到导入版本详情；身份冲突或包校验失败时不写入标准库。

## 6. 标准编辑器

### 6.1 编辑对象与壳层

编辑器只编辑用户标准草稿。顶部固定区域显示：标准名称、草稿标识、最近保存状态、“保存草稿”和“发布检查”。左侧分区导航依次为：

1. 基本信息；
2. 属性定义；
3. 取值与联动规则；
4. 字段映射；
5. 字段组合派生与 DWG 命名；
6. 模板资产；
7. 版本与发布。

右侧只渲染当前配置域。分区切换不得丢失输入；有未保存修改时离开编辑器必须进入与 SPEC-DM-015 一致的保存、放弃、留在此处三选一门禁。

### 6.2 草稿保存状态

标准草稿采用直接保存模型，遵循 [SPEC-DM-015](SPEC-DM-015-frontend-text-edit-state-contract.md)：

- `clean` 显示“已保存”或“无修改可保存”；
- `dirty-valid` 显示“有未保存修改”，保存可执行；
- `dirty-invalid` 保留修改提示并优先显示具体错误；
- 保存失败、修订冲突和只读状态均保留用户输入；
- 保存成功后以服务端响应建立新的可信基准。

### 6.3 属性定义

属性定义编辑器以可编辑表格呈现图纸集与图纸属性，支持现有属性定义 CSV 批量导入。表格至少显示字段键、显示名、作用域、值类型、必填状态和派生状态。子集属性只显示“预留，首版不可配置”的说明，不提供伪编辑入口。

## 7. 规则与派生编辑器

### 7.1 普通取值与联动规则

普通规则采用“规则列表 + 侧边编辑器”：

- 列表显示类型、自然语言摘要、启用状态和诊断；
- 侧边编辑器用字段选择器、受控操作符和值控件构造规则；
- 每次修改即时生成自然语言预览；
- 不提供 JSON、脚本、`eval` 或自由公式文本框。

枚举、必填、固定值和真正包含条件判断的联动留在本区域。大量一一对应关系不得展开成多条普通联动规则。

### 7.2 字段映射

字段映射是独立派生类型。一条映射规则由以下内容组成：

- 一个源字段；
- 一个目标字段；
- 一张两列表映射表；
- 未匹配值策略。首版固定为“阻止继续并指出缺少映射”。

映射表支持逐行增删、从剪贴板批量粘贴和 CSV 导入。源值必须唯一且非空；目标值可重复，但必须满足目标字段自身约束。编辑器必须报告重复源值、空单元格、非法目标值和枚举未覆盖项。

例如，“专业名称 → 专业代码”只建立一条规则，在表内维护“燃气 → RQ”“建筑 → JZ”等全部行。创建图纸集时选定源值后，目标字段自动生成并锁定；用户不能用手工值绕过标准。

### 7.3 字段组合派生与 DWG 命名

字段组合采用可排序片段编辑器，片段类型只有：

- 字段令牌；
- 固定文本；
- 受控序号令牌及其补零样式。

编辑器持续展示示例结果，例如：

```text
[专业代码] + [三位序号] + " " + [子集名] + [图纸序号范围]
→ RQ003 总平面图01-05
```

未知字段、循环依赖、缺失必需值和非法格式码必须就地显示，并阻止发布。日期字符串格式化不在首版出现。

## 8. 模板资产管理

### 8.1 分类列表与检查面板

模板资产采用“分类列表 + 检查面板”：

- 主分类为“基础模板”和“布局模板”；
- 来源“官方 / 用户”作为筛选器，而不是两个彼此隔离的页面；
- 列表显示名称、来源、有效状态和引用数量；
- 右侧检查面板显示受控路径、资产身份、引用关系、最近检查结果和重新检查动作。

官方资产只读；用户资产允许添加、替换和从未发布草稿中移除。替换被引用资产前必须显示影响范围并确认。

**本机模板来源与包内路径（PLAN-DM-040 Task 3 修订）：**

- 草稿只保存包内相对路径（受控副本名）；本机绝对路径只作一次性导入来源，不写入 `document.json`、发布目录或包内 `manifest.json`，也不在前端缓冲中保留；
- 桌面壳可用时，用户经固定 `template` 文件种类（`*.dwg;*.dwt`）选择本机模板，由后端把文件复制到草稿受控资产目录，返回形如 `assets/managed-<uuid4hex>.dwg|.dwt` 的受控副本名；前端把它写入当前草稿文件行；
- 无桌面壳的本地开发态提供单独标明的“来源绝对路径”输入，调用同一受控复制端点；不使用浏览器文件选择控件产生的伪路径；
- 单个来源文件不得超过 64 MiB，扩展名只允许 `.dwg`/`.dwt`；来源不存在、不是文件、扩展名不符、超限或复制失败时一律拒绝，就地显示稳定错误码与原因，保留原声明与未保存状态，不产生半成品文件、不覆盖已有副本；
- 复制成功后，保存与发布只清理草稿 `assets/` 下**未被当前文档引用且文件名匹配 `managed-` 前缀**的受控副本；其他文件（包括历史草稿中手工放置的资产）一律不动。放弃编辑产生的孤儿副本保留到下次保存或发布时再清理；
- 发布、导入与导出仍以服务端为最终权威：声明的资产文件必须真实存在于受控目录且与包内条目一致，否则阻断并给出 `STANDARD_ASSET_FILE_MISSING`/`STANDARD_ASSET_PATH_INVALID` 诊断。

### 8.2 布局模板检查

选中布局模板时，检查面板必须列出 DWG 内全部非 `Model` 布局，并逐项显示是否匹配标准允许图幅。布局名称以图幅名称严格匹配，不静默去空格或转换大小写。

以下情况阻止发布：

- 声明的图幅没有同名布局；
- 同一图幅出现重复或歧义布局；
- DWG 不可读取或所需 CAD 能力不可用；
- 资产已移动、缺失或不在标准草稿的受控资产目录内。

未被引用的有效资产为警告，不阻止发布。

## 9. 发布检查

### 9.1 独立检查页

发布使用独立检查页，不使用小型确认对话框。页面左侧列出检查域及错误/警告计数，右侧列出问题、修复入口、版本号、版本说明和发布动作。

检查域至少包括：

- 基本信息；
- 属性定义；
- 取值、联动、映射与组合规则；
- DWG 命名；
- 模板资产；
- 标准包结构与依赖。

错误阻止发布；警告允许发布，但必须在发布动作附近汇总。每个问题均可返回对应编辑分区并聚焦到字段、规则、映射行或资产。返回后重新进入发布页时，保留尚未失效的版本号和说明输入。

### 9.2 发布完成

发布成功后进入新版本只读详情，并提供“导出标准包”“用于创建图纸集”和“派生新草稿”。不得继续停留在貌似可编辑的旧草稿表单中。

## 10. 页面状态与异常

每个异步区域必须区分加载、空、失败、可重试和数据已失效状态：

| 场景 | 要求 |
| --- | --- |
| 标准库为空 | 解释官方库和用户库均为空，提供“新建用户标准”“导入标准包” |
| 搜索无结果 | 保留筛选条件，提供清除筛选，不伪装成标准库为空 |
| 列表加载失败 | 左栏就地错误与重试；右栏不显示陈旧对象为当前对象 |
| 详情加载失败 | 保留列表和当前选择，右栏就地错误与重试 |
| 草稿保存失败 | 输入与 dirty 状态保留，允许重试 |
| 草稿修订冲突 | 显示冲突说明与刷新/放弃路径，不静默覆盖 |
| 资产丢失 | 标记资产失效，显示原登记信息和替换动作 |
| 发布检查失败 | 显示检查本身失败与重试，不把它误报为“标准存在错误” |
| 官方或发布版本 | 所有编辑控件只读，并在页面顶部显示原因 |

## 11. 可访问性、响应式与视觉约束

- 所有交互复用 `UiButton`、`UiInput`、`UiSelect`、`FormField`、共享确认模态和焦点工具；确需新原语时先补共享组件测试。
- 主从分栏、侧边编辑器和发布检查均必须有语义标题与可感知的区域关系。
- 列表选中、草稿、错误、警告、只读和发布状态均不得只依赖颜色。
- 错误摘要取得焦点后，问题跳转必须把焦点移到真实控件或映射行首个可编辑单元格。
- 键盘可完成欢迎页进入、列表筛选、标准选择、分区切换、映射表编辑、发布检查和返回。
- 1440×900 为标准桌面布局；900×768 不横向溢出，主从分栏切换为分级视图；200% 缩放下关键动作与错误说明仍可到达。
- 浅色和深色主题使用 ARCH-DM-007 既有语义令牌，不为标准平台建立第二套颜色系统。

## 12. 测试与验收

### 12.1 自动化场景

| ID | 场景 | 预期 |
| --- | --- | --- |
| ST-UI-01 | 未打开工作区进入欢迎页 | 打开 DST 为主任务，创建/标准管理/导入为次级入口 |
| ST-UI-02 | 900×768 欢迎页 | 单列且无横向滚动，打开 DST 仍在最前 |
| ST-UI-03 | 标准库搜索、来源与状态筛选 | 列表与空结果状态准确，选择未被静默改写 |
| ST-UI-04 | 打开官方标准和用户发布版本 | 编辑控件不可用且显示只读原因 |

## 13. 非目标与变更控制

首版不实现：

- 子集属性编辑或强制校验；
- 日期字符串格式化；
- 通用公式、脚本、插件代码注入或自由 JSON 编辑；
- 在标准管理器中直接创建未绑定标准的图纸集；
- 在发布后原地修改版本；
- 把标准管理复制进工作区标签栏形成第二入口。

新增规则类型、改变已发布版本可变性、放宽布局名称严格匹配或把创建向导并入本文，均须修订本 Spec 或新增正式决策，不得只在实现中改变。
