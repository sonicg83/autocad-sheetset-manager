# DST Manager 前端文本编辑状态与提交动作契约

## 1. 目的与权威范围

本文是 DST Manager 前端文本框、文本域及同类值编辑控件的修改追踪、状态提示和提交动作可用性规则的唯一权威规范。页面级 Spec 只记录本页面采用字段级还是分组级提示、使用草稿还是直接保存等差异，不重复定义通用状态机。

适用范围包括：

- 图纸页属性编辑；
- 属性页图纸集名称和属性值编辑；
- 图纸目录模板编辑；
- 设置中心常规设置；
- 扩展配置的生成式表单与自定义面板。

本文不改变后端 API、草稿持久化、修订冲突、模板保存、正式发布或 CAD 执行契约，也不把文件选择、即时生效开关和纯动作按钮强行纳入文本编辑状态机。

## 2. 比较基准与术语

### 2.1 比较基准

每个可编辑值必须有明确、可信的比较基准：

| 编辑类型 | 比较基准 | 修改后的主状态文案 | 提交成功后的状态 |
| --- | --- | --- | --- |
| 加入草稿 | 当前草稿投影值 | 未加入草稿 | 待写入 |
| 直接保存 | 最近一次可信的已保存快照 | 有未保存修改 | 已保存 |

没有可信基准时不得伪造 `clean` 或 `dirty`，应进入加载失败、失效、冲突或只读状态。默认使用输入值与基准值的精确比较；只有对应领域规范明确规定规范化规则时，才可在比较前规范化。前端不得自行 `trim`、折叠空白、转换大小写或改写换行来消除差异。

### 2.2 状态定义

| 状态 | 定义 | 可见反馈 | 主提交动作 |
| --- | --- | --- | --- |
| `clean` | 当前输入与比较基准一致 | 中性状态；可显示“暂无修改”或“已保存” | 不可执行 |
| `dirty-valid` | 至少一项输入不同于基准，且本地校验通过 | 琥珀修改提示 + 明确文字 | 可执行 |
| `dirty-invalid` | 输入不同于基准，且存在本地校验错误 | 红色错误优先 + 修改文字保留 | 不可执行 |
| `submitting` | 请求正在提交 | “正在加入草稿”或“正在保存” | 不可重复执行 |
| `submitted` | 本次请求成功，已建立新的可信状态 | 草稿流为“待写入”；直存流为“已保存” | 重新按新基准计算 |
| `submit-failed` | 请求失败但输入仍保留 | 可见错误 + 修改提示保留 | 条件恢复后可重试 |
| `conflicted` | 基准修订漂移或目标失效 | 冲突说明 + 输入保留 | 按页面冲突流程处理 |
| `read-only` | 当前能力或 Schema 不允许编辑 | 只读原因 | 不可执行 |

状态不是单向计数器。用户把值改回比较基准后，必须立即回到 `clean`；不得因为字段曾被编辑过而继续显示修改或启用提交。

## 3. 状态转换

```text
可信基准加载成功
        │
        ▼
      clean ──输入变化且有效──▶ dirty-valid ──提交──▶ submitting
        ▲                              │                   │
        │                              │                   ├─成功──▶ submitted ──重建基准──▶ clean
        │                              │                   └─失败──▶ submit-failed ──重试──┘
        │                              ▼
        └────改回基准────────── dirty-invalid
                                       │
                                       └─修正错误──▶ dirty-valid
```

任何状态遇到可信基准失效、服务端修订冲突或只读 Schema 时，分别进入 `conflicted` 或 `read-only`，不得静默重建基准并覆盖用户输入。

## 4. 可见反馈与可访问性

### 4.1 普通字段级编辑器

普通表单中的修改字段必须同时具备：

- 琥珀色语义边框或容器边框；
- 低对比度琥珀语义底色；
- 可见的“未加入草稿”或“有未保存修改”文字；
- 文字与控件通过 `aria-describedby` 或等价语义关联。

不能只改变按钮、页脚计数或边框颜色来表达字段已经变化。焦点环只表达当前键盘焦点，不得作为修改提示。

### 4.2 分组级结构化编辑器

表格、列构建器和模板编辑器可采用分组级提示，条件是：

- 状态文字在编辑区域标题或固定操作栏持续可见；
- `dirty` 与 `clean` 的视觉层级有明确差异；
- 主提交动作遵循本文第 5 节；
- 错误仍定位到具体字段或行；
- 只有在能够稳定计算行级差异时才增加行级标记。

不得为了形式统一而给结构化编辑器的所有输入框同时铺设琥珀底色。本轮图纸目录模板编辑只采用模板级警示徽标，不新增行级修改追踪。

### 4.3 错误、状态播报与主题

- 错误使用红色语义边框和具体说明，视觉优先级高于修改状态；“未加入草稿”或“有未保存修改”文字仍须保留。
- 计数、保存中和成功状态使用 `role="status"` 或等价的礼貌播报区域；需要立即处理的错误使用现有 `role="alert"` 规则。
- 修改和错误均不得只依赖颜色；浅色、深色和高缩放下必须保持可辨识。
- `clean` 不要求给每个字段显示“未修改”，但操作区必须能解释为什么当前不能提交，例如“暂无修改”或“无修改可保存”。

## 5. 提交动作可用性

### 5.1 统一判定

“加入草稿”“保存修改”“保存”等会产生写操作的主动作，仅在以下条件全部成立时可执行：

1. 存在相对可信基准的可执行差异；
2. 本地校验允许提交；
3. 当前不在提交中；
4. 当前不是只读、失效或未解决冲突状态；
5. 页面原有的工作区、能力和服务端门禁已满足。

`clean` 状态点击主动作不得发出请求、创建空草稿或生成成功提示。事件处理函数必须保留同样的守卫，不能只依赖视觉样式。

### 5.2 焦点保留与 `aria-disabled`

当主动作是表单的稳定焦点锚点，或保存成功后需要把焦点归还到该动作时，`clean` 状态采用可聚焦的语义禁用：

- 按钮保留在 Tab 顺序中；
- 设置 `aria-disabled="true"`；
- 视觉与原生禁用态一致；
- 鼠标、键盘与程序触发均不执行写操作；
- 通过可见状态文字说明“无修改可保存”或“暂无修改”。

加载中、只读、能力缺失等不需要保留焦点的阻断场景可继续使用原生 `disabled`。共享 `UiButton` 应显式区分两种禁用语义，不允许页面通过 CSS 伪造。

## 6. 五个页面的裁决

| 页面 | 提交模型 | 修改提示层级 | `clean` 主动作 | 页面特例 |
| --- | --- | --- | --- | --- |
| 图纸页属性编辑 | 加入草稿 | 字段级琥珀 + 页脚计数/状态 | 语义禁用 | 跨页修改数包含隐藏页；改回草稿基准立即清除 |
| 属性页属性值 | 加入草稿 | 字段容器级琥珀 + 字段文字 + 面板计数 | 语义禁用 | “待写入”可与“未加入草稿”并存；错误边框优先 |
| 图纸目录模板 | 直接保存 | 模板栏分组级警示徽标 | 语义禁用 | 本轮不新增行级琥珀；表达式错误仍就地显示 |
| 常规设置 | 直接保存 | 字段行级琥珀 + 对话框状态 | 语义禁用 | 取消既有“无修改也可保存”例外；保存后焦点仍可归还 |
| 扩展配置 | 直接保存 | 生成式表单字段级；自定义面板对应字段级 | 语义禁用 | 自定义输出过滤文本框必须补齐修改提示；只读 Schema 使用原生禁用 |

### 6.1 文案词汇表

| 含义 | 草稿流 | 直接保存流 |
| --- | --- | --- |
| 当前没有变化 | 暂无修改 | 已保存 / 无修改可保存 |
| 当前输入尚未提交 | 未加入草稿 | 有未保存修改 |
| 请求进行中 | 正在加入草稿 | 正在保存 |
| 请求成功 | 待写入 | 已保存 |

页面可以在不改变语义的前提下增加计数或会话说明，例如“未加入草稿 2 项”或“尚未加入草稿（仅本会话保留）”。不得把内存输入称为“已保存”，也不得把加入草稿称为正式写入。

## 7. 测试与验收

每个适用页面至少覆盖以下自动化场景：

1. 初始 `clean`：有可见中性状态，主动作 `aria-disabled="true"`，点击与 Enter/Space 均不发请求；
2. 改为不同值：显示文字和琥珀视觉，主动作可执行；
3. 改回原值：修改提示清除，主动作恢复语义禁用；
4. `dirty-invalid`：红色错误优先，修改文字保留，主动作不可执行；
5. 提交中：不可重复提交，状态可被辅助技术感知；
6. 成功：草稿流显示“待写入”，直存流重建基准并显示“已保存”；
7. 失败/冲突：输入和修改提示保留，错误可见且可恢复；
8. 浅色、深色、最小支持视口和 200% 缩放下，文字、边框、焦点环和操作区均可辨识。

测试必须断言网络请求或业务事件没有在 `clean` 状态发生，不能只断言按钮样式。视觉证据采用同一数据、状态、主题和视口成对比较；真实桌面缩放证据仍遵循 GUIDE-DM-001 G9，不由浏览器模拟替代。

## 8. 非目标与变更控制

本规范不要求：

- 重写五个页面的业务 composable；
- 新增后端脏状态字段或 API；
- 改变草稿、模板、设置的持久化边界；
- 本轮为图纸目录补充单元格级或行级差异模型；
- 为所有旧按钮统一改造禁用语义。

后续若要改变比较基准、允许 `clean` 写操作、取消可见修改文字，或改变图纸目录为行级提示，必须先修订本文并重新执行 GUIDE-DM-001 的 G2、G4、G7 和 G8；不得只在页面代码中形成新例外。
