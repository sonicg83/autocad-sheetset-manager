# DST Manager 单人桌面界面人性化与易用性设计规范

> 中心工作区细化提案：图纸标签见 [SPEC-DM-009](SPEC-DM-009-sheets-workspace-ui.md)，属性标签见 [SPEC-DM-010](SPEC-DM-010-properties-workspace-ui.md)，两份均处于评审中。本文继续作为公共外壳、设计令牌、无障碍及正式写入门禁的依据；新文档不表示已实施，也不替代本文公共规则。

## 1. 背景

DST Manager 是面向单人单机真实工程的本地桌面工具，用于既有 DST/DWG 的检查、受控编辑与安全发布（见 [VISION-DM-001](../product/vision.md) 与 [ARCH-DM-001](../architecture/ARCH-DM-001-dst-manager-mvp-baseline.md)）。当前 `web/` 界面功能完备、安全流程严谨，但视觉与交互仍偏原型级：设计令牌硬编码在压缩的全局 CSS 中、破坏性操作依赖浏览器原生 `confirm()`、单页信息密度过高、缺少主题与统一组件规范。

本规范从**人性化操作**和**易用性**优先、兼顾**清爽简洁界面**的角度，定义 DST Manager 桌面端的产品级界面与交互设计系统，作为后续 `web/` 重构与 [PLAN-DM-004](../../../.planning/plans/dst-manager/PLAN-DM-004-v1.0-windows-productization.md) 产品化界面的设计依据。

本规范只约束界面与交互表现，**不改变后端 API、任务契约、发布事务或安全门禁**；界面必须继续消费服务端预览、诊断和派生结果，不得在前端复制校验或绕过发布安全流程。

## 2. 范围

### 2.1 覆盖范围

- 应用外壳（App Shell）布局、导航层级与信息架构。
- 设计令牌：颜色（浅/深双主题完整映射）、字体、间距、圆角、阴影、层级、图标。
- 通用组件规范：按钮、表单、表格、面板、模态框、状态标记、任务进度、提示与空状态。
- 核心工作流的交互与反馈：打开、浏览筛选、编辑草稿、预览，以及 §9.1 定义的**全部正式工程文件写入**（普通变更发布、CSV 导入、XML 导出/覆盖、修复发布、修订恢复）与任务监控。
- 人性化与易用性规则、无障碍（明确列出适用的 WCAG 2.1 成功准则，见 §7）、键盘操作、浅色/深色主题。
- 视觉与交互验收标准。

### 2.2 目标

- 用**单一、可预测的操作主线**降低认知负担：浏览 → 编辑草稿 → 预览 → 确认写入。
- 让用户在任何时刻都能理解**当前状态、下一步、影响范围、可撤销性**。
- 用**清晰的安全分级**消除误操作恐惧：读与预览永远安全；§9.1 的"正式工程文件写入"是不可逆写，全部共用同一套预览 + 确认 + 反馈门禁。
- 用**令牌化、双主题**的视觉系统实现清爽、一致、可扩展的界面。

### 2.3 非目标

- 不设计多用户、远程调度、跨机器 Worker 或登录鉴权界面。
- 不新增功能命令，不修改 AcSm/DST 契约、发布事务或 CAD Worker 行为。
- 不做营销落地页（现有 `--design-system` 的 landing/CTA 模式不适用于本工具，本文按"操作型应用"取舍）。
- 不引入需运行时联网的资源（字体、图标一律本地化，见 §5.2、§5.7）。
- 不改变既有写请求的字段契约；界面按 §8 消费现有请求模型。

## 3. 设计原则

按优先级排序，界面出现取舍时以序号小者为准。

| # | 原则 | 含义 | 反面 |
| --- | --- | --- | --- |
| P1 | 安全可感知 | 用视觉与文案明确区分"只读/预览"（安全）与"正式工程文件写入"（不可逆写，含发布、CSV/XML、修复、恢复，见 §9.1），破坏性操作需理解后果 | 所有按钮长得一样；原生 `confirm()` 一句话带过外部引用风险；只给普通发布做危险确认而 CSV/XML 走弱确认 |
| P2 | 状态透明 | 每个操作都可见进度、结果、耗时、失败原因与是否已回滚 | 静默成功、卡住无反馈 |
| P3 | 可恢复优先 | 强调草稿自动留存、撤销/重做、修订可恢复，降低"怕做错"的心理成本 | 用户担心一旦点错无法挽回 |
| P4 | 一次一个主线 | 每屏一个主操作，按任务分组，高级项渐进展开 | 同屏堆叠十余个平铺控件 |
| P5 | 人性化文案 | 用"动作 + 影响对象 + 数量"的白话描述结果，派生只读字段解释"为什么不能改" | 暴露 `clsid`、`vt`、内部 ID 等术语 |
| P6 | 清爽克制 | 中性底色 + 单一强调色 + 语义状态色，留白充分，去掉无谓装饰 | 多彩、重投影、拟物 |
| P7 | 键盘与无障碍优先 | 全流程可键盘操作，焦点/读屏顺序与视觉一致 | 仅鼠标可用、颜色唯一指示 |

## 4. 信息架构与布局（行为）

### 4.1 应用外壳

采用**固定标签 + 任务浮层 + 全局操作栏**的桌面外壳，替换当前的单页滚动结构，消除单页信息密度过高与长滚动问题：

```text
┌───────────────────────────────────────────────────────┐
│ 顶栏 TopBar：项目/路径 · DST 校验状态 · AutoCAD 版本 · 主题 · 帮助 │
├───────────────────────────────────────────────────────┬────────────┤
│ 标签栏 TabBar：[① 图纸] [② 属性] [③ 修订历史]（右侧预留扩展位）       │ 任务浮层     │
│ 内容区：当前标签独立布局，互不堆叠、不互相滚动                          │ 进度·预览·诊断│
│                                                      │（可收起）    │
├───────────────────────────────────────────────────────┴────────────┤
│ ActionDock：草稿 3/3 ▲ · 撤销 重做 · [预览 Primary] [确认写入 Danger] │
└───────────────────────────────────────────────────────┘
```

- **顶栏**：全局、低频信息（工作区身份、DST `VALID/REPAIRED/INVALID` 状态、CAD 版本、**关闭工作区**（确认语义见 [SPEC-DM-007](SPEC-DM-007-v031-shell-and-usability.md) §4.3）、主题切换、帮助/快捷键）。
- **标签栏**：三个固定功能标签（映射见 §4.2），同一时刻只激活一个，每个标签是独立功能域（P4 一次一个主线）；右侧预留扩展位，未来新功能域（如软件设置、打印、生成图纸目录）作为新固定标签追加，本规范不预设其内容。ARIA 角色与键盘模型见 §7.2。
- **内容区**：仅渲染当前标签的内容，标签之间互不堆叠、不互相滚动。
- **任务浮层**：右缘可收起的三页签容器——**实施进度 / 修改预览 / 诊断**。点 ActionDock"预览"→ 自动展开并激活"修改预览"页签；确认写入后 → 自动展开并激活"实施进度"页签；存在阻断诊断 → "诊断"页签红点提示（承接 §6.9 修复门禁引导）。关闭浮层不影响任务执行，顶栏状态点常驻。
- **草稿栈浮窗**：草稿计数带向上箭头，点击向上展开草稿动作栈浮窗，限高滚动，`撤销/重做/清空` 就近可用（沿用现有草稿投影与冲突保护逻辑）；`Esc` 关闭、焦点归还触发按钮（§7.2 抽屉模型）。
- **任务通知**：任务经 SSE 状态迁移触发非模态 toast（成功/失败/`NEEDS_REVIEW` 等），保证浮层收起或切换标签后任务结果仍可感知，规则见 §6.6。
- **底部操作栏**：承载"预览""确认写入"两个动作与草稿计数（含草稿栈浮窗），全局常驻，任何标签下不消失。**"预览"为 `Primary`（强调色），"确认写入"为 `Danger`（红色）——二者视觉等级不同**，避免把安全动作与不可逆写混为一谈。各状态下主/次操作的文案、等级、可用性与禁用原因由 §6.9 的"操作 × 状态矩阵"唯一确定，界面不得自行推断。

### 4.2 标签与视图映射（复用 ARCH-DM-001 §10.2 页面清单）

| 载体 | 内容 | 关键约束 |
| --- | --- | --- |
| 打开/欢迎（无标签态） | 无工作区时的空状态页 | 空状态引导：选择 `.dst` 文件（壳原生对话框 / 拖拽，见 [SPEC-DM-007](SPEC-DM-007-v031-shell-and-usability.md) §4.1）+ 最近项目 + 帮助（§6.5）；无壳回退时保留路径输入（SPEC-DM-007 §4.2） |
| 标签① 图纸 | 结构树（图纸集 → 子集 → 图纸，选中项持久高亮）+ 焦点子集图纸表格 | 浏览筛选：表格虚拟滚动 + 分页，搜索覆盖图号/标题/属性/DWG 路径（沿用现有）；增删图纸/子集：渐进展开表单（§6.3）；图纸属性值修改：选中行就地编辑 + 批量修改面板（作用于当前选择，批量选择条沿用"全选当前结果/已选 N"）；键盘模型见 §7.2 |
| 标签② 属性 | 上：属性字段定义列表（增删）；下：图纸集属性值表单 | "属性定义与结构变更必须分批预览和执行"的既有规则以行内提示 + 顶部错误摘要呈现（§6.3）；编辑先持久化到**应用数据目录**草稿，可撤销/重做/重开恢复；正式发布前不改动项目目录、DST、DWG 或其时间戳（§6.8） |
| 标签③ 修订历史 | 修订列表（修订号、时间、来源动作、变更摘要）；无修订时空状态"暂无修订历史"（§6.5） | 行内发起恢复：先预览（进任务浮层"修改预览"页签，统一 §9.1 门禁）→ 危险确认模态 → 恢复为新修订；语义与 `restore-preview`/`restore` 契约一致（依据 PLAN-DM-001/PLAN-DM-002、ADR-DM-004，见下方注） |
| 任务浮层 · 修改预览 | 服务端 diff 只读渲染 | 永远安全，可反复预览 |
| 任务浮层 · 实施进度 | 逐文件进度/耗时/错误 | SSE + 轮询回退，沿用 `JobStatusPanel` 数据结构（§6.6） |
| 任务浮层 · 诊断 | 阻断诊断列表与修复引导 | 承接 §6.9 修复门禁（沿用 SPEC-DM-004） |
| 正式写入确认 | 危险级模态 | 展示受影响文件与不可逆声明；覆盖 §9.1 全部写入类型（§6.2），与标签/浮层解耦——任何标签发起的写入走同一模态 |

> 引用说明：修订恢复的产品行为直接依据 [PLAN-DM-001](../../../.planning/plans/dst-manager/PLAN-DM-001-v0.2-stabilization-and-multi-dwg-parallel.md)、[PLAN-DM-002](../../../.planning/plans/dst-manager/PLAN-DM-002-v0.3-daily-editor.md) 与现有 `restore-preview`/`restore` API；[ADR-DM-004](../adr/ADR-DM-004-recoverable-file-deletion.md) 仅补充被删除文件如何从 before 快照重建。若恢复能力需长期稳定为产品契约，应在后续拆分为独立 Spec，本规范不将其误挂到 SPEC-DM-005。

> 工作区生命周期：v0.3.1 起支持显式关闭工作区（两态状态机），存在未发布改动时需关闭确认。该交互（含确认文案与状态清理）由 [SPEC-DM-007](SPEC-DM-007-v031-shell-and-usability.md) §4.2/§4.3 定义，不属 §6.9 ActionDock 写入主线；关闭确认模态仍须遵守 §6.2 的可访问性要求（替换原生 `confirm()`，见 §10.3）。

### 4.3 响应式与窗口

- 目标平台为 Windows 桌面；交付形态为 pywebview（WebView2）桌面壳，**壳是唯一交付入口**（选型与原生能力桥见 [SPEC-DM-007](SPEC-DM-007-v031-shell-and-usability.md) §3）。`serve` 命令直连浏览器仅作开发调试，不属于产品交付路径。Web 服务仅监听 `127.0.0.1`。
- 设计基准宽度 1440px；最小支持窗口 1024×768。
- `< 1120px` 任务浮层折叠为右缘可展开抽屉（自动展开动作改为打开抽屉）；`< 900px` 标签栏横向滚动、标签①左树折叠为抽屉、底部操作栏吸底。**抽屉必须提供始终可见的触发按钮**（含 `aria-expanded`/`aria-controls`），不得仅隐藏区域而不给入口；抽屉开关的键盘与焦点行为见 §7.2。
- 不做移动端触控布局（超范围），但保持不塌版、可读。

## 5. 视觉设计系统（令牌）

所有视觉值必须以 **CSS 自定义属性（语义令牌）** 落地；组件**必须消费声明的语义/组件令牌**，而非直接写十六进制色值或自定义间距（验收见 §10，断点、1px 边框等声明过的合法常量不计为违规）。令牌分三层：原始值 → 语义值 → 组件值。

### 5.1 颜色（语义令牌，浅/深双主题完整映射）

中性优先 + 单一冷色强调 + 语义状态色。**对比度按实际渲染的前景/背景组合校验**（不是孤立令牌）：正文 ≥ 4.5:1，非文本 UI/大文本 ≥ 3:1（§10）。

| --- | --- | --- | --- |
| `--color-bg-canvas` | `#F6F7F9` | `#10151E` | 应用底色 |
| `--color-bg-surface` | `#FFFFFF` | `#171E29` | 卡片/面板 |
| `--color-bg-muted` | `#EEF1F5` | `#212B39` | 次级面、表头、骨架 |
| `--color-text-primary` | `#1A2233` | `#E6EAF2` | 主文本 |
| `--color-text-secondary` | `#4A5568` | `#AEB8C7` | 次要文本、标签 |
| `--color-text-muted` | `#6B7280` | `#8592A3` | 提示、派生只读说明 |
| `--color-border-subtle` | `#E3E8EF` | `#2A3444` | 分隔线 |
| `--color-border-strong` | `#C7D0DB` | `#3B485C` | 输入框/卡片描边 |
| `--color-accent` | `#2F5BE0` | `#6B8DFF` | 主操作、选中、链接 |
| `--color-accent-hover` | `#2A50C8` | `#7E9CFF` | 主操作悬停 |

| `--color-success` / `-bg` | `#1B7F4B` / `#E7F4EC` | `#54C98A` / `#12301F` | 成功、无阻断 |
| `--color-warning` / `-bg` | `#946200` / `#FBF1DB` | `#E0B15A` / `#332712` | 待确认修复、需关注 |
| `--color-danger` / `-bg` | `#C2302B` / `#FBEAE8` | `#F0776E` / `#3A1917` | 破坏性、阻断、失败 |
| `--color-info` / `-bg` | `#245FA6` / `#E8F0F9` | `#7CB0E8` / `#132739` | 中性提示、延后校验 |

**交互态映射规则（两主题一致）**：`hover` 在 surface/muted 上升亮度约 +4%，`active` 下调约 -4%；`disabled` 使用 `--color-text-muted` 且透明度 0.5，不可点；`focus-visible` 恒用 `--color-focus`，与主题无关；`loading` 在按钮内联呈现（§6.6）。所有态须在前景观测下可分辨。

### 5.2 字体与排版

- 字体栈：`--font-ui: "Inter", "Microsoft YaHei", system-ui, sans-serif`（拉丁用 Inter，中文回落到雅黑，**本地内嵌** Inter 可变字体子集 + `font-display: swap`，避免 FOIT 与联网）。
- 等宽栈：`--font-mono: "IBM Plex Mono", ui-monospace, Consolas, monospace`，用于 `handle`、`sha256`、`preview_digest`、文件路径、XPath、错误码。
- 字号阶梯（px）：`12 / 13 / 14 / 16 / 20 / 24`；正文 `14`，表格 `13/14`，标签 `13`，视图标题 `20`，项目标题 `24`。
- 行高：标题 `1.2–1.3`，正文 `1.5`；长文本最大阅读宽度约 `70ch`。
- 字重：`Regular 400`（正文）、`Medium 500`（标签/表头）、`Semibold 600`（标题/按钮）；层级差异优先用字重与颜色，而非放大字号。
- 数字与代码列使用 `font-variant-numeric: tabular-nums` 保证对齐。

### 5.3 间距

4px 基准刻度：`--space-1..8 = 4 / 8 / 12 / 16 / 24 / 32 / 40 / 48`。

- 组件内边距：按钮纵向 `8`、卡片 `16`、面板 `24`。
- 区块节奏：`16 / 24 / 32`（同层级用同值，不同层级递进）。
- 表格行高：舒适 `40px`（默认）/ 紧凑 `32px`（可切换）。

### 5.4 圆角 / 阴影 / 层级

- 圆角：`--radius-sm 6` `--radius-md 8` `--radius-lg 12` `--radius-full 9999`（状态胶囊）。
- 阴影（三档、极轻）：`--shadow-1 0 1px 2px rgba(16,24,40,.06)` 卡片；`--shadow-2 0 4px 12px rgba(16,24,40,.10)` 下拉/弹出；`--shadow-3 0 12px 32px rgba(16,24,40,.16)` 模态。
- 层级 `z-index`：内容 `0` · 粘性栏 `10` · 抽屉/下拉 `100` · 模态遮罩 `1000`；不得随手加大数。

### 5.5 图标

- 单一图标族、统一描边（推荐 Lucide 或 Phosphor，本地 SVG，`stroke-width 1.5–2`）。
- 尺寸令牌：`--icon-sm 16` `--icon-md 20` `--icon-lg 24`。
- **禁止用 Emoji 作结构化图标**；纯装饰图标 `aria-hidden="true"`，独立图标按钮必须有可读文本名。

### 5.6 状态与密度令牌

- 交互态令牌化：`default / hover / active / focus-visible / disabled / loading`，两主题下均需可分辨。
- 密度令牌：`--density-comfy`（默认）与 `--density-compact` 两档，仅改变行高与间距，不改结构。

### 5.7 资源本地化

字体、图标、任何静态资源一律随 `web/dist` 本地打包，运行期不请求外部 CDN，符合离线单机与 `127.0.0.1` 边界。

## 6. 组件与交互规范

### 6.1 按钮

- 层级：`Primary`（唯一强调色 `--color-accent`，用于推进主线的**安全正向动作**，如"预览""继续"）、`Secondary`（描边）、`Ghost`（文字）、`Danger`（红色 `--color-danger`，**所有正式工程文件写入与破坏性动作**，见 §9.1）、`Danger-Confirmed`（危险且需二次确认）。
- **强调色唯一性约束**：全局唯一 `Primary` 强调色专用于安全动作；不可逆写入一律走 `Danger` 红色，不得与 `Primary` 混用，从而保证"强调色 = 安全推进"的心智稳定。
- **不存在 `Warning` 按钮层级**：按钮只使用上述五种层级；"待确认修复"等需关注场景用状态色横幅与状态胶囊表达（§6.7），动作本身仍按门禁拆分——"预览修复"为 `Primary`（安全），"确认发布修复"为 `Danger`（不可逆，仅在修复预览有效后出现/可用，见 §6.9 `REPAIRED` 行），两者不得合并为一个按钮。
- 最小可点尺寸高度 `32px`（推荐 `36–40px`），图标按钮 `≥ 36×36` 并带 `title` 与可访问名。
- 文案用动词 + 对象：`预览变更` `确认发布` `确认导入` `丢弃草稿`；`确定/取消` 仅允许出现在模态内部。
- 状态变化用颜色/透明度/投影，**不得位移布局**。

### 6.2 模态与破坏性确认（替换原生 `confirm()`）

当前发布/删除/恢复均用浏览器 `confirm()`，信息量不足且不可样式化。改为应用内模态，且**对 §9.1 定义的全部正式工程文件写入统一适用**（普通发布、CSV 导入、XML 导出/覆盖、修复发布、修订恢复），不得只为普通发布提供强确认而让 CSV/XML 走弱确认：

- 结构：标题（动作）+ 影响清单（受影响子集/图纸数量、涉及文件路径、是否含 DWG 与外部引用声明）+ 明确的可逆性标签（`可撤销` / `不可逆`）+ 主/次按钮。
- 不可逆删除整子集/主 DWG（沿用 SPEC-DM-005 与 ADR-DM-004）：必须展示"系统不证明工程外部引用，确认后由用户承担外部影响"这一既有声明，且要求**显式勾选确认框**（而非仅点按钮）后才启用危险按钮。
- 键盘：`Esc` 关闭 = 取消（安全默认），焦点困在模态内，关闭后焦点回到触发元素。
- 发布确认按钮文案对齐既有语义：`确认发布（原 DST 与受影响 DWG 永久备份）`。

### 6.3 表单与校验

- 每个输入都有可见 `<label>`（禁止仅用 placeholder）；hint 与 error 通过 `aria-describedby` 关联。
- **失焦即时校验**（on blur）为主，提交时兜底；属性定义/结构变更分批的既有规则（"属性定义与结构变更必须分批预览和执行"）以行内提示 + 顶部错误摘要双重呈现。
- 校验失败：字段下方红字行内错误 + 顶部**错误摘要**（`role="alert"`、`tabindex="-1"`、提交后聚焦摘要标题、每条链接到对应字段），保留行内错误不被摘要替代。
- 高级录入（批量新增图纸、新建子集）默认**渐进展开**（折叠/分步），减少首屏控件数量。
- 数字输入用 `inputmode="numeric"` 并保留既有范围校验与错误文案。

### 6.4 数据表格

- 表头粘性、行可选择、批量选择条吸顶（沿用现有"全选当前结果/已选 N"）。
- 派生只读字段（图号、范围、标题）以 `--color-text-muted` + 只读样式呈现，并在悬停/说明中解释"由服务端统一派生，不可手工编辑"（P5）。
- 单元格内路径/handle 用 `--font-mono` 与 `overflow-wrap:anywhere`，长值可复制。
- 大列表保持**分页/虚拟滚动**（现有首屏 80 行 + 继续加载），满足性能预算（§10）；键盘模型见 §7.2。
- 行内状态用状态胶囊（`待变更` `阻断诊断` `已解析/未解析`），颜色 + 文字双通道，不单靠颜色。

### 6.5 空状态与首次引导

- 未打开工作区：空状态卡说明"选择 `.dst` 文件打开项目"（经壳原生对话框或拖拽，见 [SPEC-DM-007](SPEC-DM-007-v031-shell-and-usability.md) §4.1），附最近项目（若有）与"这是什么"简介。
- 筛选无结果：`没有匹配图纸，试试清除筛选` + 一键清除筛选。
- 空图纸集：首个子集引导（沿用"空图纸集首个子集序号必须为 1"校验）。
- 空状态一律"说明 + 下一步动作按钮"，不留白屏。

### 6.6 任务进度与反馈

- 写入/导入/修复/恢复用**任务浮层的"实施进度"页签**承载：整体进度条 + 逐文件行（目标路径、`cad_operation`、状态、耗时、开始/结束、错误码、重试建议），沿用现有 `JobStatusPanel` 数据结构。
- 连接模式（`SSE`/`轮询`）以小状态点呈现，不喧宾夺主。
- **SSE 任务通知（toast）**：任务状态迁移（成功、失败、整批回滚、`NEEDS_REVIEW`、修复/恢复完成）触发非模态 toast 通知：成功类简短、可自动消失并带"查看"入口（跳任务浮层对应页签）；失败类**常驻不自动消失**，带错误摘要与安全重试入口（`NEEDS_REVIEW` 禁止直接重试，沿用既有规则）。用户正停留在任务浮层对应页签时不重复弹；`aria-live` 成功 `polite`、失败 `role="alert"`；`prefers-reduced-motion` 关闭滑入动画；SSE 断线转轮询时通知由轮询事件照常驱动。
- 异步反馈匹配等待时长：即时操作不闪 spinner；长任务用骨架/进度 + `aria-busy`，`prefers-reduced-motion` 下关闭非必要动画。
- 成功给简短可关闭反馈（`toast`/内联）；失败保留可见且可操作（安全重试、`NEEDS_REVIEW` 禁止直接重试的既有规则）。

### 6.7 提示与信息层级

- `notice`（信息）、`warning`（需关注，如 `REPAIRED` 待确认）、`error`（阻断/失败）、`success` 四种横幅，统一使用 §5.1 的 `-bg` + 前景色 + 左侧色条 + 图标。
- 顶部错误条为全局兜底（沿用现有 `error`），但字段级问题优先行内呈现（§6.3）。

### 6.8 草稿与撤销（人性化重点）

- **持久化事实**：草稿由后端 `DraftStore` 持久化到应用数据目录（默认 `%LOCALAPPDATA%\dst-manager\drafts`），支持重开恢复、原子替换、损坏隔离与多窗口冲突检测。它**不修改项目目录、DST、DWG 或其时间戳，也不在项目内创建 `.dst-manager/`**。文案须如实区分"应用数据持久化"与"工程文件零修改"，不得宣称"不触碰磁盘"。
- 草稿计数常驻底部操作栏（`动作 3/3`），带向上箭头，点击展开**草稿栈浮窗**（限高滚动，`撤销/重做/清空` 就近可用，沿用现有草稿投影与冲突保护逻辑；键盘与焦点行为见 §7.2）。
- **保存状态反馈**：保存中、已保存、保存失败、版本冲突四类状态可观测；保存失败或 `DRAFT_VERSION_CONFLICT` 时中止工作区切换并保留编辑（沿用现有队列刷新语义）。
- 草稿过期/冲突（`DRAFT_VERSION_CONFLICT`、`BASE_REVISION_CHANGED`）用**专用状态卡**解释发生了什么 + 唯一安全出路（丢弃/经确认后重新加载较新草稿），禁止自动 rebase（沿用现状语义），文案更口语化。

### 6.9 ActionDock 操作 × 状态矩阵

底部操作栏与快捷键的行为**必须**由本矩阵唯一确定，消除 CTA 颜色、优先级与禁用逻辑歧义。列含义：**主操作**（推进当前态的唯一点睛动作，`Primary`/`Danger`）、**次操作**（描边/文字）、**禁用原因可见**（是否以 tooltip/内联文本说明）、**快捷键**（`Ctrl+Enter` 预览、`Ctrl+S` 写入，见 §7.1）。

## 7. 键盘操作与无障碍

### 7.1 快捷键与 `Ctrl+S` 语义

- 全流程可键盘完成：`Tab/Shift+Tab` 焦点顺序与视觉/DOM 顺序一致；`Enter/Space` 触发；模态与菜单焦点困绕，关闭后焦点回到触发元素。
- 快捷键（"帮助"面板内可发现）：`Ctrl/Cmd+O` 打开（触发 `.dst` 文件选择；壳形态下调原生对话框，无壳回退时聚焦路径输入，见 [SPEC-DM-007](SPEC-DM-007-v031-shell-and-usability.md) §4.1） · `Ctrl/Cmd+Enter` 预览 · `Ctrl/Cmd+S` 写入 · `Ctrl/Cmd+Z` 撤销 · `Ctrl/Cmd+Shift+Z` 重做 · `/` 聚焦搜索 · `?` 快捷键面板。
- **单字符快捷键约束（WCAG 2.1 SC 2.1.4）**：`/` 与 `?` 属于单字符快捷键，必须满足以下至少一项：可在设置中**整体关闭**、可**重映射**为其他键、或**仅在相关组件获得焦点时生效**。默认提供"关闭单字符快捷键"设置项（状态持久化），不得强制启用；同时仅在非文本输入焦点下判定，避免语音输入、输入法或辅助技术键入同名字符时误触全局动作。该约束连同关闭后的回归测试纳入 §10 验收。
- **`Ctrl+S` 绝不直接发起执行请求**：它只能针对"当前有效预览"打开对应的确认模态，且模态内仍须完成勾选等明确确认步骤（消除鼠标流程之外的安全旁路）。按 §6.9 定义的状态：
  - 无工作区或无草稿：不执行，给非阻断提示；
  - 尚未生成预览：引导先预览（等效"请先预览"）；
  - 草稿、工作区基准或服务端预览摘要已变化：预览失效，要求重新生成；
  - 存在阻断诊断、修复门禁或任务执行中：禁用写入快捷键；
  - 模态打开时：仍需显式勾选确认才可提交。
- `Ctrl+Enter` 预览同理：仅在允许预览的状态下触发，遵循 §6.9。

### 7.2 复合组件键盘模型

**结构树（标签①左区）**（`role="tree"`，roving `tabindex`）：

- `Up/Down` 在可见节点间移动焦点；`Right` 展开（叶节点时无操作或移入子级），`Left` 折叠（已折叠或有焦点时在父级间上移），`Enter`/`Space` 选中；`Home`/`End` 首/尾可见节点。
- typeahead：字符键跳到名称前缀匹配节点。
- **焦点与选中分离**：焦点用 `focus-visible` 环表示，选中用强调色填充 + `aria-selected="true"`；选中驱动标签①的图纸表格内容。

**数据表格（标签①右区）**（虚拟滚动 + 分页）：

- 表格整体为**单一 Tab 停靠点**；进入后 `Up/Down` 移动行焦点、`Left/Right` 移动列焦点（或随简单模式退化为行内 Tab）。
- `Space` 切换当前行选择；`Shift+Up/Down` 扩展选择；`Ctrl/Cmd+A` 全选当前筛选结果；选择数量通过 `aria-live="polite"` 播报（不仅靠颜色）。
- 表头排序按钮为**各自独立 Tab 停靠点**；`Enter`/`Space` 触发排序；排序/翻页用 `aria-sort` 表达状态。
- "继续加载"按钮可达且可键盘触发；虚拟滚动卸载当前焦点行后，**焦点恢复到最近仍在视口内的行**，不得丢焦到 `<body>`。

**标签栏（TabBar）**（`role="tablist"`，标签 `role="tab"`、面板 `role="tabpanel"`，roving `tabindex`）：

- `Left/Right` 在标签间移动并激活，`Home`/`End` 首/尾标签；激活标签对应的面板经 `Tab` 进入，标签栏不困绕。
- 任务浮层的三个页签复用同一模型；浮层收起后焦点归还其触发按钮。
- 草稿栈浮窗按下方抽屉模型执行（展开后焦点入浮窗、`Esc` 关闭、焦点归还草稿计数按钮）。

**抽屉 / 面板折叠**：触发按钮带 `aria-expanded` 与 `aria-controls`；打开后焦点移入抽屉首个可交互控件并困绕；`Esc` 关闭并把焦点还给触发按钮。

**全局**：提供 skip link（跳到主内容），并使用 `banner`/`navigation`/`main`/`complementary`/`contentinfo` landmark 标注顶栏/标签栏/内容区/任务浮层/底部操作栏。

### 7.3 无障碍目标（完整 WCAG 2.1 AA）

本工具承诺符合 **WCAG 2.1 AA 完整一致性要求**：满足全部适用的 A 级与 AA 级成功准则，**不得以未定义的准则子集代表 AA**。一致性范围覆盖 §4.3 的**全部响应式变体**（同一页面的不同呈现一并纳入判定），并覆盖动态状态播报（`aria-live`）与人工读屏走查。下列为重点对照清单，仅用于测试映射，不构成豁免：

- 感知：`1.1.1` 非文本内容、`1.3.1` 信息与关系、`1.4.1` 使用颜色（不单靠颜色）、`1.4.3` 对比度（最低）、`1.4.4` 调整文本大小、`1.4.10` 回流、`1.4.11` 非文本对比度、`1.4.12` 文本间距、`1.4.13` 悬停/焦点内容。
- 可操作：`2.1.1` 键盘、`2.1.2` 无键盘陷阱、`2.1.4` 字符键快捷键（`/`、`?` 按 §7.1 提供关闭或重映射）、`2.4.1` 绕过区块、`2.4.3` 焦点顺序、`2.4.4` 链接目的、`2.4.5` 多种查找方式（结构树 + 搜索）、`2.4.6` 标题与标签、`2.4.7` 焦点可见、`2.5.3` 标签包含名称。
- 可理解：`3.1.1` 页面语言、`3.2.2` 于输入时、`3.3.1` 错误识别、`3.3.2` 标签或说明、`3.3.3` 错误建议、`3.3.4` 错误防范（正式写入经确认，与本规范 §9 对齐）。
- 稳健：`4.1.2` 名称/角色/值、`4.1.3` 状态消息（`aria-live`）。

**仅当页面不存在对应内容时方可声明不适用**：`1.2.1`～`1.2.5`（无时间基媒体内容）、`2.2.1`～`2.2.6`（无任何时限与会话超时）、`3.1.2`～`3.1.6`（界面为单一简体中文，页面内无其他语言段落）。上述之外的其余 A/AA 准则均为适用项并纳入验收。

### 7.4 通用可访问性

- 所有动态状态（任务进度、错误摘要、写入结果、草稿保存态）通过 `aria-live`（`polite`/`assertive`）播报；错误用 `role="alert"`。
- 焦点可见：`focus-visible` 环（2px `--color-focus`、偏移 2px），粘性/吸底栏与遮罩不得遮挡焦点。
- 对比度按 §10 的计算组合值判定，非颜色单指示、可放大文本不破版、`prefers-reduced-motion` 降级动画。

## 8. 接口（与后端的契约边界）

界面是后端契约的**消费者**，不复制领域规则、不要求改动既有请求模型：

- 继续以 OpenAPI 生成的类型（`web/src/api/schema.d.ts`）为唯一事实来源，界面字段与服务端命名一致。**壳桥是 OpenAPI 之外的第二契约面**：桌面壳原生能力（`window.pywebview.api` 的 `select_file`/`on_files_dropped`）的定义与演进归 [SPEC-DM-007](SPEC-DM-007-v031-shell-and-usability.md) §3.2 管理；界面必须在桥缺失时优雅降级（无壳回退），不得假设壳必然存在，也不得经壳桥引入绕过 §9 门禁的写入通道。
- 预览、诊断、语义差异、受影响文件、数量前沿、CAD 分组等**全部来自服务端**；前端只负责渲染与交互，不重算校验、不猜模板、不本地派生图号/标题。
- **正式工程文件写入的执行请求**必须同时绑定**当前 `base_revision_id` 与服务端生成的 `preview_digest`**（覆盖 §9.1 全部类型）。基准变化或摘要失效时返回 `409`，界面强制"重新预览"，不静默重试。
- **并发控制按类型区分**，不得笼统要求所有写请求携带 `base_revision_id`：
  - 草稿保存/删除以 `expected_version` 控制多窗口冲突（`DRAFT_VERSION_CONFLICT`），并携带其基准与修复状态；
  - 任务重试复用服务端冻结的原始计划与摘要，由客户端仅提交作业 `id`，**不重新提交基准**；
  - 应用内部状态、操作日志、自动回滚与启动恢复不属于用户确认的工程文件发布，不适用危险确认。
- 为支撑外壳与任务浮层上下文，若需聚合状态（任务列表、诊断计数），复用既有端点，不新增绕过门禁的写接口。

## 9. 数据与安全边界

### 9.1 正式工程文件写入（统一分类与门禁）

定义 **正式工程文件写入** = 任何用户发起、可能修改 DST、DWG 或其他正式工程文件的操作。**统一术语**：

- **预览**：调用服务端只读计算差异/诊断，产生 `preview_digest`，**永不写盘、可反复执行**。
- **确认写入**：在有效预览之上，经危险模态明确确认后提交执行，是唯一的不可逆边界。
- **发布**：普通变更确认写入的专名（"确认发布"）。

纳入"正式工程文件写入"、必须共用同一套门禁（服务端预览 → 冻结摘要 → 基准复核 → §6.2 危险确认模态 → §6.6 任务结果反馈）的类型：

1. 普通变更发布（`changes/execute`）；
2. CSV 属性导入（`custom-properties/import`）；
3. XML 导出/覆盖（`xml/export-dst` 等覆盖正式文件的执行）；
4. 修复发布（`repairs/execute`，SPEC-DM-004）；
5. 修订恢复（`revisions/{id}/restore`，PLAN-DM-001/002、ADR-DM-004）。

明确**排除**在该分类之外（不触发危险确认模态，但仍各自受控）：草稿持久化、操作日志、只读导出（不覆盖正式文件）、失败自动回滚、启动恢复、内部维护状态写入。

### 9.2 安全约束

本规范不得削弱既有发布安全（AGENTS.md、ARCH-DM-001、ADR-DM-001/004、SPEC-DM-004/005）：

- 只读打开工作区不得触发工程文件写入、创建 `.dst-manager/` 或改动 DST/DWG/时间戳——界面文案与控件也不得暗示预览会写盘（草稿写入应用数据目录是独立事实，见 §6.8）。
- "预览"永远是安全动作；§9.1 的"正式工程文件写入"是不可逆写，必须经完整预览 + 基准校验 + 危险确认模态。
- 不得把用户输入直接拼成 SCR/Shell/路径命令；界面不得提供自由格式命令输入。
- 删除类操作保留"外部引用由用户承担影响"的既有确认声明，不得为"简洁"而省略。
- MVP 阶段服务只监听 `127.0.0.1`，界面不得暴露远程访问入口。

## 10. 测试与验收

### 10.1 自动化

- **令牌消费检查**：stylelint 规则要求组件样式仅引用 §5 声明的语义/组件令牌，不得出现裸十六进制色值或未声明的自定义间距（断点、1px 边框、令牌表内合法常量不计为违规）。
- **对比度检查**：以**实际渲染的前景/背景组合**计算，而非孤立令牌；浅/深双主题下正文 ≥ 4.5:1、非文本 UI/大文本 ≥ 3:1，并覆盖 `hover/active/focus/disabled`。
- Playwright E2E 覆盖：外壳导航（标签切换、任务浮层页签自动激活）、模态危险确认（含勾选门禁，且覆盖普通发布 / CSV / XML / 修复 / 恢复各类型）、表单错误摘要与焦点、空状态、任务进度与 SSE 通知 toast、草稿保存态与冲突卡、草稿栈浮窗、深浅主题切换。
- 无障碍：axe 扫描无 Critical/Serious 问题；**补充键盘序列与焦点断言**（树 `Up/Down/Left/Right/Home/End/typeahead`、表格单停靠点与卸载后焦点恢复、抽屉 `Esc` 焦点归位、`Ctrl+S` 旁路防护断言）；**读屏播报与语义正确性仍须人工走查，不得仅以 axe 结果代替**。
- 性能预算（**固定 Chromium 环境、多次采样，记录中位数与 P95**，与 PLAN-DM-002 结论一致，单次结果不作门禁）：300 行工作区首屏可交互 ≤ 1500ms、搜索过滤中位 ≤ 50ms、P95 ≤ 100ms；冷/热启动分别计时并声明计时边界。

### 10.2 视觉与响应式矩阵

对下列**视口 × 主题**组合做截图/视觉回归，视口一律固定宽与高：`1024×768`（最小支持）、`1120×768`（任务浮层折叠断点）、`1440×900`（基准）、`900×768`（标签栏滚动与左树折叠断点；低于最小支持宽度，仅作韧性测试而非正式支持门槛）；主题 `light`、`dark`。每个组合须无溢出、无塌版、CTA 分级正确，且折叠断点下任务浮层与标签①左树能力可经抽屉完整访问（§4.3、§7.2）。

## 11. 落地顺序建议（非强制）

1. 令牌层：把现有 `style.css` 拆解为语义 CSS 变量 + 完整双主题映射（§5.1），建立 stylelint 与组合对比度校验。
2. 组件层：按钮、模态（含危险确认，覆盖 §9.1 各写入类型）、表单/错误摘要、状态胶囊、任务进度（浮层页签）、任务通知 toast、空状态、TabBar 状态机、ActionDock 状态机（含草稿栈浮窗）。
3. 外壳层：TopBar / TabBar / 标签内容区 / 任务浮层 / 底部操作栏（含草稿栈浮窗），迁移现有视图并落地 §7.2 键盘模型。
4. 交互层：快捷键（含 `Ctrl+S` 旁路防护）、焦点管理、进度与反馈、草稿状态卡。

每步以"最小充分测试"验证，不改变后端契约与发布安全流程；实现细节由后续 Plan 承接。若修订恢复需长期稳定为产品契约，另立 Spec（§4.2 注）。
