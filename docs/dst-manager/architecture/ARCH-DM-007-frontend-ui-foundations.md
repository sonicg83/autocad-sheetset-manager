# DST Manager 前端视觉基础与渐进整改架构

> 定位：规定 DST Manager 前端视觉基础、公共控件、样式作用域、可访问性和回归门禁的实现边界；承接 2026-09-14 用户截图复验发现的控件字号、尺寸和跨页面一致性问题。
>
> 核心裁决：采用“设计基线与门禁 → 公共视觉原语 → 页面渐进迁移 → 结构治理 → 真实桌面验收”的顺序，不引入大型 UI 框架，不改变后端 API、草稿投影、发布安全或业务流程。

## 1. 背景与问题

现有前端已具备浅深主题、页面级 scoped 样式和较完整的 Playwright 测试，但仍存在以下系统性偏差：

- 根元素只声明字体族，没有声明正文基准字号；`button,input,select,textarea { font: inherit }` 使未单独指定字号的控件继承浏览器默认 `16px`，与大量 `12px`、`13px` 页面文字形成断层。
- SPEC-DM-006 要求本地内嵌 Inter、`--font-ui`、`--font-mono`、正文 `14px`，生产代码尚未形成对应字体资产和令牌。
- `web/src/style.css` 同时包含令牌、reset 和页面业务规则；裸 `aside`、`article`、`table` 及 `.panel`、`.toolbar`、`.primary` 等选择器仍可能跨组件命中。
- 控件高度存在 `24/28/30/32/34/36/38px` 多档，部分按钮低于 SPEC-DM-006 的 `32px` 最小可点高度。
- 结构图标仍混用 `⚙`、`◐`、`✕`、`▸`、`▾`、`«`、`»` 等字体符号；渲染尺寸、基线和字形依赖 Windows 字体环境。
- `TaskOverlay.vue` 的 hover 边框使用 `var(--color-border, var(--color-bg-surface-2))` fallback 链；主变量与内层 fallback 均未定义，声明在 computed-value 阶段失效并回到继承值/初始值，不要求浏览器控制台产生错误。静态门禁因此必须递归解析 `var()` 的 fallback，而不能只检查最外层变量名。
- 视觉回归主要断言控件高度和布局，没有断言实际 `font-size`、`font-family` 与 `line-height`，因此测试全绿仍可漏过字号膨胀。
- `App.vue` 已超过本仓库协作规范约 500 行的源文件软上限；旧组件仍有无 `type="button"` 按钮，图纸树的 Tab 入口与嵌套交互也需收敛。
- SPEC-DM-006 与 GUIDE-DM-001 仍处于 `review`，但依赖它们的页面规范和已完成计划已把其中规则当作验收依据，治理状态不一致。

## 2. 目标与非目标

### 2.1 目标

- 建立可执行、可测试的字体、字号、控件尺寸、圆角、图标和层级令牌。
- 建立少量 Vue 公共视觉原语，使同类控件只有一个默认实现入口。
- 清理无效变量和跨页面全局样式污染，同时保持页面渐进迁移能力。
- 统一可见标签、点击目标、焦点管理、图纸树键盘模型和按钮语义。
- 将 `App.vue` 收敛为壳层编排入口，不继续承载可独立的状态域。
- 把静态检查、计算样式、视觉证据和真实桌面复验串成可失败的门禁。
- 使架构、Spec、Guide、Plan、索引和变更记录的状态与实际证据一致。

### 2.2 非目标

- 不修改 FastAPI/OpenAPI 契约、后端领域规则、草稿命令结构或发布事务。
- 不修改 DST/DWG、数据库模型、CAD SCR、Worker 插件或 AutoCAD 版本支持。
- 不引入需要运行时联网的字体、图标或其他资源。
- 不引入 Vuetify、Element Plus、Tailwind 或其他大型 UI 框架。
- 不在本轮重新设计业务流程、信息架构、颜色品牌方向或桌面壳导航。
- 不以一次性重写替代渐进迁移；不为追求行数拆散紧密业务逻辑。

## 3. 总体架构

```text
SPEC-DM-006 / 页面级 Spec
            ↓
原始令牌 → 语义令牌 → 组件令牌
            ↓
UiButton / UiIconButton / FormField / UiIcon / 对话框焦点工具
            ↓
图纸、属性、图纸目录、设置、旧页面渐进迁移
            ↓
静态门禁 + 单元测试 + 计算样式 + 视觉证据 + 真实桌面复验
```

依赖方向为：

```text
页面业务组件 → 公共视觉原语 → 设计令牌
页面业务组件 → 既有 composable / API contract
公共视觉原语 -X→ 业务状态、API 或草稿规则
```

公共视觉原语只统一外观、HTML 语义、可访问名称、焦点和交互状态，不复制后端校验，不读取业务 Store，也不改变现有 props/emits/API 数据流。

令牌分层的**当前落实程度**与一条有界豁免（颜色、间距、圆角、图标尺寸四族尚无语义层，暂按 §4.1 的例外口径执行）记在 §4.1。

## 4. 设计令牌

### 4.1 三层令牌

令牌分为三层：

- 原始令牌：字号、间距、尺寸、圆角和图标规格的有限值域。
- 语义令牌：正文、标签、辅助文字、表单控件、紧凑工具栏等用途。
- 组件令牌：按钮、输入框、图标按钮和模态等默认值。

初始基线如下：

| 类别 | 令牌/规则 | 基线 |
| --- | --- | --- |
| 字体 | `--font-ui` | `"Inter", "Microsoft YaHei", system-ui, sans-serif` |
| 等宽字体 | `--font-mono` | `"IBM Plex Mono", ui-monospace, Consolas, monospace` |
| 正文 | `--font-body` | `14px / 1.5` |
| 标签、表格 | `--font-label`、`--font-table` | `13px` |
| 辅助文字 | `--font-caption` | `12px` |
| 普通控件 | `--control-height-default` | `36px` |
| 表单输入 | `--control-height-form` | `38px` |
| 紧凑工具栏 | `--control-height-compact` | `34px` |
| 图标按钮 | `--icon-button-size` | 不小于 `36px` |
| 最小可点高度 | 全局下限 | `32px` |

组件只能消费已声明的语义令牌或组件令牌。断点、1px 边框、内容驱动高度和经 Spec 明确批准的例外可以使用常量；其余原始值必须由静态检查拒绝或进入有原因、有到期条件的白名单。

**当前落实程度与一条有界豁免（颜色、间距、圆角、图标尺寸）**：仓库尚未建立颜色、间距、圆角、图标尺寸这一层的**语义令牌**，因此上述四族目前仍是跨层直取原始令牌。口径（可跑，实测于 2026-09-15）：

```text
grep -rhoE 'var\(--(color|space|radius|icon-size)-' web/src --include=*.vue | wc -l   # 1025 处
grep -rlE  'var\(--(color|space|radius|icon-size)-' web/src --include=*.vue | wc -l   #   44 个 .vue 文件
```

（该数字随页面迁移而下降：组件层与语义层落地后，本文其余部分已统一消费语义/组件令牌。）处置口径：**先保持一致，不得为落实分层而临时新造色板或间距层**；待语义层补齐后统一收口，并同时更新本节数字。在该收口完成前，上述四族的跨层直取按本节「经 Spec 明确批准的例外」处理，属**有界且待收回**的豁免，不得据此新增其它原始值直取。依据：PLAN-DM-029 收口责任 E（Task 3 二轮评审 G1）。

`38px` 表单输入档继续保留：SPEC-DM-006 允许 `36–40px`，而 SPEC-DM-010 与 PLAN-DM-016 已明确把属性页生产输入固定为 `38px` 并形成冻结证据。本文不以减少令牌档位为由改写已接受的页面规范；未来若统一为 `36px`，必须先修订页面 Spec、冻结件和对应回归证据。

### 4.2 字体资源

- Inter 可变字体子集与 IBM Plex Mono 子集随 Web 产物本地打包，使用 WOFF2、`@font-face` 与 `font-display: swap`。
- 两套子集只包含 Basic Latin（`U+0020–007E`）、Latin-1 Supplement（`U+00A0–00FF`）和界面实际使用的通用标点；明确不打包 CJK 字形，中文继续走系统回落。生产 WOFF2 合计预算不超过 `250 KiB`；超过时必须记录字符清单、体积证据和重新裁决。
- 字体文件必须核验许可证、字符覆盖、压缩后体积和离线加载；不使用 CDN。
- 中文继续回落到 Microsoft YaHei，系统字体缺失时使用 `system-ui`。
- 字体加载失败不得改变控件盒模型；计算样式测试同时覆盖首选字体与回落栈声明。
- 当前路径、哈希和错误码区域硬编码的 `ui-monospace, Consolas, monospace` 迁移到 `--font-mono` 后字形宽度会变化；必须对表格列宽、换行、复制区和长路径执行同态视觉复核，不得只校验字体变量已替换。

## 5. 公共视觉原语

推荐目录：

```text
web/src/
├─ styles/
│  ├─ tokens.css
│  ├─ reset.css
│  ├─ primitives.css
│  └─ legacy.css
└─ components/ui/
   ├─ UiButton.vue
   ├─ UiIconButton.vue
   ├─ UiIcon.vue
   ├─ UiInput.vue
   ├─ UiSelect.vue
   ├─ FormField.vue
   └─ dialogFocus.ts
```

原语职责：

| 原语 | 职责 | 不负责 |
| --- | --- | --- |
| `UiButton` | `primary/secondary/danger/link`、`default/compact`、禁用和加载状态 | 业务确认、API 调用 |
| `UiIconButton` | 固定点击面积、可访问名称、tooltip 与图标隐藏语义 | 图标语义推断 |
| `UiIcon` | 本地 SVG、尺寸、笔画和主题色 | 任意 HTML/SVG 注入 |
| `UiInput` / `UiSelect` | 字体、盒模型、焦点、禁用、错误态透传 | 最终业务校验 |
| `FormField` | 可见 label、hint/error ID 与 `aria-describedby` | 表单提交编排 |
| `dialogFocus.ts` | 初始焦点、Tab 圈闭、Escape 与焦点归还 | 决定是否允许关闭 |

不强制一次替换全仓控件。只有迁移页面和新增页面必须使用原语；旧页面在对应阶段迁移并通过门禁后再删除旧样式。

## 6. 图标策略

- 使用一个本地 SVG 描边图标族，首选 Lucide 的 MIT 许可图标；只纳入实际使用的图标资源，不新增运行时网络或动态包扫描。
- 统一 `stroke-width: 1.5–2`，图标视觉尺寸通过 `--icon-size-sm/md/lg` 控制，点击面积由按钮控制。
- 可见文字旁的装饰图标使用 `aria-hidden="true"`；独立图标按钮必须有可读名称，状态类按钮必须暴露 `aria-expanded`、`aria-pressed` 或 `aria-selected`。
- 阶段 2 在 `UiIcon`/`UiIconButton` 成立后先迁移壳层共用的 `TopBar`、任务浮层、关闭按钮和折叠箭头；这些工作属于公共原语纵向验证，不等待阶段 3 的页面顺序。属性、图纸目录、图纸和设置内部的页面级图标则跟随各自页面迁移。
- 图纸目录的 `↑ / ↓ / ✕` 是 PLAN-DM-023 已批准差异；本轮先登记为临时例外，待 SVG 原语完成后以同态截图和键盘行为复核决定是否移除。未获批准前不静默改变其用户可见形式。

## 7. 样式作用域与迁移

`web/src/style.css` 最终只保留入口导入，实际内容按以下职责拆分：

- `tokens.css`：浅深主题映射和三层令牌。
- `reset.css`：`box-sizing`、body margin、继承字体、焦点可见和 reduced-motion 等基础规则。
- `primitives.css`：公共视觉原语必须共享的样式。
- `legacy.css`：尚未迁移页面的兼容规则，必须由明确根类限定。

采用 `@layer tokens, reset, primitives, legacy` 固定全局样式的级联顺序。Vue 单文件组件的 `<style scoped>` 当前是无层（unlayered）样式，按 CSS 级联规则优先于所有命名 layer；这是页面在迁移期能够覆盖全局默认值的明确前提。实施者不得另建 `components` layer 承载页面样式，也不得依赖提高 specificity 与原语竞争。原语通过 CSS 自定义属性、组件 props 和受控 variant 暴露定制点；页面 scoped 样式只处理确属页面布局的差异。

迁移顺序按可见问题与风险排列：

1. 属性页；
2. 图纸目录页；
3. 图纸页与任务浮层；
4. 设置中心；
5. 修订历史、修复、草稿等旧页面。

每一页必须先写计算样式和行为红灯，再迁移原语；消费方全部迁移且浅深主题通过后，才能删除对应 legacy 规则。

## 8. 结构治理

### 8.1 App.vue

`App.vue` 保留根装配、跨域事件连接和顶层渲染。按现有责任边界评估并优先拆出：

- `useWorkspaceLifecycle`：打开、关闭、恢复和工作区切换；
- `useDraftGuards`：未提交输入、草稿恢复和全局门禁；
- `useShellNavigation`：页签、任务浮层、焦点和跳转；
- `useWorkspaceCommands`：页面事件到既有命令/API 调用的编排；
- `WorkspaceShell.vue`：纯壳层布局。

拆分必须保持公共 props/emits、错误码、序列化结构和用户流程不变。目标是把 `App.vue` 收敛到约 `350–450` 行；若某段逻辑只有在根装配中才可理解，则保留，不为行数机械拆分。

### 8.2 语义与可访问性

- 全部按钮显式声明 `type="button"`；真正表单提交必须单独声明 `submit`。
- 所有输入具有可见 label；搜索等需要视觉紧凑的场景可使用可见但视觉弱化的 label。若确需无可见标签，必须在 SPEC 登记例外并保留可访问名称。
- `BooleanSwitch` 的视觉轨道可保持 `44×24px`，但实际点击盒必须扩展到至少 `44×32px`，不能只扩大装饰轨道。
- 图纸树采用单一 roving tabindex 模型：Tab 进入当前活动 `treeitem`，容器本身不形成额外停靠点；展开、收起、激活和方向键行为符合既有 SPEC-DM-009。
- 避免在 `treeitem` 内嵌第二个常驻 Tab 控件；展开动作由树项键盘模型和统一点击区域承担，或将按钮移出复合控件语义。
- 模态继续按 SPEC-DM-006 选择原生 top layer 或遮罩式原语，焦点逻辑复用 `dialogFocus.ts`；不得改变已有“嵌套模态必须使用原生 dialog”的裁决。

## 9. 自动门禁与验证

### 9.1 静态门禁

新增前端检查脚本并接入 `npm run build`：

- `var(--*)` 必须能在全局令牌、组件局部定义或动态变量白名单中解析；检查器递归遍历每个 `var()` 的 fallback 参数并拒绝未定义引用、循环引用和“外层有 fallback、内层仍不可解析”的声明。动态变量白名单必须同时登记生产者文件与消费方，不能只登记变量名；
- 禁止新增 Emoji/Unicode 结构图标；批准例外按文件、行语义和到期条件登记；
- Vue `<button>` 必须显式声明 `type`；
- 禁止业务组件新增裸全局选择器和未登记的十六进制颜色；
- 字号、高度、圆角和图标尺寸必须使用令牌或有理由的白名单。

检查器必须能通过变异测试证明可失败，不能只扫描已有文件并输出警告。变异套件在检查器首次引入及检查规则、解析算法或白名单格式变化时运行；普通 CI 每次只运行确定性的静态检查和检查器单元测试，不重复执行高成本变异轮。

### 9.2 组件与行为测试

- 单元测试覆盖视觉原语的 size/variant、disabled/loading、可访问名称、label/hint/error 关联和焦点工具。
- 图纸树测试覆盖 Tab 入口、方向键、Home/End、展开、激活和焦点恢复。
- 旧按钮补 `type` 时保持点击、禁用和事件发射行为不变。

### 9.3 计算样式和视觉证据

Playwright 直接断言：

- `html/body` 的 `font-size`、`font-family` 和 `line-height`；
- 普通、表单、紧凑和图标按钮各自的字号、盒模型、高度、圆角及对齐；
- 浅深主题下 hover、active、focus、disabled、selected 的前景、背景和边框；
- 字体或图标回落不改变控件布局。

视觉验证采用正交抽样，不计算“视口 × 主题 × 缩放 × 状态”的笛卡尔积：

| 维度 | 自动化覆盖 | 截图证据 |
| --- | --- | --- |
| 状态 | 每个迁移页面在 `1440×900`、浅色、100% 下覆盖正常、选中、展开、错误、禁用、加载和长文本；尽量使用行为/计算样式断言 | 每页选择默认、错误或该页最关键的 1–2 个状态 |
| 主题 | 每个页面在 `1440×900`、100% 下覆盖浅/深主题的默认态与一个高风险状态 | 每页至少浅色默认和深色默认各 1 张 |
| 视口 | 默认态分别跑 `900×768`、`1024×768`、`1120×768`、`1440×900` 的布局与溢出断言 | 每页只保留最窄支持视口或最能暴露问题的 1 张 |
| 缩放 | 自动化只在属性页、图纸目录页、图纸页三个关键密集页面跑 200% 韧性测试 | Windows 100/125/150/200% 由真实 WebView2 验收抽查；125% 为常用主样本，其余比例各抽查壳层和一个密集页面 |
| 用户缺陷 | 固定覆盖本次截图中的属性页、图纸目录页和批量编辑区 | 三个场景各保留修复前后同态证据 |

单页迁移阶段的新增持久截图以 `4–6` 张为上限；整轮整改新增基准预计 `24–30` 张。超出上限时优先把几何、字体和状态验证下沉为计算样式/行为断言，只有人工必须判断的视觉关系才保存截图。Playwright 的浏览器缩放或 `deviceScaleFactor` 不能替代 Windows 显示缩放结论，真实缩放只由 pywebview/WebView2 验收关闭。

自动截图附件不等于通过。冻结 Demo、生产截图和计算样式必须在相同状态下对照，P0/P1/P2 差异未清零时不得关闭 G8。

## 10. 分阶段交付

| 阶段 | 可独立交付内容 | 退出条件 |
| --- | --- | --- |
| 1. 基线与门禁 | 令牌、字体资产方案、静态检查、计算样式红灯 | 已知字号、无效变量、Unicode 图标和尺寸问题可稳定失败 |
| 2. 公共原语 | 按钮、输入、图标、表单字段、焦点工具 | 原语单测通过，不承载业务逻辑 |
| 3. 页面迁移 | 按属性→目录→图纸/浮层→设置→旧页面迁移 | 每页构建、行为、浅深主题和视口矩阵独立通过 |
| 4. 结构治理 | `App.vue` 拆分、图纸树、旧按钮、重复模态逻辑 | 公共接口不变，容量和键盘问题关闭 |
| 5. 验收闭环 | 全量门禁、真实桌面截图、文档状态收口 | 用户真实桌面确认，Spec/Guide/Plan/索引一致 |

阶段关系固定为 `1 → 2 → 3 → 4 → 5`。阶段 3 内各页面可独立提交，但按上述顺序串行验证，避免同一全局样式被并发修改；阶段 4 必须等待阶段 3 全部页面迁移完成后开始，且不得与阶段 3 并行修改 `App.vue`、`SheetTree.vue`、`TopBar.vue`、`TaskOverlay.vue` 或其直接依赖。阶段 4 只处理与本整改直接相关的结构债，不扩展到后端或无关功能重构。

## 11. 兼容性与回退

- 每个任务先写失败测试，再做最小实现；一次提交只完成一个可独立审查的整改单元。
- 页面迁移保持现有组件公开接口、API 请求、i18n key、草稿命令和错误码不变。
- legacy 样式只有在全部消费方迁移且验证通过后才能删除；回退时可恢复单页旧入口，不要求回滚整批整改。
- 字体、图标或 CSS 拆分若导致打包缺资源，构建必须 fail-closed，不允许退化为运行时联网。
- 实施中发现业务行为必须改变时，停止当前任务并另立 Spec/ADR，不把行为变化夹带在视觉提交中。

## 12. 完成标准
