# 延后 CAD 校验与子集级 CAD 操作分流

## 背景

v0.21 的结构差异预览会逐个启动 Core Console 检查模板和既有 DWG 的布局；随后确认执行又为每个重建单元启动一次 Core Console。四个子集各插入图纸时，预览的串行进程启动已经占据主要等待时间，且确认后仍会重复同类工作。

现有结构计划把每个受影响子集都视为“清除布局并重建”。但子集内图纸不能切分处理，并不等于所有变更都需要重建：仅改变子集名、图号顺行或图名序号后缀时，布局内容与 Handle 保持不变，只需批量修改布局名称。

## 决策

### 快速预览不启动 AutoCAD

结构差异预览只执行确定性派生、DST DOM 差异和轻量来源基准采集（路径、存在性、扩展名、文件身份与 SHA-256）。它必须立即给出受影响 DWG、操作类型与数量，但不得启动 Core Console，也不得创建工作区状态目录或写入 DST/DWG。

真正的布局存在性、布局集合、图纸来源和 CAD 版本校验移至用户点击“确认并执行”后的暂存任务。预览后的任何来源身份或内容变化仍会使任务拒绝发布并要求重新预览。

### 一个 CAD 工作单元只启动一次 Core Console

确认后的每个 CAD 工作单元在其暂存 DWG 内完成来源复核、CAD 校验、对应的布局操作、结果核验与保存；不得先单独检查再为同一单元重新启动进程。校验失败只能使暂存任务失败，不能触及正式 DST/DWG 或发布事务。

所有此类单元共用一个全局并发预算，配置 `DST_MANAGER_CAD_MAX_PARALLEL` 的合法范围为 1–10，默认值为 4。并发预算限制的是同时运行的 Core Console 进程总数，而不是预览请求数。

### 按子集图纸数量变化前沿分流

对原始结构和最终派生结构按最终子集顺序逐个比较。首个发生图纸数量变化的子集是“数量变化前沿”。下列情况构成数量变化：

- 既有子集的图纸数量不同；
- 插入非空子集；
- 删除原有子集；
- 删除或插入图纸。

数量变化前沿及其后的所有最终子集都必须进入 CAD 工作范围，因为全局图号和布局名称可能顺移。前沿之前，只有自身发生布局相关变化的子集才进入工作范围；仅改变子集名不会使后续子集进入工作范围。

每个最终子集只能是以下三种操作之一：

| 操作 | 条件 | CAD 行为 | Handle/DST 行为 |
| --- | --- | --- | --- |
| `none` | 子集在最终状态与原始状态无布局相关变化，且不在数量变化前沿之后 | 不启动 Core Console | 不修改该子集布局绑定 |
| `rename_only` | 图纸数量、稳定图纸 ID、顺序与布局内容来源均可证明未变，只需改变布局名或目标 DWG 路径 | 在暂存 DWG 中批量改名并校验结果 | 不读取 Handle，不重写既有 `AcDbHandle` |
| `rebuild` | 图纸数量、图纸集合、顺序、布局内容来源发生变化，或无法证明仅改名 | 清除子集全部纸空间布局并按最终列表重建，再读取 Handle | 用新读取的 Handle 写入派生 DST |

因此，“数量变化前沿之后”规定工作范围，不强制所有单元都重建；其中能够证明布局内容未变的单元使用 `rename_only`。

### `rename_only` 由受限插件命令执行

新增 AutoCAD 2016/2020 对应版本的 `DstRenameLayouts` Worker 命令。Python Worker 为每个暂存工作单元生成受控映射副文件；SCR 只传递经既有安全编码的副文件路径，不把用户文本拼接为命令。

命令必须验证当前整个纸空间布局集合与预期旧名称完全一致，拒绝模型空间、缺失布局、重复名称、非法目标名称和意外布局。重命名采用“旧名称 → 任务生成的临时名称 → 最终名称”的两阶段过程，避免名称互换或循环映射冲突。命令保存前验证最终布局集合，并写出只含最终名称集合及改名数量的结果副文件。

`rename_only` 不调用 `DstDeleteLayouts`、不导入布局、不调用 `DstGetLayoutHandles`，也不通过导出结果回写 DST Handle。若前置条件不成立，任务失败；不得静默降级为破坏性重建。

### 事务边界不变

所有 CAD 修改仍发生在写锁内的暂存副本中，并继续使用永久 before 快照、来源基准复核、发布清单、整批回滚和启动恢复。只有所有 `rename_only` 和 `rebuild` 单元成功、DST DOM 复核通过后，才允许统一发布。

## 后果

- 结构差异预览从“等待 CAD 检查”变为纯计算和文件基准采集，可更快展示受影响 DWG 与计划操作。
- 快速预览不再提前报告 CAD 布局问题；这些问题会在确认后的暂存任务中失败并保持正式文件不变。
- 标题、图号及后缀顺行等命名变更不再无条件清除和重建大量布局，降低耗时与风险。
- 工作计划、SSE 进度和 Web 预览必须显式暴露 `none`、`rename_only`、`rebuild`，避免用户误解为所有受影响 DWG 都会重建。
- 当前 `ADR-DM-002` 中“结构性工作单元一律执行 `DstDeleteLayouts`”的具体选择由本 ADR 替代；其“一单元一次 Core Console、暂存后发布”的安全边界继续保留。

## 未采纳方案

- 保留预览阶段逐个 Core Console 检查：可提前获得布局诊断，但进程启动延迟与确认阶段重复工作不可接受。
- 对所有进入范围的子集一律完整重建：实现简单，但命名类变更对大量图纸做无效清除、导入和 Handle 回写。
- 在一个子集内按单张图纸拆分重建：插件的清除布局语义覆盖整个子集 DWG，不能安全切分。
