# 受控图纸集编辑替代自由调整模型

## 背景

`ARCH-DM-001` 的 MVP 编辑能力允许同一子集内移动图纸、跨子集移动图纸、调整子集顺序，以及手工修改图纸标题。`SPEC-DM-001` 的 v0.21 业务复核表明，这些自由调整入口会让图号范围、子集显示名、图纸标题、DWG 文件名和布局名在多个位置重复维护，预览也难以完整说明最终结果。

同时，图纸标题已经被重新定义为子集标题的派生值，并可按环境配置决定是否追加序号后缀。继续保留手工标题编辑与自由排序，会直接破坏“最终顺序一次性派生全部命名结果”的约束。

## 决策

DST Manager 从自由调整模型切换为受控插入和派生模型：

- 移除 `move_sheet`、`reorder_sheet`、跨子集移动图纸和既有子集独立排序能力；
- 移除手工修改图纸标题的能力，图纸标题统一由子集标题派生；
- 结构性新增统一改为“按位置插入子集”与“按位置批量插入图纸”；
- 所有结构性变更提交后，统一基于最终子集顺序与图纸顺序，派生图号、子集图号范围、子集显示名、图纸标题、标题后缀、DWG 文件名、布局名和 DST 路径引用；
- 执行前必须展示完整预览，明确顺序变化、标题变化、后缀变化以及待创建或重建的 DWG/布局。

标题后缀的开关和类型属于运行配置，不作为用户自由输入写入 DST；领域和后续派生器只读取已经过 `Settings` 校验的 `enable_add_number_suffix` 与 `number_suffix_type`。

## 备选方案

### 保留自由编辑，仅在保存前尝试纠正派生结果

该方案需要在标题、图号、排序和 DWG/布局命名之间执行隐式修正，用户难以预测最终结果，也会扩大预览与回滚的验证面。

### 仅隐藏旧界面入口，保留底层命令

该方案不能真正收敛行为边界，API、脚本或后续调用仍可绕过新规范，无法保证所有结构性变更都经过统一派生和完整预览。

## 影响

- API、Web 和领域命令必须围绕“插入、派生、预览”重组，不再暴露旧排序和手工标题编辑入口；
- 后续纯领域派生器可以把标题后缀开关与类型视为已校验配置，而不是再次读取环境变量；
- 预览需要成为结构性编辑的强制入口，用于审阅图号范围、标题/后缀、DWG 与布局的最终结果；
- `ARCH-DM-001` 已确认的 DST/XML 受控修改、CAD Worker、双版本 AutoCAD、永久 before 快照和可恢复整批发布事务保持不变。

## 替代关系

本 ADR 替代 `ARCH-DM-001` 第 4.2 节中“在同一子集内移动图纸”“跨子集移动图纸，同时把布局迁移到目标 DWG”“修改子集名称和顺序”“修改图纸图号、标题”的自由编辑表述；其余关于事务发布、Worker 边界、路径解析、DOM 兼容和安全发布的基线继续有效。
