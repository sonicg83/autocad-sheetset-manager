# 设置中心核心配置的 Esc 关闭闸门与子视图语义不一致

日期：2026-09-13

状态：待办（未立项；来源评审条目 R22①，前向绑定自 PLAN-DM-025 任务 7/8 的复核）

关联：`SPEC-DM-011`、`PLAN-DM-025`、`MEMO-DM-034`

## 问题

`web/src/components/settings/SettingsDialog.vue` 的 `tryClose()` 在核心配置有未保存修改时会打开一次内联确认框，但该确认框没有消费 Esc：

- 复现探针（PLAN-DM-025 任务 7/8 复核）：核心配置脏状态下按 Esc → 打开确认框；**确认框打开时再按 Esc 会重开/重新聚焦确认框**，而不是取消确认并留在设置中心；
- 连续按 Esc 可达原生 `<dialog>` 的关闭路径，**丢弃核心配置与扩展设置的未保存输入**，且不经过闸门；
- 对照：同一对话框里扩展配置子视图的闸门（`ExtensionSettingsHost.vue`）已按 SPEC-DM-011 §3.3 的 SC-17 条实现「Esc 先作用于最上层原生模态、只关闸门不连带关闭设置窗口」，二者属同一缺陷类但当前语义不一致。

这是**已知的同类缺陷**，PLAN-DM-025 只记录、未修（不属该计划范围；`SC-08` 的历史验收口径未覆盖「确认框自身消费 Esc」）。

## 复现条件

1. 打开设置中心，修改任一项核心配置（不保存）；
2. 按 Esc 打开确认框；
3. 在确认框打开状态下再按 Esc（可连续按多次）。

期望：Esc 只取消确认框、输入保留，设置窗口不关闭；连续 Esc 不得绕过闸门丢弃输入。

实际：确认框被重新打开/重新聚焦，连续 Esc 可原生关闭对话框并丢弃输入。

## 完成条件

- `SettingsDialog.tryClose()` 的内联确认框在打开时消费 Esc（等价于「留在此处」），不再重开；
- 增加回归用例钉住「确认框打开时 Esc 只取消确认、输入保留、对话框不关闭」（建议与 `web/tests/e2e/extensions-settings.spec.ts` 的扩展配置闸门用例同批，保持两个闸门语义一致）；
- 确认修复不改变 `SC-08` 既有验收事实（无脏状态下 Esc 直接关闭、焦点归还齿轮入口）。

## 触发重开条件

设置中心核心配置的脏状态闸门再次被改动时，必须一并处理本项；在此之前，PLAN-DM-025 与 SPEC-DM-011 §9 均不得声称「Esc 语义在设置中心全局一致」。
