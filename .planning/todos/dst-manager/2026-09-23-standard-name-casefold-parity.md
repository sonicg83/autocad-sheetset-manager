# 标准编辑器前后端名称大小写折叠口径

日期：2026-09-23

状态：待办（未立项；来源 PLAN-DM-038 代码审查 F5）

关联：`PLAN-DM-038`、`SPEC-DM-017`

## 问题

标准编辑器前端的属性名及 DWG 文件名重名预检使用 JavaScript `toLocaleLowerCase()`，后端权威校验使用 Python `casefold()`。两者对 `ß`、连字等边缘 Unicode 字符可能得到不同结果：前端未提示冲突，后端发布时仍正确拒绝。详见[代码审查备忘 F5](../../memos/dst-manager/2026-09-23-plan-dm-038-code-review-findings.md)。

## 待处理

- 保持后端 `casefold()` 为最终口径，不为通过前端预检而放松发布门禁。
- 评估前端是否有必要实现完整等价折叠；若成本与真实收益不成比例，明确标注前端仅作近似预检，并保证后端冲突诊断可定位、可理解。
- 补边缘字符回归用例，覆盖属性名和 DWG 文件名；确认发布失败不写入部分标准。

此项是标准编辑器体验一致性问题，不作为 `PLAN-DM-036` 创建流程的前置任务；创建流程始终消费后端权威校验结果。
