# PLAN-DM-020 G8 用户真实桌面复验与原结论撤销记录

## 1. 复验范围与证据边界

- 复验日期：2026-09-11。
- 复验人：用户（业务负责人）。
- 对照基准：SPEC-DM-012 §7.4 已冻结的 G4 Demo（commit `9f3dfb3`）及 `default-light-1440x1000.jpg`。
- 生产证据：用户提供的真实 Windows 桌面完整截图与首屏截图；截图含真实工程显示信息，按私有资料处理，不复制到公开仓库或自动化夹具。
- 本次仅裁决页面视觉、信息层级和主任务操作流；没有重新验证原生另存为、Explorer、Excel 或 Artifact 行为，G9 仍未执行。
- 两侧数据行数和输出列数不同，不把业务数据内容本身计为视觉偏差；只比较稳定布局、控件形态、信息层级、滚动和操作可达性。

## 2. 用户裁决

用户明确反馈：除输出列的上移、下移、删除由文字按钮改成符号按钮这一差异可保留外，生产页面整体明显偏离已认可的 G4 Demo，不能接受 MEMO-DM-027 将 D1～D10 归为“已接受差异”并据此登记 G8 通过。

据此作出以下正式裁决：

1. MEMO-DM-027 的 G8“通过”结论自 2026-09-11 起失效；SPEC-DM-012 §16 的 G8 恢复为“未通过（用户真实桌面复验）”。
2. G4 设计冻结继续有效，不重开 G4。当前目标是把生产实现拉回既有冻结件；只有用户未来决定采用另一套布局时才重开 G3/G4。
3. G9 暂停执行。先完成 PLAN-DM-023 并由用户重新通过 G8，再使用 MEMO-DM-028 执行真实桌面功能验收。
4. PLAN-DM-020 保持 `active`，不得在 G8/G9 重新通过前标记 `completed`。

## 4. 原 G8 过程问题

- 实施侧把“功能存在、语义大致相同”替代为“符合冻结视觉”，错误接受了表格到卡片、可见语法到 tooltip、首屏预览到滚动后可达等结构变化。
- `sheet-catalog-visual-evidence.spec.ts` 只守住无横向溢出和滚动后可达，并在测试注释中预先把首屏偏差写成“已接受差异”；该测试不能作为冻结设计一致性的充分证据。
- MEMO-DM-027 没有为 D1～D10 记录业务负责人的逐项确认人和日期，却仍把 G8 登记为通过，违反 GUIDE-DM-001 G8 的差异裁决要求。
- “要求向 Demo 收敛应重开 G4”的表述方向错误：冻结件未变时应修生产实现；只有选择新方向才重开 G4。

## 5. 恢复条件

G8 只有同时满足以下条件才能重新登记为通过：

1. PLAN-DM-023 的生产改动和回归测试完成。
2. 1440×1000 浅色、900×700 深色使用相同虚构数据、滚动位置和展开状态生成成对截图。
3. 生产证据截图进入 `docs/dst-manager/specs/assets/SPEC-DM-012/production/`，不再只保存于被忽略的 `.superpowers/`。
4. V1～V8 均有同状态截图和几何/可见正文证据；A1、A2 作为仅有的预先接受差异保留。
5. 用户逐对确认并记录日期；在用户确认前不得由实施代理自行写“已接受差异”或“G8 通过”。
