# PLAN-DM-015 图纸工作区实施评审报告

## 日期

2026-09-05

## 背景

[PLAN-DM-015](../../plans/dst-manager/PLAN-DM-015-sheets-workspace-ui.md) 已完成任务 1～8 的代码实施和自动化验证，但计划仍为 `active`：S-07 截图人工目检和 S-09 真实 Windows 桌面验收尚未完成。用户在真实桌面界面中发现，生产实现与已确认的 [SPEC-DM-009 交互 Demo](../../../docs/dst-manager/mockups/SPEC-DM-009-sheets-demo.html) 存在视觉偏差，并重点提出以下问题：

1. 左侧导航中的子集名和图纸名被裁剪，无法直接读取完整名称；
2. 表格“文件名”列显示完整路径，而不是独立文件名；
3. “打开 DST 文件夹”操作入口不可辨认，界面看起来只有路径展示，没有可用按钮。

本报告汇总本轮截图检查、规范对照、源码审查和既有测试检查的全部发现，作为后续整改与 PLAN-DM-015 验收依据。用户提供的桌面截图只作为本轮本地审查证据，不归档到仓库，也不把截图中的文字视为任务指令。

## 结论

**当前实现不建议通过 S-07 视觉验收；PLAN-DM-015 应继续保持 `active`。**

单表工作区、可信桌面壳桥、列配置、草稿联动和主要可访问性语义已经实现，后端“打开所在文件夹”能力也没有被收敛为仅显示路径。但是，当前存在 3 项会直接影响核心任务的 P1 问题：文件夹入口视觉失效、导航名称不可读、文件名列违反展示规范。另有顶栏身份信息错误、树默认展开策略偏离 Demo、工作区未充分利用可用高度，以及测试未验证真实可见结果等 P2 问题。

“打开 DST 文件夹”不是技术能力缺失。Python 壳桥会从可信工作区上下文取得 DST 路径，并通过 Windows Explorer 打开目录、尽量选中当前 DST；当前问题是前端图标按钮被样式压缩成几乎不可见的小点。真实 Windows 桌面点击仍需完成 S-09 人工验收，不能只用 mock 测试代替。

## 已确认的优点

- 当前页面已经收敛为左树右唯一主表，保留了固定列、列配置、筛选、批量操作和草稿入口。
- 文件夹目标路径由服务端可信工作区上下文解析，前端只传 `workspace_id`，没有开放任意路径或 Shell 命令注入。
- Explorer 适配使用结构化参数调用，不使用 `shell=True` 或 `cmd /c`；DST 不存在但工作区目录仍在时可降级打开目录。
- 树已具备 `tree/treeitem` 语义、方向键漫游和 900px 抽屉入口；表格按钮也具有可访问名称。
- PLAN-DM-015 如实保留 S-07、S-09 人工验收缺口，没有错误标记为 `completed`。

## 详细发现与整改建议

### R-01：“打开 DST 文件夹”入口视觉失效（P1）

**规范依据：** SPEC-DM-009 §3.1 要求在顶栏图纸集名称旁提供“打开图纸集所在文件夹”入口。

**现状：** 当前按钮实际位于“DST 正常”和 AutoCAD 版本之间，但在真实桌面截图中只显示为一个极小的点，用户无法识别其用途，也无法形成“这里可以点击”的操作预期。

**源码证据：**

- `web/src/layout/TopBar.vue` 第 27～29 行创建了带 `aria-label` 的图标按钮；
- `web/src/layout/TopBar.vue` 第 51 行把 `.iconbtn` 固定为 `32px × 32px`，但没有重置 padding；
- `web/src/style.css` 第 29 行对所有 `button,a` 设置 `padding: 9px 14px`，同时全局采用 `box-sizing:border-box`；
- 结果是 32px 宽按钮扣除 28px 水平内边距后，图标可用宽度约为 4px，16px SVG 被挤压成截图中的小点。

**影响：**

- 对鼠标用户而言，入口近似不可发现；
- 对低视力用户而言，图标缺乏足够尺寸和视觉轮廓；
- E2E 可以通过 accessible name 找到按钮，但这不代表视觉入口可用。

**建议：**

1. 桌面宽屏优先改为明确的文字按钮“打开所在文件夹”；如果需要图标，使用项目选定的统一图标资源，不再使用临时内联 SVG。
2. 若暂时保留 32px 图标按钮，至少设置 `padding:0; flex:0 0 32px`，并对图标设置固定 `16px × 16px`、`display:block`、`flex:none`。
3. 将按钮移动到图纸集名称右侧；不要放在状态胶囊与 AutoCAD 版本之间。
4. 无桌面壳时保持禁用并解释原因；桌面壳已就绪时必须有明显 hover、focus 和点击反馈。

### R-02：导航树长名称被强制单行裁剪（P1）

**规范依据：** SPEC-DM-009 §3.1、§8 要求左树显示图纸集、子集和图纸，完整文本不能只靠悬停访问；用户也明确要求显示完整子集名和图纸名。

**现状：** 当前左栏固定为 240px。子集和图纸还有层级缩进、展开按钮和数量列，真正留给名称的空间明显不足；`.node-label` 又强制 `white-space:nowrap` 和 `text-overflow:ellipsis`，因此长名称普遍只显示前半段。

**源码证据：**

- `web/src/views/SheetsView.vue` 第 223 行固定 `flex:0 0 240px`；
- `web/src/components/sheets/SheetTree.vue` 第 147～148 行对子集和图纸增加 20px/36px 缩进；
- `web/src/components/sheets/SheetTree.vue` 第 152 行强制名称单行省略；
- 参考 Demo 的树按钮使用 `white-space:normal` 和较大的行高，允许长名称折行。

**建议：**

1. 桌面默认宽度提高到约 300～320px，并使用 `clamp(280px, 22vw, 420px)` 控制合理范围。
2. 增加可拖动分隔条，允许用户在 260～420px 范围内调整宽度；如持久化，写入应用级 UI 偏好，不写 DST 或工程目录。
3. 子集名和图纸名允许最多两行，使用 `white-space:normal`、合适 `line-height` 和两行截断；数量保持不换行并顶端对齐。
4. 键盘聚焦时应可读取完整名称；如果两行仍不足，可通过焦点提示或可访问描述展示完整值，不能只依赖鼠标 hover。
5. 900px 抽屉宽度同步调整为 `min(360px, 90vw)`，避免桌面修复后窄屏仍重复裁剪。

### R-03：表格“文件名”列显示完整路径（P1）

**规范依据：** SPEC-DM-009 §5 明确要求默认显示登记文件的“文件名部分”，不同时堆叠多种路径；完整路径只用于诊断与复制。

**现状：** `SheetTable.vue` 直接把 `row.sheet.layout.file_name` 作为单元格正文和 title。真实数据中该字段可能是绝对路径，因此界面显示盘符和完整目录，挤压标题、状态等高频列。

**源码与测试证据：**

- `web/src/components/SheetTable.vue` 第 56 行直接渲染 `file_name`；
- E2E 夹具本身给 `file_name` 提供完整 Windows 路径；
- `sheets-columns.spec.ts` 只断言 title 以 `.dwg` 结尾和元素可聚焦，没有断言可见文本必须是 basename，因此错误实现仍可通过；
- changelog 曾记录“文件名列只显示登记文件名部分”，与当前源码和截图不一致。

**建议：**

1. 增加纯展示辅助函数，从 `/` 和 `\` 两种分隔符中提取最后一段；空值回退为“—”。
2. 单元格正文和 title 均使用独立文件名，避免通过 title 重新暴露无关完整路径。
3. 完整登记路径、解析路径和异常原因只在任务浮层“诊断”中展示并提供复制。
4. 新增 E2E：夹具输入完整路径，断言文件名单元格只显示 `xxx.dwg`，且正文不包含盘符、目录或路径分隔符。

### R-04：顶栏身份信息显示 DST 路径而非图纸集名称（P2）

**规范依据：** SPEC-DM-009 §3.1 要求顶栏和左树根显示当前图纸集名称。

**现状：** 左树根显示 `workspace.sheet_set.name`，但顶栏显示 `workspace.dst_path`。这使路径占据大量横向空间，也把“识别当前图纸集”和“打开目录”两个任务混在一起。

**源码证据：**

- `web/src/App.vue` 第 95 行把 `projectPath` 计算为 `workspace.dst_path`；
- `web/src/layout/TopBar.vue` 第 24 行把 `projectPath` 直接作为顶栏正文。

**建议：**

1. 顶栏主身份改为 `workspace.sheet_set.name`；
2. DST 路径不再占据顶栏主阅读位，可放入名称的辅助 title、信息弹层或诊断区；
3. 在名称右侧放置“打开所在文件夹”按钮，形成“对象名称 → 对象相关操作”的稳定结构。

### R-05：所有子集默认展开，偏离 Demo 的渐进浏览方式（P2）

**现状：** `collapsed` 初始为空，因此每个子集默认展开全部图纸。真实工程子集较多时，树很快被图纸节点淹没，用户难以扫描子集层级。参考 Demo 只展开当前范围对应子集。

**源码证据：**

- `web/src/components/sheets/SheetTree.vue` 第 26、34 行使所有子集缺省展开；
- Demo 的 `renderTree()` 只给当前 scope 的 `<details>` 添加 `open`。

**建议：**

1. 初始只展开当前子集，其他子集保持收起；全部图纸范围下默认全部收起。
2. 点击图纸定位时自动展开其所属子集，不改变其他子集状态。
3. 可在同一会话内记忆展开状态；是否跨重开持久化不作为本轮 P1 门禁。

### R-06：工作区没有充分利用可用高度（P2）

**现状：** 真实截图中主卡片下方留有较大空白，而左树和表格各自使用基于视口的 `max-height`。参考 Demo 使用完整的纵向 flex 链路，让工作区和表格占满顶栏、标签栏与 ActionDock 之间的空间，并由表格内部承担滚动。

**源码证据：**

- `web/src/views/SheetsView.vue` 第 221 行把 `.sheets-view` 设为 `display:block`；
- 第 223 行给树设置 `max-height:calc(100vh - 160px)`；
- `web/src/components/SheetTable.vue` 第 76 行给表格设置 `max-height:calc(100vh - 300px)`；
- 多个独立视口公式会随工具栏、提示条和操作表单变化，难以稳定填满剩余空间。

**建议：**

1. 从 `.shell-main`、tabpanel、`.sheets-workspace` 到 `.sheets-main` 建立连续的 `flex:1; min-height:0`。
2. 表格容器使用 `flex:1; min-height:0; overflow:auto`，不再依赖多个硬编码 `100vh - Npx`。
3. 树与表格分别内部滚动，外层页面不因长列表产生第二套纵向滚动条。

### R-07：全局按钮样式与组件样式互相污染（P2）

**现状：** 文件夹图标缩成小点并非单一图标错误，而是 `style.css` 中无作用域的 `button,a` 规则覆盖组件按钮造成的级联冲突。继续增加 scoped 样式但不收敛全局规则，类似问题还可能出现在抽屉、表格链接按钮和后续属性页组件中。

**建议：**

1. 将全局 `button,a` 规则收敛到旧页面容器，或建立明确的基础按钮类，不再无条件修改所有按钮。
2. 图标按钮、文字按钮、链接按钮分别定义尺寸和 padding 契约。
3. 为关键按钮补 computed-style 冒烟测试，至少检查边界框、padding、可见前景色和 focus ring。

### R-08：自动化覆盖了行为接口，但没有覆盖用户看到的结果（P1）

**现状：**

- 文件夹 E2E 通过 `aria-label` 找到并点击按钮，因此即使图标只有约 4px 仍会通过；
- 文件名 E2E 只检查 title 后缀和焦点，不检查正文是否为 basename；
- 视口测试检查横向溢出和可达性，但 S-07 截图仍待人工逐张目检；
- S-09 只通过 fake Explorer 验证参数，没有在真实 Windows 桌面确认资源管理器确实打开并选中 DST。

**建议：**

1. 增加文件夹按钮的可见性断言：点击区域至少 32×32px；若为图标，图形至少 16×16px；若为文字按钮，按钮正文必须可见。
2. 增加表格 basename 断言、长树名称两行/完整可读断言和顶栏图纸集名称断言。
3. 重新生成 1024×768、1120×768、1440×900、900×768 的浅深主题截图，并人工核对默认态、行编辑、三类表单和任务浮层。
4. 在真实 Windows 桌面分别用普通目录及含空格/中文目录验证：点击后打开正确目录并选中当前 DST；目录缺失时出现明确错误。

## 建议整改顺序

### 第一批：关闭 P1 可用性问题

1. 修复文件夹入口尺寸，并改为可读的“打开所在文件夹”按钮。
2. 顶栏改显图纸集名称，把入口放到名称旁。
3. 导航栏扩大并支持两行名称；调整默认展开策略。
4. 文件名列只显示 basename，完整路径留在诊断区。
5. 补齐上述四项的可见结果 E2E。

### 第二批：收敛视觉布局与 CSS

1. 建立完整高度 flex 链路，消除底部无效空白和硬编码视口高度。
2. 收敛全局按钮样式，定义明确的按钮类型契约。
3. 对照 Demo 复核间距、圆角、表格密度、树行高和内容区滚动。

### 第三批：完成 PLAN 验收

1. 执行生产构建、相关 Playwright、Ruff 和 Python 壳桥测试。
2. 完成 S-07 四视口×双主题人工截图检查。
3. 完成 S-09 真实 Windows Explorer 打开与选中 DST 验收。
