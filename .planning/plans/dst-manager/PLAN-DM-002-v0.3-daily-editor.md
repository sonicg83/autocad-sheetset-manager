# 阶段 2：v0.3 受控日常编辑器

状态：待实施  
建议周期：2～3 周  
前置条件：`SPEC-DM-004` 已完成评审并明确其发布门禁；v0.2.1 的受控编辑、快速预览、修复确认和 CAD 分流能力保持回归通过。  
阶段目标：将现有表单整理为适合约 300 张图纸工程的日常工作区；所有编辑仍受既有领域规则、修复门禁和发布事务约束。

## 1. 成功标准

- 用户无需查看或理解命令 JSON，即可完成已允许的属性维护、受控插入、删除和预览发布。
- 图号、标题、范围、DWG 文件名和布局名明确展示为派生字段，不能被前端、CSV 或 API 绕过修改。
- 草稿可撤销、重做、移除和恢复；草稿只保存用户意图，提交前仍由后端重新规划、校验并绑定当前基准。
- 搜索、过滤、批量选择和批量修改既有自定义属性在大工程中保持流畅；不提供拖放排序、跨子集移动或批量重编号。
- 所有写入路径（含普通编辑、CSV 和修复确认）都显示人类可读预览，并使用当前基准修订和预览摘要执行。
- `VALID`、`REPAIRED`、`INVALID_REPAIR_REQUIRED`、`INVALID_UNRECOVERABLE` 状态在工作区中可理解地呈现，阻断状态不能被普通编辑绕过。

## 2. 工作包

### E2-01 前端结构重构

- [ ] 将单体 `App.vue` 拆为工作区外壳、项目导航、图纸表格、属性面板、变更草稿、预览、任务、修复状态和历史组件。
- [ ] 建立统一 API 客户端、错误类型、加载状态和响应序列化类型。
- [ ] 为工作区原始快照、编辑草稿、选中状态、修复状态和任务状态建立清晰的数据边界。
- [ ] 组件不得直接拼装任意命令字典；命令创建集中到类型化模块。

### E2-02 受控命令与只读派生字段

- [ ] 以带判别字段的请求模型覆盖既有允许命令：图纸集/子集/图纸自定义属性更新、子集创建与改名、受控图纸插入、受控删除和自定义属性定义维护。
- [ ] 在 API 和 Web 共享可序列化的命令、诊断、修复状态和预览类型说明，避免字段漂移。
- [ ] 对位置、来源文件、来源布局、空子集删除确认和危险名称执行字段级校验。
- [ ] 将图号、标题、范围、DWG 文件名和布局名作为只读派生输出；拒绝手工改号、改标题、改布局、排序和跨子集移动命令。
- [ ] 保留未知命令拒绝、越界路径和危险名称校验。

### E2-03 可撤销草稿模型

- [ ] 编辑动作先作用于内存草稿，再由原始快照确定性地产生允许命令序列。
- [ ] 增加撤销、重做、清空和单项移除；同一对象的重复属性修改合并为稳定意图。
- [ ] 基准修订或修复状态变化时标记草稿过期，禁止直接执行并提供重新加载或丢弃选项。
- [ ] 草稿持久化到应用数据目录而非工程目录；保存工作区、基准修订、修复状态和编辑意图。
- [ ] 草稿不是修订历史、不能代替发布前预览，也不能绕过服务端规则。

### E2-04 大项目导航与批量属性维护

- [ ] 提供图纸集、子集、图纸三级导航。
- [ ] 支持按图号、标题、自定义属性和 DWG 文件搜索；派生字段仅用于查找和定位。
- [ ] 支持按子集、诊断/修复状态、路径状态和待变更状态过滤。
- [ ] 支持多选、全选当前过滤结果和批量修改既有自定义属性；批量范围在预览中逐项可审计。
- [ ] 大表格使用虚拟滚动或增量渲染，并保留键盘操作和无障碍焦点。

### E2-05 受控编辑流程

- [ ] 创建、改名和删除子集，删除最后一张图纸时单独确认是否删除子集和主 DWG。
- [ ] 更新图纸集、子集和图纸已有自定义属性，并维护受控的属性定义。
- [ ] 从已检查的 DWG/DWT 模板布局新增图纸，或复制既有受允许来源；显示由领域层派生的编号、标题和目标路径。
- [ ] 删除图纸时清晰显示受影响的 DST、DWG、CAD 操作和回滚边界。
- [ ] 不支持任意自定义属性 schema、AcSm GUID、Handle 或派生字段编辑。

### E2-06 人类可读预览与修复门禁

- [ ] 按“图纸集属性、子集、图纸、文件操作、CAD 操作、修复状态、诊断”分组展示预览。
- [ ] 显示字段 before/after、受影响 DWG 及 `none`、`rename_only`、`rebuild` 分流，而非原始命令 JSON。
- [ ] 显示预计 Core Console 数量、并发度和预计耗时范围；默认并发为 4，允许范围为 1～10。
- [ ] 阻断诊断提供对象定位和修复建议；`REPAIRED` 必须先生成并确认独立修复预览，两个 `INVALID_*` 状态只读。
- [ ] 普通编辑、CSV 导入和修复确认均只接受当前、无阻断且绑定基准的预览摘要。

## 3. 重点修改入口

- `web/src/`：组件、状态管理、类型化命令、草稿、修复状态和预览。
- `src/dst_manager/interfaces/`：类型化请求、草稿和预览摘要 API。
- `src/dst_manager/application/`：统一各写入入口的基准与预览摘要校验。
- `src/dst_manager/domain/`：既有受控编辑命令的确定性规划与派生字段校验。
- `src/dst_manager/infrastructure/acsm_xml/`：受控 DOM 变更与修复加载门禁。
- `tests/integration/` 与 `web/tests/e2e/`：API、草稿、预览和主交互流程。

## 4. 测试矩阵

- [ ] 允许命令、只读派生字段、未知命令和危险输入的正常值、边界值及非法值测试。
- [ ] 撤销/重做、重复编辑合并、草稿恢复、修订冲突和修复状态变化测试。
- [ ] 子集创建/删除、受控图纸插入/删除、批量属性修改的领域与 XML 回归测试。
- [ ] 普通编辑、CSV 与修复确认的统一摘要/基准校验和绕过拒绝测试。
- [ ] 约 300 张图纸数据下的搜索、过滤、选择和滚动性能测试。
- [ ] Playwright 覆盖打开、搜索、多选、批量属性修改、草稿、修复门禁、预览、执行和完成反馈。
- [ ] 对会触发 CAD 的结构命令运行可用的 AutoCAD 2016/2020 系统测试；环境不可用时记录跳过条件，不将其视为通过。

## 5. 阶段验收

- [ ] 用户可在一个界面完成打开、查找、受控属性维护、插入、删除、预览和发布。
- [ ] 所有主要编辑意图可在发布前撤销，刷新后可恢复草稿或明确丢弃。
- [ ] 派生字段和被否决的自由编辑能力没有可用入口，服务端绕过尝试稳定被拒绝。
- [ ] 所有写入入口都需要当前预览摘要，修复状态与普通编辑门禁一致。
- [ ] 约 300 张图纸项目的常用交互无明显卡顿。
- [ ] Ruff、相关 pytest、Web 构建、Playwright 和可用 CAD 系统测试结果均被记录。

## 6. 风险与回退

- UI 草稿不得成为最终业务规则来源；后端必须重新规划、校验和绑定基准。
- 批量编辑必须产生稳定顺序和逐项预览，不能依赖浏览器对象遍历顺序。
- 草稿、修复确认和 CSV 都不得绕过摘要校验、锁、暂存、发布日志和回滚事务。
- 前端可按组件逐步替换，保留现有 API 主流程直至新 E2E 覆盖完成。
