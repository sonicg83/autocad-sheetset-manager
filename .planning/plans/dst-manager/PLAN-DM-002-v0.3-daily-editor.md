# 阶段 2：v0.3 受控日常编辑器

状态：已完成
建议周期：2～3 周  
前置条件：`SPEC-DM-004` 已接受并明确其发布门禁；v0.2.1 的受控编辑、快速预览、修复确认和 CAD 分流能力保持回归通过；`delete_subset` 开发前先完成本计划 E2-05 所列文件删除事务的 Spec/ADR 决策。
阶段目标：将现有表单整理为适合约 300 张图纸工程的日常工作区；所有编辑仍受既有领域规则、修复门禁、统一预览摘要和发布事务约束。

## 1. 成功标准

- 用户无需查看或理解命令 JSON，即可完成已允许的属性维护、受控插入、图纸删除、子集整体删除和预览发布。
- 图号、标题、范围、DWG 文件名和布局名明确展示为派生字段，不能被前端、CSV 或 API 绕过修改；自定义属性作用域只包含 `sheetset` 和 `sheet`。
- 草稿可撤销、重做、移除和恢复；草稿只保存用户动作与有效意图，提交前仍由后端重新规划、校验并绑定当前基准。
- 搜索、过滤、批量选择和批量修改既有自定义属性在约 300 张图纸工程中满足量化性能预算；不提供拖放排序、跨子集移动或批量重编号。
- 所有由用户发起并可能修改 DST、DWG 或其他正式工程文件的发布路径，都显示人类可读预览，并使用当前基准修订和预览摘要执行。
- `VALID`、`REPAIRED`、`INVALID_REPAIR_REQUIRED`、`INVALID_UNRECOVERABLE` 状态在工作区中可理解地呈现，阻断状态不能被普通编辑绕过。

## 2. 工作包

### E2-01 前端结构重构

- [x] 将单体 `App.vue` 拆为工作区外壳、项目导航、图纸表格、属性面板、变更草稿、预览、任务、修复状态和历史组件。
- [x] 建立统一 API 客户端、错误类型、加载状态和由后端契约生成的请求/响应类型。
- [x] 为工作区原始快照、编辑动作历史、有效意图、选中状态、修复状态和任务状态建立清晰的数据边界。
- [x] 组件不得直接拼装任意命令字典；命令创建集中到类型化模块。
- [x] 完整既有 Playwright 行为覆盖及新增用例必须全部通过，生产构建必须通过；删除或改写旧用例时保留等价行为覆盖，不固定当前用例数量。

### E2-02 受控命令与只读派生字段

- [x] 以 Pydantic 判别联合覆盖既有允许命令及新增 `delete_subset`：图纸集/图纸自定义属性更新、子集创建与改名、受控图纸插入/删除、子集整体删除和自定义属性定义维护；保持现有 `{"type": ...}` JSON 形状，拒绝未知字段。
- [x] 将预览请求和执行请求分离；执行模型必须提交 `preview_digest`，旧命令别名只在明确兼容层正规化，再转换为不依赖接口框架的领域命令对象。
- [x] 为命令、工作区、诊断、修复状态、预览、任务和修订建立 Pydantic 请求/响应模型；导出 OpenAPI/JSON Schema 生成 TypeScript 类型，并由 CI 拒绝未提交的生成漂移。
- [x] 对位置、来源文件、来源布局、子集整体删除确认、危险名称和越界路径执行字段级校验。
- [x] 复用 `sheet.layout.file_name`、`relative_file_name`、`layout_name` 作为稳定只读输出，不再平铺重复字段；拒绝手工改号、改标题、改布局、排序和跨子集移动命令。
- [x] 自定义属性作用域只接受 `sheetset` 和 `sheet`；保留未知命令、未知字段、越界路径和危险名称拒绝。

### E2-03 可撤销草稿模型

- [x] 编辑动作先追加到不可变动作历史，再由原始快照确定性投影为允许命令序列；同一对象同一规范化字段/属性名只在有效意图中保留最后值。
- [x] 增加撤销、重做、清空和单项移除；撤销/重做以一次 UI 动作为单位，批量编辑作为一个原子动作，撤销最近动作后必须恢复上一个有效值。
- [x] 基准修订或修复状态变化时将草稿标记为过期并禁止执行；v0.3 不自动 rebase，用户只能查看旧意图、重新加载最新工作区后手工重做，或明确丢弃。
- [x] 增加可配置的绝对草稿目录，默认解析到 `%LOCALAPPDATA%/dst-manager/drafts` 且不依赖 CWD；按 `workspace_id` 保存基准修订、修复状态、schema 版本和动作历史。
- [x] 草稿使用同目录临时文件加原子替换持久化；损坏草稿隔离并允许丢弃，多窗口写入检测版本冲突，不静默覆盖较新草稿。
- [x] 草稿不是修订历史、不能代替发布前预览，也不能绕过服务端规则。

### E2-04 大项目导航与批量属性维护

- [x] 提供图纸集、子集、图纸三级导航。
- [x] 支持按图号、标题、自定义属性和 DWG 文件搜索；DWG 搜索对文件名、相对路径和解析路径进行不区分大小写匹配，派生字段仅用于展示、查找和定位。
- [x] 支持按子集、诊断/修复状态、路径状态和待变更状态过滤。
- [x] 支持多选、全选当前过滤结果和批量修改既有 `sheetset`/`sheet` 自定义属性；批量范围在预览中逐项可审计。
- [x] 大表格使用虚拟滚动或增量渲染，并保留键盘操作和无障碍焦点。
- [x] 使用合成 300 行 Workspace JSON 在固定 Playwright Chromium 环境连续采样 20 次：数据加载后的搜索、过滤和全选状态计算中位数不超过 50 ms、P95 不超过 100 ms，首个可交互表格渲染不超过 1.5 秒；记录运行环境与原始结果。

### E2-05 受控编辑流程

- [x] 创建和改名子集；普通 `delete_sheet` 删除最后一张图纸继续返回 `EMPTY_SUBSET`，Web 引导用户改用独立 `delete_subset`。
- [x] `delete_subset` 删除整个 `AcSmSubset` 节点及其完整受控子树、其中全部图纸和对应主 DWG，不允许留下空 `AcSmSubset` 或空 DWG；请求必须显式确认删除全部图纸和主 DWG。
- [x] 子集删除预览逐项列出子集、全部图纸、主 DWG、后续派生命名/CAD 影响和回滚边界；系统不证明工程外部对主 DWG 的引用，用户对确认后的外部影响负责。
- [x] 删除前检查待删除子树的 AcSm ID 未被子树外 XML 节点引用，命中时返回 `UNKNOWN_REFERENCE_BLOCKED`；删除后若仍存活图纸引用待删除 DWG，则以文档断链阻断发布。
- [x] `delete_subset` 实施前新增或修订正式 Spec/ADR，明确主 DWG 删除如何进入永久 before 快照、暂存清单、发布日志、多文件删除/替换事务、失败回滚和启动恢复；未接受该决策前不得实现正式文件删除。
- [x] 更新图纸集和图纸已有自定义属性，并维护受控的 `sheetset`/`sheet` 属性定义；不支持子集自定义属性。
- [x] 从已检查的 DWG/DWT 模板布局新增图纸，或复制既有受允许来源；显示由领域层派生的编号、标题和目标路径。
- [x] 删除图纸或子集时清晰显示受影响的 DST、DWG、CAD 操作和回滚边界。
- [x] 不支持任意自定义属性 schema、AcSm GUID、Handle 或派生字段编辑。

### E2-06 人类可读预览与统一写入门禁

- [x] 按“图纸集属性、子集、图纸、文件操作、CAD 操作、修复状态、诊断”分组展示预览。
- [x] 显示字段 before/after、受影响 DWG 及 `none`、`rename_only`、`rebuild` 分流，而非原始命令 JSON。
- [x] 显示预计 Core Console 数量、并发度和预计耗时范围；数量/并发由执行计划确定，耗时优先按 AutoCAD 版本和 `cad_operation` 使用历史 `duration_ms`，无足够历史时使用版本化保守 fallback，并标注“估算值”。
- [x] 阻断诊断提供对象定位和修复建议；`REPAIRED` 必须先生成并确认独立修复预览，两个 `INVALID_*` 状态只读。
- [x] 普通编辑、CAD 结构编辑、CSV 导入、修复发布、修订恢复和 XML 导出/覆盖统一执行“预览 → 明确确认 → `base_revision_id + preview_digest` 执行”；执行时重新生成预览并以 `409 REPREVIEW_REQUIRED` 拒绝摘要或基准变化。
- [x] 预览摘要使用版本化确定性序列化，至少绑定 `schema_version`、`operation_type`、`workspace_id`、基准修订、规范化输入、人类可读语义差异、目标文件基准，以及适用的 CAD 版本和来源文件基准。
- [x] 草稿、SQLite 应用状态、日志、只读导出、自动回滚和启动恢复不要求用户摘要；任务重试只能复用冻结计划和原摘要，任一基准漂移必须重新预览。

## 3. 重点修改入口

- `web/src/`：组件、状态管理、生成类型、类型化命令、动作历史、草稿、修复状态和预览。
- `src/dst_manager/interfaces/`：Pydantic 判别请求、响应模型、OpenAPI 契约和必填摘要 API。
- `src/dst_manager/application/`：统一正式写入入口的基准、预览摘要、草稿和耗时估算编排。
- `src/dst_manager/domain/`：既有受控编辑命令、`delete_subset`、确定性规划与派生字段校验。
- `src/dst_manager/infrastructure/acsm_xml/`：子集子树删除、未知引用防御、受控 DOM 变更与修复加载门禁。
- `src/dst_manager/infrastructure/filesystem/`：在前置 Spec/ADR 接受后实现主 DWG 删除的 before 快照、发布和恢复语义。
- `src/dst_manager/config.py` 与草稿适配器：绝对草稿目录、schema 版本、原子持久化和冲突处理。
- `tests/unit/`、`tests/integration/`、`tests/system_autocad/` 与 `web/tests/e2e/`：契约、草稿、摘要、删除、性能和主交互流程。

## 6. 风险与回退

- UI 草稿不得成为最终业务规则来源；后端必须重新规划、校验并绑定当前基准和摘要。
- 批量编辑必须产生稳定顺序和逐项预览，不能依赖浏览器对象遍历顺序；动作历史与有效意图投影必须分离。
- 预览摘要规范必须版本化并使用稳定序列化；任何操作类型不得自定义一个无法复核的临时摘要算法。
- 子集删除不证明工程外部引用，必须在确认界面明确提示；内部 AcSm ID 引用、存活图纸 DWG 引用和最终 DOM 校验仍是阻断门禁。
- 主 DWG 文件删除的永久快照、发布和恢复语义未被 accepted Spec/ADR 覆盖前，`delete_subset` 只能停留在预览/领域设计阶段，不得直接覆盖或删除正式文件。
- 草稿目录不得落入工程目录；损坏或并发冲突时宁可隔离并要求用户选择，也不静默覆盖或自动 rebase。
- 前端可按组件逐步替换，保留现有 API 主流程直至新契约和完整 E2E 覆盖完成。
